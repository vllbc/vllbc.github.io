视觉语言模型 · arXiv 2507.06167v3 · 2025-07

Skywork-R1V3：把文本推理迁移到视觉，靠 RL 激活

Skywork-R1V3 是一个 38B 开源视觉语言模型。它不靠额外继续预训练，而是把文本 LLM 的推理模式通过冷启动 SFT 注入 VLM，再用 GRPO 在 15K 多模态数学题上做强化学习，最后用 connector-only 微调把知识分布拉回多学科。MMMU 达到 76.0%；域外 MMMU 上 RL 到 74.5%，而 SFT 反而掉到 65.4%。

TL;DR · 30 秒抓住核心

报告的核心不是新架构，而是一套后训练配方：冷启动 SFT 把 R1V2 的推理风格迁到 InternVL-38B；RL 阶段用 15K 多模态数学题和 GRPO 激活推理；RL 后再用 10K 跨 20 个领域的数据只训练 connector，恢复被数学数据拉偏的知识分布。

三个关键观察：一，connector 在 RL 阶段必须可训练，冻结后奖励迅速崩塌；视觉编码器冻结仍能训练，但解冻有额外收益。二，用“关键推理 token 的熵”挑 checkpoint——真正会推理的模型在 “Wait…/Alternatively…” 处更不确定，只会模仿风格的模型更确定。三，RL 提升域外泛化，SFT 只学到推理风格：Table 3 里 RL 的 OOD MMMU 是 74.5，SFT 是 65.4，低于 baseline 的 68.1。

代价与边界：MMMU 76.0 是表内最高，但 MathVision、LogicVista、SeePhys、EMMA 仍低于 Claude 3.7 Sonnet；MMBench 虽高于 Claude 3.7 Sonnet 与 GPT-4o，仍低于 InternVL3-78B 和 Qwen2.5-VL-72B；MMStar 低于 Qwen2.5-VL 0.2 点。作者自述报告范围窄，不研究视觉编码器与 LLM 预训练，也把视频、Agent、工具调用列为未来工作。

01

开源 VLM 缺的不是参数，是会推理的后训练

读完这节应该知道：为什么直接搬到 VLM 的文本 RL 配方不够用。

报告开头的判断是：闭源 VLM（Gemini Pro 2.5、OpenAI o 系列、Seed-VL）在多模态推理上领先，开源模型（QwenVL、InternVL、LLaVA）不仅性能落后，还缺少结构化的思考模式。文本 LLM 这边，DeepSeek-R1 一类模型已经用 RL 把长 CoT 做出来了；但视觉侧的多模态数据异质、标注稀缺，直接套文本 RL 配方不够（§1）。

论文把差距归因到后训练：基座 InternVL-38B 已经具备视觉理解，缺的是“先想再答”的推理行为。R1V2 的做法是把 InternViT-6B 与 QwQ-32B 拼起来，让视觉推理从文本推理继承过来；R1V3 则把这种推理风格作为冷启动数据，迁到 InternVL-38B，再用 RL 激活。整个流程不做额外继续预训练（Abstract、§3.2）。

核心判断

RL 激活的是“可泛化的推理”，不是“推理腔调”

§6.1 用同分布 MathVista 与域外 MMMU 对比 RL 与 SFT：两者都能把域内分数抬高、都能让输出“看起来像在推理”，但只有 RL 把域外分数从 68.1 提到 74.5；SFT 把域外分数压到 65.4。论文据此区分“真正推理”与“模仿推理风格”。

02

已有方案：拼接式迁移与直接套文本 RL，各有瓶颈

读完这节应该知道：本文之前的两条路为什么都不够，R1V3 从哪一步接上。

路线 A：拼接式视觉推理迁移（R1V2）。R1V2 直接把 InternViT-6B-448px-V2.5 与 QwQ-32B 拼起来，让视觉推理从文本推理继承（§3.2）。这条路能快速拿到推理风格，但瓶颈在继承：R1V2 的输出有可读性差、语言混杂的问题，需要再用 Skywork-VL-Reward 与 GPT-4o 过滤冗长样本；它的 CoT 幻觉（“I can’t see the image”）也被 R1V3 继承下来，本版没有解决（§3.2、§6.4、§8）。

路线 B：把文本 RL 配方直接搬到 VLM。论文明确说，文本 LLM 的 RL 技术不能直接迁移到 VLM，视觉模态整合带来不同挑战，需要 VLM-specific 的 RL 配方（§5）。没有冷启动、只靠指令自激励的 RL 也长不出长 CoT：Figure 11 里模型既没有持续的 “aha moment”，响应长度也不随奖励增长，后期还会崩（§6.6）。此外，VLM 的 connector 在 RL 中必须可训练，冻结会直接让奖励崩塌（§5.2）。

本文的位置

先用 R1V2 的推理链做冷启动，再做 VLM 专属 RL

R1V3 不额外做继续预训练：把 R1V2 的推理风格作为冷启动数据迁到 InternVL-38B，再用 GRPO 激活，最后用 connector-only 微调把知识分布拉回多学科（Abstract、§3）。

03

三阶段配方：冷启动 → RL → connector-only

读完这节应知道：每个阶段吃什么数据、奖励怎么构成、checkpoint 怎么挑。

冷启动 SFT。从中国高中难度的理科题里收集约 20K 题，覆盖物理、化学、生物、数学；用早期 R1V2 生成逐步推理，再用拒绝采样只保留最终答案正确的样本，得到约 12K 条带推理链的数据（§2）。这一阶段让模型学会 “think before answering” 的格式与节奏。

RL。15K 条 K12 多模态数学题，全部是选择题或填空题，只有题目与答案，没有推理步骤（§2）。奖励由格式奖励与准确率奖励组成，准确率权重 ε=0.8；准确率由模型验证器（如 Qwen2.5-Instruct 32B）或规则判定（§3.1）。算法用 GRPO，框架是 VERL（§3.3）。

Connector-only 微调。RL 数据几乎全是数学，模型的知识分布会向数学偏。RL 后用 10K 条、20 个领域的数据只训练 connector：数学、物理、化学、生物，工程、农业、环境、计算机，医学、药学，音乐、文学、哲学、历史，经济、心理、政治、社会、教育、法律（§2、§3.4）。

奖励、GRPO 与“关键 token 熵”

奖励。格式奖励 R_format = 1(c=1)，表示回答符合 chat template；准确率奖励 R_accuracy 在模型验证器或规则判对时为 1，否则为 0。最终奖励是 R = ε·R_accuracy + (1−ε)·R_format，ε=0.8（Eq. 1–3）。也就是说，准确率是主目标，格式只占 0.2。

GRPO。对每个问题采样 M 条轨迹，用组内均值与标准差归一化最终奖励，得到 token 级优势；再套 PPO 的 clip 目标，并加 KL 正则（Eq. 6–7）。实现上每个 episode 采 1,024 条 rollout，每个 prompt 32 条；mini-batch 32，每个 episode 只做 1 次梯度更新；PPO clip 0.2；长 CoT 训练不加 KL；actor 学习率 1e−5；上下文与输出长度从 4,096 逐步加到 8,192（§3.3）。

关键 token 熵。§5.1 观察到一个区分现象：冷启动模型可以在训练/验证集上拿高奖励，但多数时候只是在重复已有模式。真正学会推理的模型，在 “Wait…”“Alternatively…” 这类推理起点 token 上会表现出更高的不确定性；只会模仿风格的模型在这些位置更确定。论文把这种熵作为 checkpoint 选择指标，Figure 5 显示它与验证集推理性能强相关。

口径

“熵下降”与“高熵 token 变多”同时发生

§6.5 / Figure 10 说：从第 140 步到第 220 步，生成 token 的平均熵持续下降；但高熵 token（熵 > 6.8）出现的概率反而上升。两者度量的是不同量：前者是逐步平均，后者是高熵样本的出现概率；原文没有把两者合成一个结论，页面并列呈现。原文给的是概率，不是计数。

消融：connector-only 最好。RL 后 baseline 是 74.5；只调 connector 到 76.0；connector + LLM 降到 73.2；connector + ViT + LLM 降到 69.7（Table 2）。论文的解释是：过多更新核心模块会破坏 RL 强化的推理模式；只动 connector 能在吸收多领域知识的同时保留推理能力（§5.6）。

思考模式的取舍。Slow Thinking 平均 1,272 token、MMMU 76.0；NoThink 263 token、68.9；NoWait 1,040 token、74.1。NoWait 比 Slow 少 232 token，约 18%（232/1272=18.2%），准确率只低 1.9 点。§6.3 的 thinking budget 更像一条饱和曲线：1K 预算只有 61.6，2K 到 67.7（仍低于 NoThink 的 68.9，差 1.2 点），4K 72.3，8K 75.2，16K 76.0；从 1K 到 16K 共提升 14.4 点，但 8K 之后只增 0.8 点。

07

报告的边界：窄范围、单模型、未解幻觉

先看作者自述，再看页面补充的使用边界。

§8 的自述限制有四条。第一，报告范围刻意收窄：不研究视觉编码器结构与 LLM 预训练，因此“提升通用视觉能力”不是目标。第二，数据 curation 仍是关键方向，需要更严格的数据筛选。第三，视频理解与 Agent 训练没有覆盖。第四，R1V2 继承来的 CoT 幻觉（“I can’t see the image”）会拖累推理，本版没有解决，只列为未来工作。

页面再补三点。第一，主表只有 38B 一个规模，没有 1.5B/7B/72B 的 scaling 曲线，无法判断配方在小模型上是否同样有效。第二，RL 数据全是 K12 数学选择题/填空题，奖励是可验证答案；open-ended 视觉推理、图表问答、多轮交互没有验证。第三，connector-only 的收益只在 MMMU 上做了消融（Table 2），论文没有给其他学科基准的逐项恢复情况。

别用 1

当成通用 VLM 配方

配方围绕数学可验证奖励设计；开放任务、视频、Agent 未验证，作者也把工具调用列为未来工作。

别用 2

忽略 connector 的稳定性作用

RL 阶段冻结 connector 会奖励崩塌、输出退化；connector 不是可选的“小模块”。

别用 3

把 SFT 当泛化手段

Table 3 显示 SFT 域内涨、域外跌；若目标是跨域推理，SFT 不能替代 RL。

还有两个原文内部张力，页面并列不消解。第一，§5.2 说冻结视觉编码器时奖励曲线 “largely consistent”，但又说解冻“continues to bring additional performance gains”；两句话分别描述训练过程与最终性能推断（依据：§5.2 原文 “the reward curve remains largely consistent” 修饰 Figure 6A 的训练曲线，“continues to bring additional performance gains” 修饰解冻 ViT 的最终收益；Conclusion 原文 “demonstrating remarkable generalization through cross-domain transfer—particularly from mathematical to other subject domains” 也只把结论落在最终泛化上），不能合成“冻结完全无影响”。第二，§7 自称 “the first predominantly RL-enhanced open-source VLM”，这是作者主张，报告没有给出与所有开源 VLM 的穷举对比；页面只把它当作原文表述，不当作已验证事实。

笔记勘误与说明（不改笔记原文）
  • 笔记说“课程学习如果是针对同一个数据集……先训练简单题再逐步增加难度会提高性能”。原文 §5.3 只报告了“先 Normal 后 Hard”的两阶段课程失败，归因于分布偏移；它没有做“同一数据集内由易到难”的实验，因此这半句不能由原文支持。笔记后半句“两个难度不同的数据集并不一定能提高性能”与原文相符。
  • 笔记说熵“极值的数量增加”。原文 §6.5 / Figure 10 给的是高熵 token（熵 > 6.8）出现的概率上升，不是极值计数；同时平均熵在下降。两个量要分开写。
  • 笔记说“思考时间和性能之间有一个平衡，超过这个平衡……性能也不会有大的提升”。原文 §6.3 的曲线在 16K 预算处饱和到 76.0，8K 到 16K 只增 0.8 点；方向相符，但原文没有给出“平衡点”的精确定义，页面按预算档位表述。
  • 笔记的三张图依次是报告 Figure 9（thinking budgets）、Figure 7（curriculum learning）、Figure 10（entropy distribution）的截图；截图内自带图注，但笔记 markdown 未写出处。页面改用表号与节号定位（Table 1、§5.3、§6.5）。
