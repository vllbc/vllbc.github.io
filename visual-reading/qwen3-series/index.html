Qwen3 系列：
把 thinking 和 non-thinking 装进同一套权重

Qwen3 有 6 个 dense 模型和 2 个 MoE 模型，从 0.6B 到 235B； 旗舰 235B-A22B 每 token 激活 22B。 它真正的改动不在注意力，而在后训练：四段流水线先把 reasoning 练出来，再用 chat template 把 non-thinking 焊回同一套权重； 小模型跳过四段 RL，直接向 32B/235B 教师做两阶段蒸馏。

Qwen Team · An Yang et al. arXiv 2505.09388v1 ↗ GitHub ↗ Hugging Face ↗
TL;DR · 30 秒抓住核心

Qwen3 的尺寸表是 6 个 dense（0.6B/1.7B/4B/8B/14B/32B）加 2 个 MoE（30B-A3B/235B-A22B）。 旗舰 235B-A22B 的 MoE 层有 128 个专家、每 token 激活 8 个，并且不像 Qwen2.5-MoE 那样保留 shared expert（§2）。

预训练总量 36T tokens，覆盖 119 种语言和方言。 分三段：S1 >30T @4,096，S2 约 5T @4,096，长上下文阶段 数千亿 token @32,768； RoPE 基频从 10,000 提到 1,000,000，推理时再用 YARN + DCA 扩 4×（§3.2）。

后训练四段：Long-CoT 冷启动 → Reasoning RL（3,995 对 query-verifier、GRPO、170 步）→ Thinking Mode Fusion（/think、/no_think、空 think 块）→ General RL（20+ 个任务）。 0.6B–14B 和 30B-A3B 走 strong-to-weak 蒸馏：先 off-policy，再 on-policy 对齐教师 logits（§4.5）。

效果不是单边上涨：235B thinking 在 AIME'24 拿 85.7、AIME'25 拿 81.5， 但 GPQA 是 71.1，低于 DeepSeek-R1 的 71.5。 更反直觉的是 Stage 3/4：AIME'24 从 83.8 降到 81.4，LiveCodeBench v5 从 68.4 降到 65.7，论文明确接受这个 trade-off（§4.7）。

01

把 chat 和 reasoning 分成两个模型，切换成本落在用户侧

Qwen2.5 与 QwQ 是两条产品线；Qwen3 要把两种行为、以及思考长度控制，压进同一套权重。

Qwen3 之前，开源模型通常用两条产品线覆盖两类请求：Qwen2.5 负责通用对话，QwQ 负责多步推理。 用户要在两者之间切换，部署方要维护两套权重和两套推理配置（§1）。

合并的难点不在注意力结构。Qwen3 仍然用 GQA、SwiGLU、RoPE 和 pre-norm RMSNorm； 真正的改动是让同一套权重在两种行为之间切换，并且让用户在推理中途按 token budget 截断思考（§1、§4.3）。

第三个约束是尺寸覆盖：Qwen3 要同时发布 6 个 dense 和 2 个 MoE。 如果每个尺寸都独立跑完 reasoning RL，训练成本会随尺寸增长； Qwen3 的选择是只让 32B/235B 走完四段，其余尺寸向它们蒸馏（§4.5）。

核心矛盾

模式控制、预算控制、尺寸覆盖，三件事叠在一起

模式控制决定模型要不要写思考链；预算控制决定思考链什么时候停；尺寸覆盖决定哪些模型有能力自己练出这两种行为。 三者共享同一套 tokenizer（151,669 词表）与 chat template；否则部署侧仍然要按模型分支（§2、§4.3）。

02

旧方案各自缺一块：分开的模型、逐尺寸 RL、带 shared expert 的 MoE

Qwen3 的改动可以拆成三处：模式融合、蒸馏替代小模型 RL、MoE 去掉 shared expert。

两套权重

分开的 chat 与 reasoning 模型

Qwen2.5 + QwQ 的路线能覆盖两类请求，但切换靠换模型；同一个请求里不能按需开关思考，也不能在中途截断（§1）。

逐尺寸 RL

每个尺寸独立做 reasoning RL

Reasoning RL 需要 query-verifier 和大量 rollout；小模型也能涨，但 GPU 小时不划算。Qwen3 改为旗舰走四段、其余蒸馏（§4.5、§4.7）。

MoE 选择

去掉 shared expert

Qwen2.5-MoE 使用 shared expert；Qwen3-MoE 改为 128 总专家 / 8 激活，并移除 shared expert，用 global-batch load balancing loss 促进专家 specialization（§2）。

Qwen3 保留 Qwen2.5 的 GQA、SwiGLU、RoPE、pre-norm RMSNorm； 改动是移除 Qwen2 使用的 QKV-bias、加入 QK-Norm（§2）。这些是稳定性改动，注意力仍是 GQA。

  • QKV-bias：Qwen3 移除 Qwen2 使用的 QKV-bias，加入 QK-Norm，论文给出的理由是稳定训练（§2）。
  • MoE 专家：沿用 Qwen2.5-MoE 的 fine-grained expert segmentation，但把 shared expert 去掉；128 个总专家、每 token 激活 8 个（§2、Table 2）。
  • 负载均衡：用 global-batch load balancing loss 鼓励专家 specialization；本页未获取 shared expert 的消融数据，不替它补因果（§2）。
  • tokenizer：沿用 Qwen 的 byte-level BPE，词表 151,669（§2）。
03

先把 reasoning 练出来，再用 chat template 把两种模式焊在一起

四段里前两段只练 thinking，第三段才引入 non-thinking；模式切换靠模板，不靠两套权重。

Stage 1 · Long-CoT 冷启动：学格式，不追分数

数据覆盖数学、代码、逻辑推理和通用 STEM。先用 Qwen2.5-72B-Instruct 过滤掉不易验证、含多个子问题、或不用 CoT 就能答对的 query， 再用 QwQ-32B 为每个 query 生成 N 个候选，按答案错、重复、明显猜测、thinking 与 summary 不一致、语言混用、与验证集过近等标准过滤。 目标是让模型学会推理格式，而不是在这一步把分数拉满，所以论文倾向压小样本数和训练步数（§4.1）。

Stage 2 · Reasoning RL：用可验证 reward 把数学和代码拉起来

query-verifier 对要满足：未在冷启动用过、冷启动模型可学、尽量难、覆盖多个子域。 最终收集 3,995 对，用 GRPO 更新。训练上用大 batch、每个 query 多次 rollout、off-policy 提高样本效率，并控制熵稳定； 170 步内，Qwen3-235B-A22B 的 AIME'24 从 70.1 升到 85.1（§4.2）。

Stage 3 · Thinking Mode Fusion：同一套权重，两种回答格式

做法是在 Stage 2 模型上继续 SFT：thinking 数据用 Stage 2 模型对 Stage 1 query 做拒绝采样生成，避免额外的 SFT 把 Stage 2 的能力冲掉； non-thinking 数据覆盖代码、数学、指令跟随、多语言、创意写作、问答和角色扮演，并用自动 checklist 评质量；低资源语言还提高了翻译任务比例（§4.3）。

模式切换靠 chat template：thinking 样本在 user query 或 system message 里带 /think，non-thinking 带 /no_think； non-thinking 的 assistant 回复保留一个空的 <think></think> 块，保证格式一致。 默认是 thinking，所以训练里也有不带 flag 的 thinking 样本；多轮对话随机插入多个 flag，模型跟最后一个走（§4.3、Table 9）。

Table 9（Qwen3 技术报告）：thinking 与 non-thinking 的 SFT 模板，按原文转录、换行省略；原文说明 thinking 模式下 /think 可省略，因为它是默认行为。

Budget 控制不是单独训练的模块。模型在 Stage 3 学会两种模式后，论文发现它也能处理“思考到一半”的输入： 当思考长度达到用户阈值，就手动插入一句停止指令，让模型基于已有推理直接给答案。停止指令的核心是 Considering the limited time by the user, I have to give the solution based on the thinking directly now.</think>.； 论文明确说这个能力没有被显式训练，是 Thinking Mode Fusion 的自然结果（§4.3）。

Stage 4 · General RL：补通用、指令和 agent；Stage 3 已回退，Stage 4 继续小幅回退

奖励系统覆盖 20+ 个任务，目标是指令跟随、格式跟随、偏好对齐、agent 能力和 RAG 等专项场景； 奖励分 3 类：规则奖励、带参考答案的模型奖励、不带参考答案的模型奖励（§4.4）。 agent 任务的 rollout 允许模型与真实环境做完整多轮交互，用执行反馈训练长程决策（§4.4）。

四段的分工

前两段造能力，第三段造接口，第四段补通用

Stage 1 学格式，Stage 2 用可验证 reward 把数学/代码推理拉起来，Stage 3 把 non-thinking 融进同一套权重并让 budget 截断成为可能， Stage 4 用多任务 reward 补通用、指令和 agent。代价出现在 Stage 3/4：专项数学和代码在 thinking 模式下回退（Table 22、§4.7）。

04

36T token 分三段；MoE 每 token 只激活 8/128 个专家

先把通用能力堆到 30T+，再用 5T 高质量数据补 reasoning，最后用长上下文阶段把训练窗口拉到 32K；MoE 的稀疏度决定每 token 的算力。

预训练数据 36T tokens、119 种语言和方言；相比 Qwen2.5，token 数是 2 倍、语言数是 3 倍。 PDF 文本用 Qwen2.5-VL 识别、Qwen2.5 精炼；合成数据来自 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder； 30T+ tokens 做了教育价值、领域、安全等多维标注，数据配比在 instance 级做消融（§3.1）。

07

边界：小模型不走四段 RL，模式融合也不是免费午餐

把 Qwen3 当成一个统一模型之前，先确认尺寸、模式、上下文和评测口径。

  • 尺寸分叉：0.6B/1.7B/4B/8B/14B 和 30B-A3B 走 strong-to-weak 蒸馏；32B/235B 走四段。小模型的能力来自教师，不是自己跑完四段 RL。
  • 模式能力是学出来的，budget 截断是涌现的：论文明确说它没有被显式训练（§4.3）。不要假设任意模型、任意 budget 下都能稳定截断。
  • thinking 不总是更好：RULER 235B 95.0 → 92.2、32B 93.7 → 91.0；GPQA/INCLUDE 也有 thinking 低于基线（Table 11、Table 23）。
  • Stage 3/4 有代价：AIME'24 83.8 → 81.4、LiveCodeBench 68.4 → 65.7（Table 22）；Stage 3 已回退，Stage 4 继续小幅回退。论文接受这个 trade-off（§4.7）。
  • 蒸馏证据的范围：Table 21 只比较 8B 学生、数学与代码 query；不能外推到所有尺寸、所有任务（§4.7）。
  • 上下文分档：0.6B/1.7B 是 32K，其余是 128K；长上下文阶段本身只训到 32,768，128K 靠推理扩展（§3.2、Table 1）。
  • Qwen3-Next / Coder-Next 是另一条线：Qwen3-Next 用 Gated DeltaNet + Gated Attention 3:1、 512 专家 / 10 激活 / 1 shared、15T tokens、 262,144 原生上下文；Coder-Next 基于 Qwen3-Next，80B/3B、 256K。这些数字不属于 Qwen3 主报告。

Qwen3-Next 的总专家数是 Qwen3-MoE 的 512 / 128 = 4 倍（本页复算），并且包含 1 个 shared expert； 它和 Qwen3 的 128 专家 / 无 shared expert 是两套设计，不能把 512 专家的稀疏度直接套到 Qwen3-235B-A22B 上（Qwen3-Next §Model Overview、§2）。

系列谱系。Qwen3 的数字来自 Table 1/2/3/5；Qwen3-Next 来自官方 HF 模型卡 §Model Overview（读取于 2026-11-06）； Qwen3-Coder-Next 的 80B/3B 来自 arXiv 2603.00729v1 §1；48 层来自官方模型卡 Qwen/Qwen3-Coder-Next 的 §Model Overview；256K 标称来自同一模型卡的 Highlights（Model Overview 与 arXiv §3.1 写 262,144，二者是同一上下文长度）。三份材料的口径不同，不要跨列比较。

什么时候别用

  • 需要确定性的思考长度。budget 截断是 Stage 3 的涌现行为，不是可证明的控制器；论文没有给任意 budget 下的稳定性保证（§4.3）。
  • 只部署小模型却想要 235B 的 thinking 上限。0.6B–14B 与 30B-A3B 是蒸馏产物，不是四段 RL 的同构缩小版（§4.5）。
  • 把 128K 当所有尺寸的默认。0.6B/1.7B 是 32K；长上下文阶段本身只训到 32,768（Table 1、§3.2）。
  • 把 Qwen3-Next 的规格当成 Qwen3 的规格。Qwen3-Next 是另一份官方模型卡/报告，专家数、注意力结构和上下文都不同（Qwen3-Next §Model Overview）。
一句话

核心不是新注意力，而是三条可分别验证的工程路径

mode fusion 把两种行为压进同一套权重；strong-to-weak distillation 让小模型不用逐尺寸跑 RL； sparse MoE 把每 token 的算力压到 22B/235B。三条路径各有各的边界，不能互相替代。
