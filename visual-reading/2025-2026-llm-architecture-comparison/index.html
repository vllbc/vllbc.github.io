九个模型，三本账：
激活参数、KV cache、长上下文

2026-11-06 9 个主模型 · 8 份技术报告 + 1 份模型卡 从问题开始
TL;DR · 30 秒抓住三本账

先给结论：2025–2026 的旗舰模型不再用「总参数」单轴比较。DeepSeek-V3 用 37B 激活撑 671B 总参数；Kimi K2 把总参数推到 1.04T，激活仍只有 32.6B；Qwen3-Next 与 Kimi Linear 则把注意力本身做成混合结构，用 3:1 的线性/全注意力层比例换长上下文。

但「激活参数少」不等于「一定更快」。三本账要分开算：训练/推理的算力看激活参数与 token 数；解码显存看 KV cache 的形状与层数；长上下文能力看位置编码、注意力窗口和线性状态，而不是只看 context length 的标称值。

01

参数规模不再是唯一坐标：37B 激活也能撑起 671B 总参数

读完这节你应该知道：为什么 2025–2026 的架构比较必须同时看总参数、激活参数和注意力形状，而不能只看一个参数量。

在 dense 时代，参数量同时是容量、每 token 算力和显存占用的近似代理：参数越多，模型越大，训练和推理也越贵。稀疏 MoE 把这三个量拆开了。总参数决定模型能存多少专家、能覆盖多大的知识容量；激活参数只计算每个 token 实际走到的专家；attention 的形状则决定解码时 KV cache 的大小。三者不再同向变化。

这带来三个直接后果。第一，比较两个 MoE 模型时，只看总参数会高估每 token 算力；只看激活参数会低估存储和专家并行的成本。第二，MLA、GQA、banded/full 交替和线性混合都会改变 KV cache 的增长率，同样的 128K context，解码显存可能差一个数量级。第三，标称 context length 只是一个上限，位置编码和注意力窗口才决定这个上限能不能用。

所以本页把架构拆成三本账：参数账、缓存账、上下文账。后面所有模型都按这三本账并列，而不是按「总参数排行榜」排列。

这三本账不是独立的。专家的 intermediate size 会影响参数账，也会影响每 token 的 all-to-all 通信；MLA 的潜维 d_c 会同时影响缓存账和 attention 的 up-projection 开销；位置编码的选择会和 context extension 的训练阶段绑定。把它们分开，只是为了不让一个数字掩盖另一个数字。

02

三条路线：dense 求稳、稀疏 MoE 省算力、线性混合省 KV

读完这节你应该知道：九个主模型不是九个孤立配置，而是三种取舍——用更多总参数换容量、用更少激活参数换算力、用混合注意力换长上下文。

Dense

Qwen3-32B

32B / 32B，全部参数每 token 都参与；64 层，GQA 64 Q / 8 KV，128K context。结构简单、并行策略直接，代价是每 token 算力随参数量线性增长。

本页只把它当 dense 参照，不计入九个主模型。

Sparse MoE

六个旗舰

总参数从 116.8B 到 1.04T，激活从 5.1B 到 37B；专家数 128–384，shared expert 0–1。

稀疏度的差异比参数量差异更大：Qwen3 的 128/8、DeepSeek 的 256+1/8、K2 的 384+1/8、GLM 的 160+1/8、gpt-oss 的 128/top-4、MiniMax 的 256/8，每 token 只走一小撮专家。

Hybrid / linear

三个效率模型

Qwen3-Next 用 3:1 的 Gated DeltaNet : Gated Attention；Kimi Linear 用 3:1 的 KDA : full MLA；Nemotron 3 Nano 用 6 层 GQA + 其余 Mamba-2（52 层）。

共同点：全注意力层只占少数，KV cache 只按这些层算；线性/状态层的开销不随 context 线性增长，但状态精度和 kernel 实现变成新的边界。

三条路线不是互斥的。Qwen3-Next、Kimi Linear、Nemotron 3 Nano 同时也是稀疏 MoE；Qwen3-235B 是 MoE 但没有 shared expert；DeepSeek-V3 和 K2 是「MLA + 细粒度 MoE」；GLM-4.5 和 MiniMax-M2 在 MoE 之外保留了 full attention。把它们分成三张卡片，是为了看清每个模型主要用哪种手段换效率，而不是给它们贴阵营标签。

03

四个开关决定架构差异：专家稀疏、注意力混合、Norm 位置、位置编码

读完这节你应该知道：把九个模型拉开差距的，不是某个单点技巧，而是四个可以独立拨动的开关；下面的对照台可以按维度切换。

开关 1

专家稀疏

看三个数：总专家数、每 token 激活专家数、shared expert 数。DeepSeek-V3 是 256 + 1 / 8，K2 是 384 + 1 / 8，Qwen3 是 128 / 8 + 0 shared。专家越细、稀疏度越高，每 token 算力越省，但路由和 all-to-all 越复杂。

开关 2

注意力混合

MLA 缓存低秩潜向量，GQA 共享 KV 头，banded/full 交替把局部窗口和全局层分开，线性注意力把历史压成状态。四种手段都能降 KV，但降的是不同的账：MLA 降每层元素数，GQA 降 KV 头数，banded 降窗口，线性降增长率。

开关 3

Norm 位置

Qwen3 用 Pre-RMSNorm + QK-Norm；GLM-4.5 用 QK-Norm；K2 则明确说 QK-Norm 不适用于 MLA，改用 QK-Clip。Norm 放在 attention 前、QK 上还是只做权重裁剪，会改变训练稳定性，但不直接改变推理的 KV 形状。

开关 4

位置编码

RoPE、partial RoPE、NoPE、完全无位置编码都在这一页出现。Kimi Linear 在 MLA 层用 NoPE，把位置信息交给 KDA；Nemotron 3 Nano 不用任何 positional embedding；Qwen3-Next 的 Gated Attention 只保留 64 维 RoPE。NoPE 不等于没有位置信息，只是位置信息由别的层携带。

04

算力看激活参数，解码看 KV cache；两者不是同一本账

读完这节你应该知道：激活参数少不等于 KV cache 小——KV cache 由层数、KV 头数、head dim 和精度决定，和总参数/激活参数不是同一条公式。

训练和推理的算力主要随「每 token 实际参与矩阵乘的激活参数」增长。MoE 每 token 只走 top-k 专家，所以 推断（依据：Table 2A 的激活专家数是 top-4/top-8，激活参数为 5.1B–37B；实际 FLOPs 还受 attention、shared expert 和 EP 通信影响）不能把总参数直接当每 token 算力。反过来，解码阶段的显存瓶颈主要不是权重，而是 KV cache：它随 context 长度线性增长，且每层都要存。

KV cache 的账本只有三个乘数：层数 × 每层缓存的元素数 × 每元素字节数。MLA 把每层的 KV 压成 c_KV（d_c）和 k_R（d_R）；GQA 缓存 2（K 和 V）× KV 头数 × head dim；线性注意力把历史压成常数状态，不随上下文线性增长。下面的计算器只算全注意力层的 KV，不把线性状态混进来。

05

同一副 Transformer 骨架，四种层堆叠

读完这节你应该知道：九个模型都能画成 decoder-only 骨架，但层内顺序和注意力/FFN 的组合方式不同；这张图只画类型，不按真实层数比例。

DeepSeek-V3 是 61 层 / 7168 hidden 的 MLA + MoE；Kimi K2 也是 61 层 / 7168 hidden，但专家数从 256 + 1 增到 384 + 1，attention heads 从 128 降到 64，dense 层从 3 降到 1。两个模型都用 MLA，却用不同的稀疏度换容量。

Qwen3-235B 是 94 层、128 experts / 8 active、GQA 64 Q / 4 KV，没有 shared expert（0 shared），但加了 QK-Norm；它有 128K context，报告没有给 hidden 和 head dim，本页留空。

Qwen3-Next 与 Kimi Linear 把大部分层换成线性注意力：前者是 3:1 的 Gated DeltaNet : Gated Attention，后者是 3:1 的 KDA : full MLA。Nemotron 3 Nano 把大部分层换成 Mamba-2，只保留 6 层 GQA（共 52 层）。三者的全注意力层只占少数，KV cache 只按这些层算；线性/状态层的状态另算，不混进 KV cache。

07

边界：跨报告的数字不能直接排名

读完这节你应该知道：这张表能回答「谁用了什么结构」，不能回答「谁更强」；评测分数、训练 token、硬件和精度都不同口径。

不同报告的评测协议不同：Qwen3 系列用 36T token 训练，Kimi K2 用 15.5T，Nemotron 3 Nano 用 25T；gpt-oss 的 2.1M H100 hours 与 DeepSeek 的 2.788M H800 hours 不是同一硬件、同一精度、同一模型规模。把 MMLU 分数并列排名会制造虚假精度。

MoE 的激活参数不等于实际 FLOPs：路由、共享专家、attention、embedding 都计入不同的账；KV cache 也受 dtype、paging、prefix caching、张量并行切分影响。本页的 KV 表只算全注意力层，且用 2 B/值 的 BF16 假设。

跨报告还有一个更隐蔽的问题：同名指标的分母不同。比如「激活参数」有的含 embedding，有的不含；「context length」有的是训练长度，有的是外推后的标称上限。遇到这种差异，本页只并列，不替论文消解。
