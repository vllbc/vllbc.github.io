RLPR：用参考答案的平均 token 概率当奖励，绕开验证器

RLPR 不判断模型答案对不对。模型照常生成完整回答 o=z∥y，但奖励计算时把生成的 y 替换成参考答案 y*，得到 o′=z∥y*，读取 y* 每个 token 的平均概率作为奖励；不把 y 送进验证器。再减去“没有推理链时”的同一概率，得到去偏奖励。Qwen2.5-7B：MMLU-Pro 从 Instruct 对照的 54.5 到 56.0、TheoremQA 从 Instruct 的 47.3 到 55.4（RLPR 从 Base 起训练），训练不需要外部验证器。

Tianyu Yu、Bo Ji、Shouli Wang 等 · 清华 / NUS / 上海期智研究院 / 哈工大 / BUPT / UIUC 等 原文 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

RLPR 的奖励是参考答案 y* 在给定推理链 z 下的平均 token 概率：mean(πθ(y*i|x,z,y*<i))。它比序列似然（论文用 n 次根归一化的概率乘积）稳健，因为未归一化的乘积会被单个低概率 token 主导：论文举例 (0.01,0.7,0.9) 与 (0.05,0.7,0.9) 的乘积相差 5 倍，均值只差 0.013。

为去掉“问题本身或答案格式”带来的偏置，RLPR 再算一次“不给推理链、直接生成 y*”的概率 r′，用 clip(0,1,r−r′) 作为最终奖励；训练时用 GRPO，并按奖励标准差动态过滤太简单/太难的 prompt。

Qwen2.5-7B 的七基准总平均 53.6，高于 RLVR 的 52.6 与 General Reasoner 的 52.0；但 GPQA 上 Oat-Zero 38.8 高于 RLPR 37.6，MATH-500/AIME 也不是 RLPR 最高，数学专项模型仍更强。

01

RLVR 的奖励靠验证器，通用领域的答案却没法规则判等

数学和代码有符号验证器或沙箱；开放式问答、法律、生物、商业没有廉价而可靠的“判对错”程序。

标准 RLVR 给每个回答一个标量奖励：

J(θ) = Ez,y∼πθ(·|x) [ fverifier(y, y*) ]
Eq. 1：z 是推理链，y 是最终答案，fverifier 是任务特定的规则验证器。

规则验证器在数学题上是 Math-Verify，在代码上是沙箱执行；换到自然语言答案，验证器要处理同义改写、部分正确、格式差异，工程量迅速失控。另一种办法是训练一个模型验证器，但论文指出这需要大量标注、奖励质量不稳定、还要在训练时额外维护一个模型。

规则验证器

便宜、确定、不可扩展

答案可判等时很好；自由形式答案的多样性让规则覆盖不过来，论文的原话是“impossible to devise rule-based verifiers”。

模型验证器

通用、昂贵、奖励质量有限

要训练专门的判等模型（如 General Reasoner 的 1.5B verifier），需要标注数据，训练框架更复杂，还会多一份推理成本。

RLPR 的观察是：模型对参考答案的生成概率，本身就是它对自己推理质量的内部评价。如果推理链 z 好，模型应该更“敢”生成 y*；如果 z 差，概率就低。于是奖励可以从模型内部读出，而不必外接一个裁判。

02

VeriFree 已经用过参考答案概率，RLPR 改的是聚合方式与去偏

两条路线都不需要验证器，差别在奖励怎么从 token 概率变成一个标量，以及怎么处理“问题本身带来的偏置”。

表中 VeriFree 的“<7 token”来自 RLPR 论文对其复现设置的描述（§3.1）；RLPR 自己不做这个长度限制。

序列似然是 ∏pi（论文实际用 n 次根归一化，fseq = (∏pi)1/n；下面的 5 倍按未归一化乘积口径计算，用来说明低概率 token 的影响）。论文给了一个直观例子：概率序列 (0.01, 0.7, 0.9) 与 (0.05, 0.7, 0.9) 只差第一个 token，但乘积结果相差 5 倍；对长答案，只要出现一个极低概率 token，奖励就会被压到接近 0。平均概率把每个 token 的贡献拉平，更接近“整体置信度”。

但平均概率仍有偏置：有些问题本身就让模型容易/不容易生成 y*，这与推理链 z 无关。RLPR 用“无推理链时直接生成 y*”的概率 r′ 作基线，奖励变成 r−r′，衡量的是“经过思考后，置信度提升了多少”。

03

奖励 = 平均 token 概率 − 无推理基线，再按标准差筛 prompt

三个组件：平均概率、去偏、标准差过滤；训练算法仍是 GRPO。

1 · 平均 token 概率

把模型回答拆成推理链 z 和答案 y，用数据集里的 y* 替换 y，得到 o′=z∥y*；把 o′ 喂给策略模型，取 y* 对应 token 的概率：

r = fseq({pi | o′i ∈ y*}) = (1/|y*|) Σi pi
Eq. 2：fseq 取平均，而不是连乘；pi 是 y* 第 i 个 token 的生成概率。

2 · 去偏

再算一次没有推理链的基线 r′：直接把 y* 喂给模型（不加 z），用同一公式取平均概率。最终奖励：

r̂ = clip(0, 1, r − r′)
Eq. 4：clip 到 [0,1]；r−r′ 表示“有了推理链之后，模型对 y* 的置信度增量”。

3 · 标准差过滤

GRPO 需要同一 prompt 的多条回答之间有奖励差异。若一组回答的奖励标准差很低（全高或全低），这题对当前模型太简单或太难，梯度信号弱。RLPR 用指数移动平均维护阈值 β，过滤掉奖励标准差低于 β 的 prompt；β 在 Qwen 上取 0.5，Llama 0.9，Gemma 1.0（Table 7）。

概率奖励计算器三个 token 概率 + 无推理基线 r′
平均概率、连乘与去偏奖励

平均概率 = (p1+p2+p3)/3；连乘 = p1p2p3（页面演示用原始连乘；论文的序列似然基线用 n 次根归一化）；去偏奖励 = clip(0,1,平均−r′)。r′ 是页面演示参数，不是论文的具体数据。

手算：默认 0.50 / 0.70 / 0.90，r′=0.30 与 JS 逐位一致

平均 = (0.50+0.70+0.90)/3 = 0.700；连乘 = 0.50×0.70×0.90 = 0.315；去偏 = clip(0,1,0.700−0.300) = 0.400。

换成论文的例子：(0.01,0.7,0.9) 平均 0.537、连乘 0.006；(0.05,0.7,0.9) 平均 0.550、连乘 0.032。平均只差 0.013（0.550−0.537）；连乘差 5.0 倍（按未舍入值 0.0315/0.0063；若按显示的四舍五入值 0.032/0.006 则约 5.3）。

若 r′ ≥ 平均，r̂ 被 clip 到 0；若平均−r′ > 1，r̂ 被 clip 到 1。页面没有把 clip 前的负值当成负奖励。

训练目标与 GRPO

最终梯度估计器就是策略梯度：

∇JRLPR(θ) = Eo∼πθ(·|x) [ r̂ ∇ log πθ(o|x) ]
Eq. 5：o = z∥y，奖励 r̂ 对整条回答做加权；实现上用 GRPO 的组归一化优势。

注意 RLPR 的奖励是连续的，不是 0/1；这让它可以给“部分正确”的回答一个中间分，而不是像规则验证器那样直接判 0。论文的 AUC 分析就是在检验这个连续分能否把正确回答排在错误回答前面（§3.3、Figure 4）。

05

生成 z 和 y → 拼 y* → 读 token 概率 → 去偏 → GRPO

关键差别：模型照常生成完整回答 o=z∥y，但奖励计算不把生成的 y 送进验证器，而是替换成 y* 做一次前向；奖励来自 z∥y* 的 token 概率。

07

它绕开验证器，但没有绕开参考答案与额外前向

RLPR 的边界可以归成三类：奖励依赖 y*、概率依赖 tokenization/语义、训练依赖额外计算与过滤超参。

参考答案质量

y* 错，奖励就错

RLPR 把“验证器质量”换成“参考答案质量”。若 y* 有错、有偏，或只是众多等价答案之一，概率奖励会放大这个信号。论文没有做参考答案噪声的鲁棒性实验。

语义等价

token 概率不理解同义改写

模型答案 y 与 y* 语义相同但措辞不同，PR 仍按 token 概率评分；平均概率比连乘稳健，但没有显式建模等价类。论文 §2.2 提到对同义改写敏感、平均概率更稳健，未单列局限。

训练成本上，每条回答多一次“拼接 y*”的前向；论文用 32×A100、768 prompt×8 条、4 次更新，未给总 GPU 小时。与“只做一次推理”相比，RLPR 仍是大规模 RL 训练，不是免费的测试时技巧。β 过滤阈值也需要按模型调（Qwen 0.5、Llama 0.9、Gemma 1.0）。

评测上，主实验用多选题与可抽取答案，WebInst. 是 held-out 验证集并做了 10-gram 去重；开放式生成、长文本、代码、多模态没有验证。论文的“通用领域”仍是 benchmark 意义上的通用，不等于任意自由形式任务。

理论上，RLPR 没有收敛性证明或最优性保证；它给的是奖励质量的经验分析（AUC、与长度/熵的相关性）和消融。RLPR 的奖励是启发式的连续信号，论文没有声称它与 RLVR 目标等价。
