用 0.8k 样本、50 步，把 7B 推理模型的 CoT 砍掉一半

大推理模型在简单题上也会生成几千 token 的思维链。这篇论文不跑在线 RL，也不训练奖励模型：它从模型自己的 16 次采样里挑出「最短的正确」和「最长的正确」组成偏好对，再用一个不含 NLL 项的 Bradley-Terry 目标做 50 步离线训练。代价约为 10.4 A100·h（7B），换来多个基准上约一半的长度削减。

论文先回答 RQ1：模型自己的生成空间里存在更短但同样有效的路径。在 LIMR 上每题采样 16 条输出并按长度排序，7B 模型在排序 10 之后性能才明显退化，1.5B 从排序 7 开始退化；排序 0–6 的短轨迹基本稳定（Figure 2a）。

01

长 CoT 的麻烦，是简单题也在过度思考

读完这节，你应该知道两件事：更长的推理轨迹并不更好；模型对难度的感知和真实能力错位。

Figure 1 给了一个 MATH-500 的例子：DeepSeek-R1-Distill-Qwen-7B 用了 5,465 tokens 解一道题，经过 LCPO 训练后的模型只用 1,128 tokens，相对原始长度减少 79.37%（Figure 1）。这是一个样例，不是基准平均；它说明「更短且正确」的轨迹确实存在。

论文进一步在 LIMR 上做系统分析：每题采样 16 条输出，按长度排序，再看「第 r 短的轨迹集合」的整体准确率。Figure 2a 显示，7B 模型在排序 10 之后开始明显退化，1.5B 从排序 7 就开始退化；排序 0–6 的短轨迹，性能基本稳定（Figure 2a）。这是 RQ1 的肯定回答。

核心错位

模型能用约 2,200 tokens 达到 90% 以上准确率，却平均花 7,000 tokens

§3.2 的原话是：模型可以在约 2,200 tokens 内达到 90% 以上准确率，但在同样的任务上平均需要 7,000 tokens 才能完成推理。作者把这称为「perceived difficulty 与 actual capability 的 misalignment」——不是模型不会做，是它觉得自己需要想更久。

Figure 4 把这种错位具体化到 MATH-500 的难度等级：训练前，最简单的 Level 1 平均输出长度反而高于 Level 2 和 Level 3（Figure 4）。简单题消耗更多 token，正是「过度思考」的直接表现。

所以问题不是「把 CoT 截短」这么简单：截断可能删掉必要步骤；而要让模型自己学会在简单题上写短、在难题上保持探索，就需要改变生成分布。论文把约束写得很清楚：在有限数据与有限训练下做到这一点。

02

三条现成路线，各自卡在成本或稳定性

论文的对照不只是「谁更准」，而是「要多少数据、多少算力、是否稳定」。

推理时

CoD / 提示词压缩

不改权重，在 prompt 或生成过程里加长度提示，让模型早点停。成本最低，但 §1 指出这类方法长度下降不稳定，而且经常牺牲推理能力。

在线 RL

L1 / TrEff / ThinkPrune

在 accuracy reward 之外加长度奖励，或设置 token budget 做预算强制。效果强，但需要大规模在线 RL 和复杂训练系统；budget 还要人工预先设定。

离线偏好

DAST

用通过率估计难度、构造偏好数据，再用 SimPO 训练。路线与本文最接近，但 Table 1 里 DAST 需要 150k rollout 数据和 20.6k 训练样本。

Table 1（v2）把数据账摊开：L1 需要 645k 训练样本，TrEff 24.8k，DAST 20.6k；本文方法用 22k rollout 数据、0.8k 训练样本。这里的「Data」是 rollout 数据量，「Train Samples」是实际参与训练的样本量。

03

把「最短的正确」和「最长的正确」放在一起，直接优化长度偏好

方法有两半：用通过率把题目分成 easy/medium/difficult，只拿 easy 构造偏好对；再用一条不含 NLL 项的 BT 损失训练。

3.1 数据：easy 不是「通过率高」，是 16 次全对

论文对每题采样 16 条输出，记 s_i 为这 16 条的平均准确率，然后按 Eq. 2 打标签：

label(qi) = easy if si = 1  ·  medium if 0 < si < 1  ·  difficult if si = 0
Eq. 2（§3.2）：标签由 16 次采样的平均通过率决定；训练只用 easy split。

偏好对的构造规则在 Appendix B 里写得更细：easy split 取最短的正确回答为 chosen、最长的正确回答为 rejected；medium split 取最短正确 vs 最长错误，并过滤掉「最长错误比最短正确还短」的题；difficult split 直接取最短 vs 最长，不看正确性（Appendix B）。训练用的是 easy split（§3.2），所以主实验的偏好对全部来自「16 次全对」的题。

3.2 目标：用序列级 log-odds 直接比较 chosen 和 rejected

先把偏好优化写成 BT 损失。Eq. 8 是常规形式，ε 设为 0：

−log σ( β rθ(yw|x) − β rθ(yl|x) + ε )
Eq. 8（§3.3.3）：Bradley-Terry 损失；论文设 ε=0 以让模型更早收敛。

关键是把 NLL 也写成 BT 形式。论文定义长度归一化的序列概率 pθ(y|x) = exp( (1/|y|) log πθ(y|x) )，于是 NLL 的隐式奖励是：

rθ(y|x) = log( pθ(y|x) / (1 − pθ(y|x)) )
Eq. 10（§3.3.3）：序列级 reward；p 是长度归一化后的序列概率。

LCPO 直接把 chosen 与 rejected 的这个 reward 相减，套进 log-sigmoid：

LLCPO = log σ( log( pθ(yw|x) / (1 − pθ(yw|x)) ) − log( pθ(yl|x) / (1 − pθ(yl|x)) ) )
Eq. 11（§3.3.3）：LCPO 目标。没有 reference model，没有 reward model，也没有额外的 NLL/SFT 项。

符号照录：v2 的 Eq. 11 在 PDF 与 HTML 里都写作 log σ(...)，没有前导负号；同文 Eq. 8 的 BT 损失写作 −log σ(...)。页面按原文转录，不代改符号。

论文的解释是：SFT / ORPO 一类目标里含有 NLL 项，模型会倾向于拟合 chosen 的每个 token，收敛被 NLL 主导，长度偏好反而学得慢（§3.3.2、Appendix D）。LCPO 只保留 BT 部分，直接把「chosen 的序列级 log-odds 高于 rejected」作为优化信号。Appendix D 的结论是：BT 损失提供可预测的收敛条件，NLL 会放大数据对收敛的影响；长度控制需要一个负的 reward 来抵消 NLL。

SFT / ORPO

NLL 项在场

SFT 只拟合 chosen（Eq. 21）；ORPO 把 NLL 与 BT 相加（Table 8）。Appendix D 推导出：当 chosen 概率升高后，ORPO 的收敛越来越由 NLL 主导。

LCPO

只留 BT

直接比较 chosen / rejected 的序列级 log-odds（Eq. 11）。没有 reference model，也不需要先训练 reward model；论文称目标「converge rapidly without requiring any hyperparameter tuning」（§3.3.3）。

07

它解决的是「长度」，不是「通用推理」

四条边界：训练分布、模型规模、训练上下文，以及可验证奖励的前提。

边界一

只验证了数学训练集

LIMR 是 MATH 训练集的一个子集，共 1,389 题（Appendix A）；Appendix H 明确说训练集聚焦 math tasks，简洁推理行为的多样性依赖 LRM 自身的潜力。OOD 测了 MMLU、GPQA-D、WinoGrande（Table 5），附录还测了 LiveCodeBench v6、AIME25、HLE-Math（Table 10），但这仍是有限外推，不能覆盖所有领域。

边界二

只做了 1.5B 和 7B

Appendix H 写明：受计算资源限制，只做了 1.5B 与 7B 两个规模。更大模型是否有同样的长度弹性、同样的难度筛选收益，论文没有验证。

边界三

训练上下文 2.3k，而基准原文长度远超

Appendix B 写 context length 限制为 2.3k；但 Table 3 的原始平均长度在 MATH-500 是 4,223、AIME24 是 13,411（7B）/16,355（1.5B）。Appendix B 没有展开超长偏好对如何截断或处理。推断（由这两个数字并列推出）：训练时可能对超长响应做了截断，这会影响长轨迹上的偏好信号。

边界四

需要可验证的正确性

s_i 是 16 条输出的平均准确率（§3.2），依赖一个正确性判定器。开放式任务没有这种可验证信号，easy/medium/difficult 的划分不能直接照搬。推断（由 s_i 的定义推出）：这类任务需要先构造可验证的评分，或者改用别的难度代理。

另外，准确率不是处处持平：7B 的 AIME24 −2.71、AMC23 −1.09、MATH-500 −0.80；1.5B 的 AIME24 +0.41、GSM8K −0.46（Table 3）。AIME24/AMC23 的评测是 16 次采样的 pass@1（§4.1）；如果应用对这几个基准特别敏感，需要单独评估。

成本也不是零：7B 约 10.4 A100·h（Table 11），rollout 的 16×1,389 次生成是主要成本（Appendix G.4）。论文强调这是一次性离线过程，数据可以复用；但如果换基座模型，偏好数据是否需要重新生成，论文没有讨论。
