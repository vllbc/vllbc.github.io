GSPO：把重要性采样从 token 级搬回序列级

GRPO 把同一个组内归一化优势分给整条响应，却仍按 token 计算重要性比率；论文认为这一步既没有完成分布校正，又把高方差噪声带进了长序列。 GSPO 改成用整条响应的似然比 si(θ) 做一次裁剪，让一条响应里的所有 token 共享同一权重。 代价是裁剪范围要缩到 3e-4 / 4e-4 量级，实验也只覆盖一个 MoE 底座的数学与代码任务。

Chujie Zheng, Shixuan Liu, Mingze Li, Xiong-Hui Chen, Bowen Yu 等 · Qwen Team, Alibaba arXiv 2507.18071v2 ↗ 博客笔记 ↗
TL;DR · 30 秒抓住核心

GSPO 的出发点是让优化单元与奖励单元对齐：奖励按整条响应给，重要性比率和裁剪也应该按整条响应做。 GRPO 的 token 级权重只基于每个位置的一次采样，重要性采样需要的「多样本平均」并不成立，结果是噪声而不是校正。

目标函数保留 GRPO 的组内相对优势，只把比率换成序列似然比的几何平均： si(θ) = (πθ(yi|x) / πold(yi|x))1/|yi|（Eq.7）。 长度归一化把不同长度响应的比率压到同一数值范围，否则少数 token 的似然变化就能让整条序列的比率剧烈波动。

梯度分析给出最直接的差别：GRPO 给每个 token 各自的权重（Eq.12），GSPO 给同一条响应的所有 token 相同权重（Eq.10）。 论文在 Qwen3-30B-A3B-Base 上报告：GSPO 训练更稳、在相同计算与 query 消耗下效果更好，并且不再需要 MoE 的 Routing Replay。

01

GRPO 的毛病不在裁剪太松，而在被裁剪的对象错了

先建立两个前提：大规模 RL 首先要稳；token 级重要性采样在长序列上会累积噪声。

论文把稳定训练列为扩大 RL 计算投入的首要前提。作者观察到，以 GRPO 为代表的现有算法在训练超大模型时会出现严重的稳定性问题，甚至导致灾难性且不可逆的模型崩溃；崩溃发生后，回退到旧 checkpoint、重新调裁剪范围、延长生成长度或更换 query 都不一定救得回来（§1、§3）。

论文给出的根因不是裁剪范围没调好，而是 GRPO 的重要性采样权重用错了层级。重要性采样的目标是估计目标分布下的期望，它依赖从行为分布抽取多个样本后对权重求平均：

Ez~πtar[ f(z) ] = Ez~πbeh[ (πtar(z) / πbeh(z)) · f(z) ]
Eq.4 · 重要性采样需要 N ≫ 1 个来自行为分布的样本，权重才能完成分布校正（§3）

GRPO 却在每个 token 位置 t 上使用 πθ(yi,t|x,yi,<t) / πold(yi,t|x,yi,<t)（πold 即论文的 πθold）。这个权重只基于下一 token 分布的一次采样 yi,t，没有多样本平均，因此没有完成它声称要做的分布校正；相反，它把高方差噪声带进梯度。序列越长，噪声累积越多，再被裁剪机制放大，最终可能把训练推向崩溃（§3）。

核心判断

奖励是序列级，优化却停在 token 级

论文把这一点上升为设计原则：优化目标的单元应该与奖励的单元匹配。既然 verifier 只对整条回答给一个分数，那么在 token 级做 off-policy 校正就没有对应的奖励粒度。GSPO 的全部改动都从这条原则推出（§3、§4.1）。

这也解释了为什么问题在长响应任务上更尖锐：token 数越多，单样本权重的噪声累积越久；模型越大、越稀疏，梯度里的小偏差越容易被放大。推断（依据：§3 明确写噪声随 response length 累积，并被 clipping 放大；§5.3 补充 MoE 稀疏激活会让 token 比率波动更大）。

02

PPO 甩掉 value model，GRPO 又引入 token 级噪声；MoE 还要额外补丁

两路对照：PPO 的代价是 value model，GRPO 的代价是 token 级比率；MoE 把后者的代价放大。

PPO

用 value model 换稳定性

PPO 用旧策略采样，通过裁剪把更新限制在旧策略附近。每个 token 的优势 Ât 由另一个 value model 估计（Eq.1）。

代价：value model 通常与策略模型体量相近，带来可观的内存与计算负担；算法效果还依赖 value 估计是否可靠，而把可靠的价值模型扩展到更长响应、更复杂任务本身就更难（§2）。

GRPO

用组内相对优势绕开 value model

GRPO 对同一个 query 采样 G 条响应，用组内归一化的奖励作为每条响应的优势，所有 token 共享这个优势（Eq.2–3）。这样就不需要 value model。

代价：重要性比率仍然是 token 级的 wi,t。论文认为这正是 §3 所说的高方差噪声来源；在 MoE 模型上，专家激活波动会让这些 token 比率进一步失真（§5.3）。

MoE 把 token 级比率的问题放大

MoE 的稀疏激活带来额外的稳定性问题。论文报告：在 48 层的 Qwen3-30B-A3B-Base 上，每次 RL 梯度更新后，对于同一条 rollout 样本，新策略 πθ 激活的专家里大约有 10% 与旧策略 πold 不同；模型越深，这个现象越明显（§5.3）。

专家组合一变，token 级重要性比率就会剧烈波动。此前的做法是 Routing Replay：缓存 πold 激活的专家，在 πθ 计算重要性比率时重放同一套路由，使新旧策略共享激活网络，从而恢复 token 比率的稳定性（§5.3）。Figure 3 显示，Routing Replay 对 GRPO 的 MoE 训练正常收敛起关键作用。

但 Routing Replay 不是免费的：复用路由模式会带来额外的内存与通信开销，还可能限制 MoE 模型的实际容量（§5.3）。GSPO 的切入点就是：如果只关心序列似然，就不需要让 token 级路由保持一致。

03

一条响应只算一个比率、只裁一次，所有 token 共享同一权重

三个公式：序列级目标、组内优势、序列似然比；再用梯度分析看清它和 GRPO 的差别。

目标函数：把 min/clip 从 token 移到响应

GSPO 保留 GRPO 的组采样与组内相对优势，只把优化对象从「每个 token 的比率」换成「整条响应的比率」：

JGSPO(θ) = Ex~D, {yi}~πold[ (1/G) Σi=1G min( si(θ) Âi, clip(si(θ), 1−εlow, 1+εhigh) Âi ) ]
Eq.5 · GSPO 目标：每条响应一个比率 si(θ)，整条响应一起裁剪；原文以 1±ε 记，§5.1 给出左右不同值，本页用 εlow/εhigh 表示
Âi = ( r(x,yi) − mean({r(x,yi)}i=1G) ) / std({r(x,yi)}i=1G)
Eq.6 · 组内归一化优势；同一条响应里的所有 token 共享 Âi
si(θ) = ( πθ(yi|x) / πold(yi|x) )1/|yi| = exp( (1/|yi|) Σt=1|yi| log( πθ(yi,t|x,yi,<t) / πold(yi,t|x,yi,<t) ) )
Eq.7 · 序列重要性比率：token 似然比的几何平均；指数 1/|yi| 是长度归一化

长度归一化不是为了好看。论文解释：如果不除以 |yi|，少数 token 的似然变化就能让整条序列的比率剧烈波动；不同长度响应也会需要不同的裁剪范围。归一化后，si 被压到统一的数值范围，裁剪范围才能对所有长度共用（§4.1）。论文也指出：正因为比率定义不同，两者通常相差数量级；因此两组数值不宜直接横向比较。推断

梯度分析：GRPO 每个 token 一个权重，GSPO 整条响应一个权重

忽略裁剪，GSPO 目标的梯度是：

∇θJGSPO(θ) = E[ (1/G) Σi=1G si(θ) Âi · (1/|yi|) Σt=1|yi| ∇θ log πθ(yi,t|x,yi,<t) ]
Eq.10 · 同一条响应内，所有 token 的梯度共享系数 si(θ) Âi / |yi|

作为对照，GRPO 的梯度是：

∇θJGRPO(θ) = E[ (1/G) Σi=1G Âi · (1/|yi|) Σt=1|yi| wi,t(θ) ∇θ log πθ(yi,t|x,yi,<t) ]
Eq.12 · 每个 token 有自己的 wi,t(θ)，权重在序列内不相等

论文进一步指出，GRPO 的这些不等权重不是可以忽略的小量：当 Âi > 0 时它们落在 (0, 1+ε]，当 Âi < 0 时落在 [1−ε, +∞)，并且会随训练累积，产生不可预测的后果。GSPO 则把同一条响应的所有 token 等权处理，直接消掉了这个不稳定性来源（§4.2）。

GSPO-token：序列级裁剪 + token 级优势

如果未来需要在多轮 RL 里做更细的优势分配，论文给出一个变体：保留 si(θ) 的序列级裁剪，但允许每个 token 有自己的 Âi,t。它把比率写成：

si,t(θ) = sg[ si(θ) ] · πθ(yi,t|x,yi,<t) / sg[ πθ(yi,t|x,yi,<t) ]
Eq.14 · sg[·] 表示只取数值、停止梯度（PyTorch 的 detach）；比率数值上等于 si(θ)

因为 πθ / sg[πθ] 的数值为 1，si,t 与 si 数值相同。论文证明：当所有 token 的 advantage 都设为 Âi 时，GSPO-token 与 GSPO 在目标、裁剪条件和理论梯度上完全相同；区别只在于前者允许逐 token 调整优势（Eq.13–17、§4.3）。论文没有报告 GSPO-token 的实验，它只是一条可扩展的接口。

04

没有额外 value model，但裁剪范围要缩到万分之一量级

工程账本：底座、采样协议、mini-batch、两组裁剪范围，以及 §5.4 的推理引擎可能性。

实验从一个 Qwen3-30B-A3B-Base 冷启动模型出发，每批 rollout 数据被切成 4 个 mini-batch 做梯度更新。评测协议是：AIME'24 用 32 次采样的平均 Pass@1；LiveCodeBench（202410–202502）用 8 次采样的平均 Pass@1；CodeForces 用 Elo rating（§5.1）。

换个说法：GSPO 的序列比率只有落在 [1−0.03%, 1+0.04%] 内才不被裁剪。这个量级说明它裁的是「整条响应偏离旧策略」这件事，而不是逐 token 的局部波动；一条响应里只要整体似然有明显漂移，整条就被排除出梯度估计。

§5.4 的工程承诺还停留在「可能」

训练引擎（如 Megatron）与推理引擎（如 SGLang、vLLM）之间存在精度差异，实践中通常要用训练引擎重新计算旧策略下采样响应的似然。论文认为，GSPO 只用序列级似然而非 token 级似然，前者对精度差异更宽容，因此有可能直接使用推理引擎返回的似然，省掉训练引擎的重算；这在 partial rollout、多轮 RL 和训练-推理分离的框架里尤其有价值（§5.4）。

但论文没有给出精度误差、重算耗时或端到端吞吐的测量，也没有报告 GPU 小时、显存或墙钟时间。§5.4 是一段方向性论证，不是已量化的工程结果。推断（依据：§5.4 全文只写 intuitively / makes it possible，未给实验或数字）。

07

它解决的是「序列级奖励下的稳定性」，不是通用 RL 的全部问题

论文自己承认的边界，加上从实验设置能看到的限制。

边界一

单一底座、单一算法对照

实验只用一个冷启动的 Qwen3-30B-A3B-Base，对照只有 GRPO；论文未报告 dense 模型、其他规模或其他 MoE 配置，也未报告与 PPO、DPO 或其他 RL 算法的直接比较。因此「GSPO 比 GRPO 更稳」有证据，「GSPO 是通用最优 RL 算法」没有证据（§5.1）。推断

边界二

任务限于可验证奖励的数学与代码

三个 benchmark 都是有明确正确答案的推理任务：AIME'24（数学）、LiveCodeBench（代码）、CodeForces（竞赛编程）。论文未报告开放写作、主观对话、多轮交互等奖励更模糊的任务。GSPO-token 虽然是针对多轮 RL 等需要更细优势分配的场景提出的接口，但论文没有跑任何多轮实验（§4.3、§5.1）。

边界三

没有超参数敏感性与方差报告

GSPO 的裁剪范围固定为 3e-4 / 4e-4，论文未报告敏感性分析；GRPO 的 0.2 / 0.27 被称为「仔细调参」后的值，但论文也未报告调参过程或方差。正文未报告误差带、seed 数或显著性检验，因此不能从图里读出稳定的置信区间（§5.1）。推断

边界四

工程收益尚未量化

§5.4 说 GSPO 的序列级似然对训练 / 推理引擎的精度差异更宽容，可能省掉重算；但论文未报告精度误差、重算耗时、吞吐或显存数据；Routing Replay 被去掉后省下多少内存与通信，论文也未量化。这些都是方向性判断，不是测量结果（§5.3、§5.4）。

什么时候别用：如果奖励不是「一条响应一个标量」，而是需要细粒度 credit assignment（例如多轮工具调用里每一步都该单独评价），GSPO 的序列级比率会把整条响应绑在一起；论文给出的 GSPO-token 只是接口，没有验证。反过来，如果任务短、模型密集、训练稳定，token 级噪声可能不是主要矛盾，GSPO 的收益也未必值得改动训练栈。推断（依据：论文只在长响应、MoE、可验证奖励的设置里报告收益，未覆盖上述场景）。
