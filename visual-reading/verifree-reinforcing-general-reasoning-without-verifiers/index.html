VeriFree：不训练验证器，把参考答案的概率当奖励

RLVR 需要规则或模型验证器判断“答案对不对”。VeriFree 绕开这一步：只让模型生成推理链 z，把数据集里的参考答案 y* 拼在后面，直接读模型对 y* 的条件概率 πθ(y*|x,z)。这个连续概率既当推理链的奖励，也当参考答案项的权重。Qwen3-8B 在 MMLU-Pro 上从 59.8 升到 67.2，SuperGPQA 从 31.0 升到 38.0，训练时不需要额外验证器模型。

Xiangxin Zhou、Zichen Liu、Anya Sims 等 · Sea AI Lab / 中科院 / NUS / Oxford / 中国人民大学 原文 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

传统 RLVR 的奖励是 0/1：模型生成完整回答 (z,y)，验证器比较 y 与 y*。VeriFree 把 y 从采样中拿出来，解析地求和：如果只有 y* 得 1，那么 Ey[1{y=y*}] 就等于 πθ(y*|x,z)。于是奖励从“对错判断”变成“模型对参考答案的置信度”，而且不需要验证器。

在唯一正确答案假设下，VeriFree 的目标与 RLVR 在期望上等价，梯度估计方差更低（Theorem 1，Rao-Blackwellization）。实际训练还要处理两个工程点：推理链与答案的 tokenization 边界，以及 RLOO 基线。

效果上，Qwen3-8B 的 MMLU-Pro 平均 59.8→67.2、SuperGPQA 31.0→38.0，超过同规模 Verifier 基线（65.9 / 37.1）；但 GPQA 上 1.7B 和 4B 的 VeriFree 反而低于 Verifier，不是每个基准都赢。

01

验证器是 RLVR 的入口，也是它扩不到通用领域的墙

R1-Zero 式训练在数学、代码上有效，因为答案可以用规则或测试用例判对错；法律、生物、商业没有这样廉价的 verifier。

标准 RLVR 把模型输出拆成推理链 z 和最终答案 y，用验证器给 0/1 奖励：

RVerifier(y; y*) = 1{ y ≡ y* }
Eq. 1 附近的奖励定义；≡ 表示语义等价，允许多种写法都被判对。

优化目标是先采样 z、再在 z 下采样 y，最大化期望奖励：

JVerifier(θ; x, y*) = Ez∼πθ(·|x) Ey∼πθ(·|x,z) [ RVerifier(y; y*) ]
Eq. 2：推理链和答案分两步采样，验证器只在最后判 y。

问题在于验证器。规则 verifier 只适用于答案可判等的任务；模型 verifier 要额外加载一个强 LLM，训练时占用显存、增加查询成本，还可能被 reward hacking——模型学会迎合验证器，而不是学会正确推理。论文把这两条路都视为“显式验证”，VeriFree 的目标是第三条路：不判断答案，只评估参考答案在给定推理链下的概率。

规则验证器

数学 / 代码可用

答案可解析、可执行；换到开放式问答、法律分析、商业策略就难以定义“正确”。

模型验证器

通用但有代价

用强 LLM 判等；需要额外显存与查询，且验证器本身可能被利用。论文的 Verifier 基线就是 Qwen2.5-Math-1.5B 微调出的判等模型。

VeriFree 仍然需要“参考答案 y*”，所以它不是“无监督”：它去掉的是验证器，不是参考答案。这个区别是后面所有边界的前提。

02

JLB / LaTRO 也在绕验证器，但优化的是下界且权重固定为 1

VeriFree 不是第一个“无验证器”思路；它的区别在于：在单一正确答案下精确恢复 RLVR 的目标，而不是优化一个下界。

把推理链 z 看成隐变量，JLB 与 LaTRO 分别优化 log Ez[πθ(y*|x,z)] 的下界。它们的梯度里，参考答案项 ∇θ log πθ(y*|x,z) 的权重固定为 1：不管推理链多差，都推高 y* 的概率。VeriFree 的权重是 πθ(y*|x,z) 本身：推理链差、置信度低，参考答案项的更新就小。

这也解释了论文为什么强调“exact”而不是“近似”：JLB/LaTRO 的目标与 RLVR 不完全相同，而 VeriFree 在假设成立时在期望上逐项对应相等。代价是它继承了“唯一答案”假设；多答案、语义等价答案的场景需要额外处理（§3.3 的等价类消融）。

03

把 y 从采样里拿出来：奖励变成 π(y*|x,z)，再用 RLOO 去基线

推导只有三步：条件期望、指示函数求和、把求和识别成概率。真正难的是让它在 token 级别可训练。

从 0/1 奖励到连续置信度

假设只有一个正确答案 y*，验证器奖励是 1{y=y*}。对 y 求期望：

Ey∼πθ(·|x,z)[ 1{y=y*} ] = Σy πθ(y|x,z) · 1{y=y*} = πθ(y*|x,z)
Eq. 4 的中间两步：不需要采样 y，直接算 y* 的概率。

因此目标变成：

JVeriFree(θ; x, y*) = Ez∼πθ(·|x) [ πθ(y*|x,z) ]
Eq. 4：只采样推理链 z，奖励是模型对参考答案的置信度。

对应的梯度有两项：

∇θJVeriFree = Ez[ Ri · ∇θ log πθ(z|x) + Ri · ∇θ log πθ(y*|x,z) ]
Eq. 5：Ri = πθ(y*|x,zi)。第一项更新推理链，第二项更新参考答案。

实现时对每个问题采样 G 条推理链，用 RLOO 基线减方差：

Ai = Ri − (1/(G−1)) Σj≠i Rj
∇θJ = (1/G) Σi [ Ai ∇θ log πθ(zi|x) + Ri ∇θ log πθ(y*|x,zi) ]
Eq. 7：G=8；参考答案项仍用 Ri 加权，推理链项用 RLOO 优势 Ai。
RLOO 优势计算器拖动三条推理链的置信度 Ri=π(y*|x,zi)
RLOO 优势（G=3，其余两条的均值作基线）

公式：Ai = Ri − mean(Rj≠i)。三条置信度都相等时，三条优势都为 0，推理链项没有更新信号；参考答案项仍按 Ri 加权。

手算：默认 0.60 / 0.30 / 0.20 与 JS 数值一致

A1 = 0.60 − (0.30+0.20)/2 = 0.35；A2 = 0.30 − (0.60+0.20)/2 = −0.10；A3 = 0.20 − (0.60+0.30)/2 = −0.25。

三个优势之和为 0.35−0.10−0.25=0，符合 RLOO 的零和性质。若三条都是 0.4，则每条基线也是 0.4，三个优势都为 0。

这里只演示 Eq. 7 的推理链项；实际训练中参考答案项仍用 Ri，而不是 Ai。

tokenization 的坑：停在 “<answer”，而不是 “<answer>”

如果按文本把回答切成 z 和 y，再换上 y*，同一个 “>” 在两种上下文里可能被 tokenizer 切成不同 token，导致训练与采样不一致。论文把 z 的结尾定义在 “<answer” 这个 token（不含 “>”），因为 “ r>” 不在标准 tokenizer 词表里；实现上等价于把 “<answer” 设为停止符，让 vLLM 直接采样 z。页面照原文写，不额外推断其他 tokenizer 的行为。

另一个工程点是 RLOO：论文说去掉 RLOO 会让最终 MMLU-Pro 准确率低 3 个百分点以上（原文 more than 3% lower，未说明相对/绝对；§3.3、Figure 6 左）；简单文本分割（w/o token split）则会引入 off-policy 数据、训练不稳定。两者都不是“可选项”，而是让 Eq. 7 可训练的必要组件。

04

8×H100、每题 8 条推理链、每步 16 题：省掉验证器，没省掉采样

VeriFree 不需要在显存里多放一个验证器，也不需要 reference model（无 KL）；但每题仍要采样 8 条推理链，再做一次参考答案的前向。

省下的

验证器模型的显存与查询；KL 项和 reference model；验证器被 reward hacking 的风险。

仍要付的

每题 8 条推理链的采样；一次参考答案前向（不做自回归解码）；约 3k–4k 步 RL 训练。

新增依赖

训练数据必须带参考答案 y*；答案质量直接决定奖励质量 推断，这一点论文没有专门讨论或量化（§5 结论与正文都未展开；原文没有 Limitations 章节）。

05

采样推理链 → 拼参考答案 → 一次前向 → RLOO → 更新

和 RLVR 的差别只在“奖励怎么来”：不生成答案、不调验证器，直接读参考答案的概率。

07

它去掉的是验证器，不是参考答案；唯一答案假设仍是硬约束

VeriFree 的边界比它的卖点更值得看：没有验证器不等于没有监督，概率奖励也不等于正确性保证。

唯一答案假设

多答案时目标不再精确等价

推导假设只有一个正确答案且精确匹配；多个等价答案（“1.6”与“8/5”）时，π(y*|x,z) 只覆盖其中一个字符串。论文用等价类数据做了初步消融，只有小幅提升（§3.3），没有给出多答案下的精确目标。

参考答案依赖

y* 错，奖励就错

VeriFree 把“验证器质量”换成“参考答案质量”。数据里的 y* 有错、有偏或只是众多答案之一时，模型会放大这个信号；论文的 WebData 用答案 <7 token 与 Qwen2.5-72B 过滤，但没有逐条人工审计。

评测上，主实验用多选题以便判等；开放式生成、长文本、代码、Agent 任务没有验证。多选题的“参考答案概率”与真实开放式推理的正确性之间还有距离 推断。论文也没有给出收敛性、最优性保证或 reward hacking 的形式化分析；它给的是期望等价与方差更低的定理，以及经验结果。

计算上，VeriFree 省掉验证器模型和 reference model，但每题仍要 8 条推理链；与“只做一次前向”的推理相比，训练成本仍在采样侧。页面没有把“省显存”外推成“总成本更低”：论文只报告 8×H100 与步数，没有给总 GPU 小时、单步耗时或峰值显存。

还有一个隐含假设：高质量推理链应该让模型对 y* 更自信。若模型用一条有缺陷的推理“碰巧”推出高置信度，VeriFree 会强化这条推理；论文的 ρ=0.82 是相关性，不是因果保证。这个风险论文没有专门讨论或量化（原文没有 Limitations 章节），页面把它作为机制边界保留。

笔记勘误（只改页面，不动笔记）：

  • 笔记说 VeriFree“稳定地优于或持平于需要额外验证器的 Verifier 方法”。Table 1 的 1.7B Avg 是 46.9 对 47.0（低 0.1 点）；Table 2 的 4B Med. 是 34.5 对 35.5；Table 3 的 GPQA 1.7B 30.3 对 36.4（低 6.1 点）、4B 42.4 对 44.4（低 2.0 点）。论文的准确表述是“matches and even surpasses”作为整体结论，不是每个基准、每个领域都占优。
  • 笔记说 Figure 4 的红色曲线“自始至终都位于灰色曲线之上”。论文正文写的是“VeriFree consistently outperforms the baseline”，页面只引用这句话与最终数值，不把平滑曲线读成逐步严格支配；图本身没有给出每一步的逐点差值。
  • 关于 NoMath 消融：Figure 5 只报告 Math-Eval-Suite 的聚合结果 推断，论文没有给出该图的逐基准数值；页面因此只写“无数学训练仍可迁移”的定性结论，不补逐项数字，也不拿 Table 3（完整 WebData 训练）的逐项结果去对照它。
  • 口径说明：无验证器不等于无监督。训练仍需要参考答案 y*，也需要一次前向计算 π(y*|x,z)；它不是无监督学习，也不能在没有参考答案的数据上直接使用。
  • 笔记说 VeriFree 与 Verifier 的对比“公平”，因为都用 Dr. GRPO。论文确实对 Verifier 基线用 Dr. GRPO 并保持其他设置一致，但 Verifier 的奖励还包含格式惩罚 −0.5 与长度惩罚 −0.05×min(10, |len 差|)（§3.1），VeriFree 的奖励只有 π(y*|x,z)。两者不是完全相同的奖励形状，页面在 §04 说明这一点。
