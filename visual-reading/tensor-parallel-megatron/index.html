Tensor Parallel：一层 Transformer 的两种切法

8.3B 的训练状态装不进一张 32GB V100。Megatron 没有把层拆开，而是把每层的矩阵按列、按行各切一刀（attention 与 MLP 两个子块各一套）： 第一刀让每张卡独立算 GeLU，第二刀在出口做一次 all-reduce 把部分和加回来。 代价是每层前向 2 次、反向 2 次 all-reduce；收益是每卡线性层权重和 GEMM 同步缩到 1/TP。

Shoeybi et al., NVIDIA · arXiv 1909.08053 v4 · Megatron-Core 70f7a26 原文 ↗ 源码 ↗ 文档 ↗
TL;DR · 30 秒抓住核心

Transformer 的两块计算都能拆成连续两个 GEMM：MLP 是 h → 4h → h，attention 是 QKV → 头内注意力 → 输出投影。 Megatron 把第一个 GEMM 按列切，让每张卡拿到一部分输出通道；把第二个 GEMM 按行切，让每张卡消费自己那份输入。

这样切的关键收益是中间不需要同步：GeLU、softmax 都在本卡的通道/头上独立完成。整个子块只在行并行的出口做一次 all-reduce，把各卡的部分和相加。一个 Transformer 层有 attention 和 MLP 两个子块，所以前向 2 次、反向 2 次。

通信量按激活大小走：每次 b·s·h 个元素，和 TP 度数无关；线性层权重则按 1/TP 缩小。8.3B 模型只用 8 路 TP（8 卡）时弱扩展效率 77%；再叠 64 路 DP、共 512 张 V100 后为 74%（§5.1）。

01

装不下，不只是因为「层太多」

先分清两种内存压力：层数堆高了放不下，和单层本身放不下。TP 解决的是后者。

论文的出发点是 8.3B 参数的 GPT-2 式模型（§1）。按 fp16 存权重约 16.6 GB（8.3B × 2 B 的换算，见 LEDGER），而训练时还要放梯度、Adam 的优化器状态和每层的激活；单张 32GB V100（§5）装不下。 一个自然的想法是把 72 层分给 8 张卡，每张卡放 9 层。但这样做的瓶颈不在权重总量，而在每一层自己的 GEMM 和激活：PP 不切单层，单层的 GEMM 和激活尺寸不变；论文因此做层内切分，并与 PP 正交组合。

核心矛盾

一个线性层切开后，部分和必须先相加，才能过非线性

线性层是 Y = XA。如果按行切 A、按列切 X，得到的是 X₁A₁ + X₂A₂；但 GeLU 是非线性的： GeLU(X₁A₁ + X₂A₂) ≠ GeLU(X₁A₁) + GeLU(X₂A₂)。 于是必须在 GeLU 之前做一次同步，把部分和加起来——这正好是 TP 想避免的通信点（§3 Eq. 2–3）。

论文的解法是换一个切法：先按列切 A，让每张卡的输出通道互不重叠。这样 GeLU 可以分别在每张卡上做，不需要先求和； 紧接着的第二个 GEMM 按行切，让每张卡用自己的那部分 GeLU 输出继续算，最后只加一次部分和。切分点从「非线性之前」挪到了「整个子块的出口」。

02

数据并行复制模型，流水并行切层，都绕不开单层

把三条并行轴放在一起看，才能看出 TP 为什么必须存在，以及它为什么总和 DP、PP 一起出现。

Data Parallel

复制模型，切 batch

每张卡放完整模型，喂不同 batch，反向时 all-reduce 梯度。它能把吞吐做上去，但每卡显存不降：模型参数、优化器状态、激活都还是完整一份。

适合「单卡放得下、想跑得更快」。

Pipeline Parallel

切层，流水执行

把第 1–9 层放卡 0、第 10–18 层放卡 1，以此类推。每卡只存一部分层，但单层的张量仍要完整放得下；并且流水线有气泡，边界还要传激活。

适合「层数很多、单层还算得动」。

还有一条更早的路线是 Mesh-TensorFlow：用一套语言描述张量在哪些维度上分布，再编译出集合通信。论文没有走编译器路线，而是直接在 PyTorch 的 Transformer 实现里插入几个 autograd 算子—— f 在前向是恒等、反向做 all-reduce；g 在前向做 all-reduce、反向是恒等。Transformer 层的切分只靠这两个共轭算子拼出来（§3、Code 1）。

Megatron 的位置

层内并行：切矩阵，不切层

论文明确把 TP 定位成与 PP 正交且互补（§3 末段）。实际训练时常见组合是：TP 放在机箱内（NVLink），PP 跨机箱，DP 放在最外层复制。 8.3B 的配置就是 8 路 TP × 64 路 DP = 512 张卡（Appendix B.1）。

03

第一刀切列，第二刀切行，中间不通信

看懂 MLP 的这两刀，attention 的 QKV 和输出投影是同一套动作换个矩阵形状。

MLP：列并行接行并行

第一层是 Y = GeLU(XA)，其中 X 是 [b, s, h]，A 是 [h, 4h]。 把 A 按列切成 [A₁, …, A_TP]，每张卡算自己的 Yᵢ = GeLU(XAᵢ)，输出通道是 4h/TP。 第二层是 Z = YB，B 是 [4h, h]；把 B 按行切成 [B₁; …; B_TP]，每张卡算 Zᵢ = YᵢBᵢ，最后把所有 Zᵢ 相加：

[Y₁, …, YTP] = [GeLU(XA₁), …, GeLU(XATP)]
Z = Σi YiBi  =  all-reduce(Z₁, …, ZTP)
§3 Eq. 3 与 Figure 3a；求和发生在行并行出口，GeLU 之前没有同步

换成 PyTorch 的权重形状（nn.Linear(in, out) 的权重是 [out, in]），列并行切的是输出维：每卡权重 [4h/TP, h]； 行并行切的是输入维：每卡权重 [h, 4h/TP]。两者各自是 4h²/TP 个参数，一层 MLP 合计 8h²/TP。

Attention：QKV 按头切，输出投影按行切

Multi-head attention 的 Q、K、V 投影可以拼成一个 [3h, h] 的矩阵（GQA 时是 [h + 2hkv, h]）。 论文把 QKV 投影按列切，让每张卡只拿自己负责的那几个头：每卡 h/TP 个头，每个头在自己的卡上完成 softmax(QKᵀ/√d)V，头与头之间不需要通信（§3、Figure 3b）。 随后的输出投影是 [h, h] 矩阵，按行切，出口做一次 all-reduce。

在 Megatron-Core 里，这个融合的 QKV 层是列并行线性层：非 TE 路径为 ColumnParallelLinear（megatron/core/tensor_parallel/layers.py:1107），TE 路径为 TELayerNormColumnParallelLinear（megatron/core/extensions/transformer_engine.py:1551）；attention 模块里的实例化见 megatron/core/transformer/attention.py:1871–1886。 GQA 时权重按 [q₁ q₂ k₁ v₁ | q₃ q₄ k₂ v₂ | …] 交错排列，切分时再拆成 q、k、v 三段（megatron/core/transformer/attention.py:2034–2035、megatron/core/transformer/attention.py:2084–2097）。

Embedding：按词表切，logits 不进 all-gather

输入 embedding 的论文记法是 [h, vocab]，按词表维切分后每张卡存 vocab/TP 列；输入 token 落到别的卡上时置零，最后做一次 all-reduce 得到完整 embedding（§3）。 Megatron-Core 的 VocabParallelEmbedding 权重布局为 [vocab, h]，对应每卡 vocab/TP 行（megatron/core/tensor_parallel/layers.py:351）。 输出 logits 如果先算成 [b, s, vocab] 再 all-gather，通信量是 b·s·vocab，比激活大得多；论文把并行 GEMM 的输出直接接上交叉熵，只传 b·s 个标量损失，把这一块通信压掉了（§3）。Megatron-Core 对应 vocab_parallel_cross_entropy（megatron/core/tensor_parallel/cross_entropy.py:251）。

04

每层都要同步，所以 TP 被关在 NVLink 机箱里

TP 的通信频率远高于 DP：不是每个 step 一次，而是每个 Transformer 层 4 次。这决定了它通常只放在机箱内的 8 张卡上。

一张层内的通信账

记激活的 hidden 为 h、micro-batch 为 b、序列长为 s、元素字节数为 d。每次 all-reduce 的张量是 [b, s, h]， 每层前向 2 次、反向 2 次，所以每层每卡的 payload 是 4·b·s·h·d 字节；按 ring all-reduce 的带宽模型，每卡实际搬运约 8·b·s·h·d·(TP−1)/TP 字节。 这个量只随 b·s·h 增长，不随 TP 度数下降——TP 降低了每卡的 GEMM，但没有降低每卡要同步的激活。

Vpayload = 4 · b · s · h · d      Vring ≈ 8 · b · s · h · d · (TP−1)/TP
4 次来自 Figure 4 与 §3；ring 系数 2(TP−1)/TP 是标准 ring all-reduce 的每卡搬运量

这就是 TP 与 DP 的物理差别：DP 的梯度 all-reduce 每个 step 一次，张量和参数同大；TP 的 all-reduce 每层 4 次，张量和激活同大。 层数一多，TP 的通信次数是 4 × layers，所以它对延迟和带宽都敏感。论文的 512 卡集群里，机箱内 NVSwitch 是 300 GB/s，跨机箱 InfiniBand 是 100 GB/s（§5），8 路 TP 可以放在一个 DGX-2H 机箱内。

TP

切每层的矩阵

每层 4 次集合通信，张量 [b,s,h]；延迟敏感，放在 NVLink 域内。

PP / DP

切层 / 切 batch

PP 只在层边界传激活，DP 每个 step 传一次梯度；都可以跨机箱，常放在 TP 外层。

Megatron-Core 加了什么：sequence parallel 与 TP overlap

原始 Megatron-LM 的 TP 只切矩阵，LayerNorm、dropout、残差这些逐元素操作仍在每张卡上完整复制（§3）。Megatron-Core 的 sequence_parallel 把这些区域的激活沿序列维再切一刀： 列并行层在 forward 前做 all-gather 把序列拼回来（megatron/core/tensor_parallel/layers.py:697–698），行并行层在出口做 reduce-scatter（megatron/core/tensor_parallel/layers.py:1761–1764），反向对应互换（megatron/core/tensor_parallel/mappings.py:528–549）。 配置项的注释直接指向 Korthikanti et al. 2022 的 Reducing Activation Recomputation in Large Transformer Models（megatron/core/model_parallel_config.py:123–127）。

结果是：残差流激活从每卡 b·s·h 降到 b·s·h/TP；通信字节不变（4 次 all-reduce 换成 2 次 AG + 2 次 RS 的前向，反向再各两次），但集合通信的调用次数从 4 变成 8。 省下的是显存，不是带宽。

05

把两条子块画成同一条数据流

MLP 和 attention 的矩阵形状不同，但都是「列并行 → 本地非线性 → 行并行 → all-reduce」。

把图读成两句话：列并行负责「每张卡算不同通道」，行并行负责「每张卡消费自己的通道并求和」。 前者消掉了 GeLU 前的同步，后者把同步推迟到子块出口；两者合起来，一层里只剩两次前向 all-reduce（attention 一次、MLP 一次）。

反直觉：头越多，扩展效率越低

TP 不是越大越好：整除、机箱和 batch 都在限制它

下面这些条件不满足时，TP 要么直接报错，要么收益被通信吃掉。

硬约束

维度必须整除

ColumnParallelLinear 用 divide(output_size, world_size)（megatron/core/tensor_parallel/layers.py:1213），RowParallelLinear 用 divide(input_size, world_size)（megatron/core/tensor_parallel/layers.py:1608）； divide 在不能整除时直接断言失败（megatron/core/utils.py:599–608，断言在 ensure_divisibility 599–601）。头数也要能被 TP 整除（megatron/core/transformer/attention.py:365–367）。

软约束

通信放在 NVLink 域内

每层 4 次 all-reduce，跨机箱的 100 GB/s InfiniBand 很容易把 GEMM 的收益吃掉（§5 的 300 GB/s NVSwitch vs 100 GB/s IB）。常见做法是 TP ≤ 8、放在同一台 DGX 内，PP/DP 往外层放。

几个容易踩的边界

  • GQA / MQA 的 TP 上限：当 num_query_groups < TP 时，每张卡分不到完整的 KV 头；Core 的做法是先 all-gather QKV，再按 rank 切片（megatron/core/transformer/attention.py:2033–2053），多了一次通信，也不再是「头内本地计算」。
  • 词表要 padding：论文把 50,257 的词表补到 51,200，使每卡词表是 128 的倍数（§5.1）。TP 度数变了，padding 目标也要跟着变，否则各卡分到的词表大小和 GEMM 对齐都会变。
  • 小 batch 不划算：Table 8 的强扩展在 8 卡只有 2.98×；当 b·s 很小时，每卡 GEMM 太小，all-reduce 的固定延迟占比更高。
  • TP 不省激活：原始 TP 只切线性层，LayerNorm、dropout、残差仍然复制；长序列训练还需要 activation checkpointing 或 sequence parallel（Core 的 sequence_parallel）。
  • 不减少总 FLOPs：TP 只是把同样的计算分给更多卡，并额外加上通信；模型能单卡放下且吞吐够用时，DP 更简单。
一句话选择

单层放不下 → TP；层数放不下 → PP；吞吐不够 → DP

实际训练通常三者叠加：TP 在最内层（机箱内），PP 跨机箱切层，DP 在最外层复制。Megatron 的 8.3B 配置就是 8 路 TP × 64 路 DP（Appendix B.1）；PP 是论文明确说「正交且互补」的另一条轴（§3）。
