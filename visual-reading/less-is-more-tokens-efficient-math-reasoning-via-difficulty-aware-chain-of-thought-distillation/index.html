Less is More Tokens：按难度压缩 CoT，SFT 学长度、DPO 做偏好

不管题难不难，推理模型都爱写一样长的思维链。论文先用 GPT-4o-mini 给每道数学题打 1–10 的 AoPS 难度分，再让 GPT-4o-mini 按难度把纯文本 DeepSeek-R1 / QwQ-32B 的长 CoT 压短（§3.1 称压缩用 GPT-4o-mini；A.5 的 gpt4o_DA2 用 GPT-4o）；学生模型先 SFT 学“长度与格式”，再用 DPO 偏好“压缩且正确”的回答。1.5B 模型在 AIME 上从 20.0 升到 23.4，同时 token 从 6768 降到 6192；7B 则是 35.0→31.7，token 6360→5724。

Abdul Waheed、Chancharik Mitra、Laurie Z. Wang、Deva Ramanan、Bhiksha Raj · Carnegie Mellon University 原文 ↗
TL;DR · 30 秒抓住核心

论文先验证一个现象：现有推理模型在简单题和难题上生成的推理长度差不多，即 E[T|d(x)] 对难度 d(x) 不敏感。理想情况应该是难题多想、简单题少想。

方法分两段。数据段：GPT-4o-mini 按 AoPS 标准打 1–10 难度分；纯文本用 DeepSeek-R1/QwQ-32B 生成冗长 CoT，多模态用 GPT-4o；GPT-4o-mini 按难度压缩（§3.1 称 GPT-4o-mini；A.5 的 gpt4o_DA2 用 GPT-4o），得到“难度对齐”的 trace。训练段：SFT 学压缩 trace 的长度和格式；DPO 以压缩 trace 为 preferred、原始长 trace 为 rejected，论文称这样能保正确率；两者串联。

1.5B 的 SFT+DPO 在 AIME 上 23.4（base 20.0），token 6192（base 6768，少 8.5%）；7B 的 AIME 是 31.7（base 35.0，低 9.4% 相对），token 5724（少 10.0%）。

收益不是所有基准都“既短又准”：1.5B 在 AIME/AMC/MATH 上升，GSM8K 略降；7B 在 MATH 上升，AIME/AMC/GSM8K/HMMT 下降。论文的多模态结论主要来自 Figure 1 的柱图，没有逐项数值表。

01

简单题也写长链：推理长度对难度不敏感

论文的起点不是“CoT 太长”，而是“长度没有随难度变化”。这既是算力浪费，也说明模型没有学会按需分配思考。

对一个问题 x，记难度为 d(x) ∈ [1, 10]，推理 trace 为 r，长度 T = |r|。现有模型的典型行为是：

E[ T | d(x) ] ≈ 常数，或随 d(x) 变化很小
论文 §1 的观察：推理长度与问题难度脱钩。

理想行为则是：

E[ T | d(x) ] 随 d(x) 单调上升
简单题只给核心步骤，难题保留更多中间推导；最终答案仍要正确。

这会带来两类成本。第一类是显式成本：每个 token 都要付推理算力和延迟，简单题上的冗长 CoT 是纯浪费。第二类是隐式成本：模型没有学会“先判断难度，再决定想多久”，遇到真正难的题时也不一定分配更多计算。

现象

长度与难度脱钩

现有 CoT 模型在 GSM8K 和 AIME 上可能都写上千 token；长度主要由模型习惯决定，而不是题目难度。

目标

难度感知的长度分配

不是把所有 CoT 压到固定预算，而是让简单题短、难题长；压缩比例随难度变化。

手段

数据工程，不改架构

不修改模型结构，也不改解码策略；通过构造“难度对齐”的训练数据，把行为蒸馏进学生模型。

02

固定预算、统一压缩、纯 SFT：各缺一块

已有工作大致分三类：长度控制、CoT 压缩/蒸馏、SFT+DPO 对齐。论文的差异在于把“难度”作为压缩比例的条件。

长度控制

L1 等方法：给一个预算

L1 用强化学习控制推理长度，让模型在指定 token 预算内作答。它能把长度压到目标值，但预算通常是全局或按题设定的，不直接建模“难度→长度”的函数。

CoT 压缩/蒸馏

统一压缩会伤难题

直接用摘要模型压缩所有 trace，简单题和难题用同一套压缩提示；难题可能丢失必要步骤，简单题又压得不够。论文用 Table 4 比较了多种摘要策略。

纯 SFT

学得会长度，学不会正确率

SFT 能让学生模型模仿压缩 trace 的格式与长度，但论文发现它常为了简洁牺牲正确率：7B SFT 的 AIME 只有 8.4%，远低于 base 35.0%。

纯 DPO

论文称保正确率，但长度降不下来

DPO 以“压缩 trace 优于长 trace”做偏好；论文称 DPO 能保住正确率，同时观察到 DPO 单独使用时推理长度仍然接近原始长 CoT，效率收益有限。Table 2 的 DPO-only 行并不支持“保住正确率”（见 §06 的并列）。

因此论文的组合是：SFT 先学“怎么写短”，DPO 再学“短也要对”。这不是把两个损失相加，而是两阶段课程：SFT 塑造长度与格式，DPO 在已经会写短的基础上做偏好修正。

03

先打难度分，再按难度压缩，最后 SFT→DPO

方法可以拆成数据管线和训练管线两部分；数据管线的核心是“难度分 → 压缩比例”的映射。

数据管线：难度分与压缩比例

第一步，用 GPT-4o-mini（temperature=0）按 AoPS 竞赛难度给每道题打 1–10 分。评分 prompt 在 Figure 3（纯文本）与 Figure 4（多模态），评分标准覆盖 AMC 8/10/12、AIME、USAMO/IMO 等层级；§3.1 正文却写评分 prompt 在 Figure 18，页面并列两处说法（见 footer）。

第二步，用强教师模型生成长 CoT：纯文本用 DeepSeek-R1 与 Qwen-QwQ-32B，多模态用 GPT-4o。纯文本数据来自 OpenMathReasoning 的 CoTsplit，约 125K 道题；多模态数据来自 LLaVA-CoT-100K 的子集，约 60K 条。

第三步，用 GPT-4o-mini 按难度压缩长 CoT（§3.1 称 GPT-4o-mini；A.5 的 gpt4o_DA2 用 GPT-4o）：难度低的问题大幅删减，难度高的问题保留更多步骤。Table 1 给出不同难度下的压缩比例：

训练管线：SFT 学形式，DPO 学正确性

Stage 1 · SFT

用压缩 trace 做交叉熵

学生模型 fθ 对每道题学习压缩后的 trace r̃：LSFT = CE(fθ(x), r̃)。这一步主要让模型学会长度、格式与“按难度分配步骤”的表面模式。

Stage 2 · DPO

压缩 trace 优于长 trace

对同一道题，构造偏好对：preferred = 压缩 trace r̃，rejected = 原始长 trace rlong。DPO 让模型提高 r̃ 的相对概率、降低 rlong 的相对概率，同时用 β=0.1 的 KL 约束稳定训练。

论文强调两者的分工：SFT 捕捉的是“推理长度和格式”这类表面模式；DPO 捕捉的是“在压缩条件下仍保持正确”的偏好。单独 SFT 会为了短而错，单独 DPO 会为了对而长；串联后才有“短且尽量对”的行为。

05

难度分 → 长 CoT → 压缩 trace → SFT → DPO

把数据管线和训练管线接起来：教师模型只负责“写长”，GPT-4o-mini 负责“打难度 + 压短”（§3.1 称 GPT-4o-mini；A.5 的 gpt4o_DA2 用 GPT-4o），学生模型负责“学短且对”。

数据侧

难度是压缩的条件

同一道题先有难度分，再有压缩比例；难度分不是训练标签，而是数据生成的控制变量。

训练侧

先 SFT 后 DPO

SFT 用压缩 trace 做监督；DPO 用“压缩 vs 原始长 trace”做偏好。DPO 的参考模型是 SFT 后的模型推断（论文未逐字说明，依据两阶段串联的训练顺序）。

07

省 token 是真的，但不是所有基准都“又短又准”

论文的边界在数据规模、难度代理、LoRA 容量与评测口径；这些限制直接影响结论能推广多远。

难度代理

GPT-4o-mini 的打分不是人类真值

难度分由 GPT-4o-mini 按 AoPS 标准给出，论文没有做与人类评分的一致性分析。评分偏差会沿着“压缩比例→训练 trace→学生行为”传播。

数据规模

比大规模蒸馏工作小

125K 纯文本 + 60K 多模态，相比 DeepSeek-Distill、Nemotron 等大规模数据小；论文在 Limitations 里承认可能限制 OOD 泛化。

训练只用 LoRA rank 16，没有做全量微调；论文承认这可能低估模型容量。评测只用 pass@1，没有 pass@k、多种子或置信区间；1.5B 的 HMMT 只有 12.2%，SFT 单独训练甚至降到 0.0%，推断低资源基准上的方差可能很大（依据：论文只报单次 pass@1，无置信区间）。

多模态评测只保留单图、自由作答样本，排除了多图与部分选择题；因此多模态结论不能直接推广到所有视觉数学任务。Figure 1/Figure 2 只给柱图，没有逐项表；页面不把柱高当作精确数值。

最后是“效率”口径：论文的 token 降幅有时相对 base，有时相对教师，有时是单基准，有时是多模态平均；§1 引言/§7 结论的“最多 30%”不能直接套到 §5 纯文本总结的 8–10%。页面在每个数字旁标明比较对象，避免把不同分母混在一起。

笔记：Less is More Tokens：Efficient Math Reasoning via Difficulty-Aware Chain-of-Thought Distillation

笔记勘误（只改页面，不动笔记）：

  • 澄清（不判笔记错）：Table 2 的 Base 是公开的 R1-Distill-Qwen-1.5B/7B 检查点，不是论文 SFT 的产物。笔记所说“在原始长 CoT 数据上微调的学生模型”对应论文 §4.2 的 unimodal baseline 说法（如 Qwen fine-tuned on DeepSeek-R1-generated reasoning）；论文的 SFT 才是用压缩 trace 微调。
  • 笔记说 SFT+DPO“在保持或提升性能的同时”省 token。Table 2 里并非所有基准都成立：7B 的 AIME 31.7 < 35.0、AMC 69.9 < 71.1、GSM8K 86.9 < 88.0、HMMT 20.0 < 24.4，幅度 −1.1 到 −4.4 点；1.5B 的 GSM8K 82.3 < 83.9。更准确的说法是“部分基准提升、部分基准小幅下降”。
  • 笔记用“如 DeepSeek-R1”举例，未提 QwQ-32B；论文 §3.1 写纯文本长 CoT 由 DeepSeek-R1 与 Qwen-QwQ-32B 生成，多模态长 CoT 由 GPT-4o 生成（笔记未提 GPT-4o 作为多模态教师）。
  • 笔记把 MathVerse 的 token 378→296 归给 SFT+DPO。论文 §5 的上下文是 SFT 相对 7B 教师降低 25–30%，MathVerse 378→296 与 HLE 580→411 是 SFT 的效率；SFT+DPO 保留这一效率并提升准确率。页面按原文的归属写。
  • 笔记说 LLM-as-Judge 在清晰度、完整性、正确性上不输基线。论文的文字结论是 SFT+DPO 最平衡、在 correctness/completeness 上高于 base 与 SFT-only，并保持较低冗余；没有说四个维度对所有基线都占优，Figure 2 也没有逐项分数表。
  • 笔记说 7B 的 AIME 31.7 vs 35.0 是“微小差距”。按 Table 2，这是 −3.3 点、相对 −9.4%；可以叫“小幅下降”，但页面给出精确差值，避免“微小”掩盖方向。
  • 笔记用“MathVerse、MathVision、OlympiadBench、MMStar 等”举例，未点名 HLE (V)。论文 §4.1 明确列了五个多模态基准，包括 HLE (V)。
  • 笔记第 98 行说 GSM8K token“减少 8%（498 vs 553）”；按 Table 2 的 7B Base 553、SFT+DPO 498 计算，(553−498)/553×100≈9.95%，约 10.0%，不是 8%。页面 Table 2 已转录 498/553，此条指出百分比口径。
