MOAT：先让 planner 学会 grounder 的「口味」，再让 grounder 适应 planner 的输出

独立训练的两个智能体，各自在自己的数据上刷分：planner 的子目标越写越漂亮，grounder 却未必接得住。 MOAT 把训练改成两段交替——planner 用 grounder 的困惑度做 DPO 偏好，grounder 用 planner 真实采样出的子目标做 critic 过滤后的 SFT。 代价是每轮要采样 K=15 个子目标序列，并让 critic 逐条判定。

Minghang Zhu, Zhengliang Shi, Zhiwei Xu, Shiguang Wu, Lingjie Wang, Pengjie Ren, Zhaochun Ren, Zhumin Chen · Shandong University / Leiden University arXiv 2509.09629v1 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

能力差距不是「某个智能体不够强」，而是两个智能体的分布对不上：planner 在 ground-truth 子目标上训练，grounder 也在 ground-truth 子目标上训练；推理时 grounder 看到的却是 planner 自己采出来的子目标。

MOAT 把「谁适应谁」拆成两段。Stage 1 让 planner 采样 K 个子目标序列，用 grounder 对正确动作序列的 PPL 排序，最低的当 chosen、最高的当 rejected，做 DPO；Stage 2 复用这些子目标，让 grounder 生成动作，critic 判定并修正，再 SFT。

在 Llama-2-7B / Mistral-7B-v0.2 / Qwen2.5-14B 上，MOAT 对 Agent Lumos 的 18 个任务格全部更高；held-in Avg 分别 +3.0 / +3.1 / +2.5 个百分点，held-out Avg 分别 +2.7 / +4.4 / +1.3 个百分点（Table 2）。

但增益不是「全面领先」：GPT-4 仍在 GSM8K、StrategyQA、SVAMP、HotpotQA 四个任务以及两个 Avg 上更高；主实验只跑 2 轮、K=15；理论上的非降/收敛论证依赖「PPL 与真实 reward 负相关」这一前提。

01

两个各自很强的智能体，凑在一起却会「鸡同鸭讲」

先建立共同认知：能力差距是分布错配，不是单点能力不足。

论文把多智能体系统拆成三段：规划智能体 πp 把任务 x 分解成子目标序列 s；接地智能体 πg 在工具集 I 和子目标 s 的条件下生成工具调用序列 a；执行模块执行 a，得到最终答案（§3）。

s = πp(x)
a = πg(x, I, s)
§3 · plan–ground–execute 管线；论文只研究这一种双角色、线性交互的结构 推断（依据：§1 只声明 “we focus on this plan-ground-execute paradigm”，未实验其他拓扑。）

问题出在两个方向都可能错位。planner 可能生成「高层但空泛」的子目标，较弱 grounder 不知道怎么把它落成工具调用；反过来，较强的 grounder 也可能被较弱 planner 的模糊子目标拖住，产生错误或低效执行（§1）。

方向 A

planner 太强，grounder 接不住

子目标逻辑上成立，但缺少可执行的中间步骤；grounder 只能猜，或者调用错误的工具。

论文原句：a planning agent might generate high-level subgoals that are difficult for a weaker grounding agent to understand and execute（§1）。

方向 B

grounder 太强，planner 给不准

grounder 有能力执行，但 planner 的子目标粒度、顺序或措辞与它的工具接口不匹配，能力被浪费。

论文原句：a strong grounding agent might struggle with subgoals generated by a weaker planning agent（§1）。

独立训练会把这种错配固化。planner 的训练目标是「生成正确的子目标」，grounder 的训练目标是「在正确子目标下生成正确动作」；两者都以 ground-truth 子目标为条件，但推理时 grounder 的输入来自 planner 的采样分布。这个分布差，论文称为 capability gap。

核心判断

不是把单个模型再训强一点，而是让训练分布对齐推理分布

如果 planner 永远只学 ground-truth 子目标，它不会知道自己的输出会被 grounder 怎样消费；如果 grounder 永远只学 ground-truth 子目标，它也不会遇到 planner 真实输出的噪声和风格。MOAT 的两个阶段，分别从两侧补上这个缺口。

02

前人把两个智能体都训好了，但没让它们互相看过对方

AgentTuning / Agent-FLAN 是单智能体；Agent Lumos / α-UMi 是多智能体但独立训练；AutoACT 是自训练。共同缺口是「没有跨智能体的联合优化」。

单智能体 tuning

把一个模型训成「多面手」

AgentTuning、AgentOhana 用 GPT 系列生成的轨迹微调较小模型（§2）；Agent-FLAN 用模块化参数组训练不同的单智能体能力（§6.2）。

它们能提升指令跟随和推理，但论文认为，对需要长期规划和执行的复杂任务仍然有限。

多智能体独立训练

把角色分开，但数据也分开

Agent Lumos 和 α-UMi 为不同角色构造专门数据，分别微调；AutoACT 让每个智能体在自己的数据上自训练（§1 的独立训练概括；Agent Lumos 的分角色微调见 §6.2；AutoACT 见 §2）。

这里的含义是：每个智能体的训练数据在训练前就固定了，训练过程中没有机制让一方根据另一方的行为调整。推断（依据：§1 的 “construct specific training data for each agent and train each agent independently”；§6.2 的 Agent Lumos “separately fine-tunes models on datasets to obtain specialized agents”。原文没有逐字写「训练前固定」，这是对独立训练流程的概括。）

However, existing methods often train agents independently, lacking joint optimization to ensure effective coordination.（§2）

MOAT 与 Agent Lumos 的差别不在 cold start 数据——MOAT 的 cold start 使用 Lumos 公开的 SFT 数据（§4.3、A.1），Agent Lumos 作为该数据的来源也用同一套数据训练。推断（依据：§4.3 写 SFT dataset collected in previous work (Yin et al., 2024a)；A.1 写 public datasets provided by Lumos；原文未逐字写两者共用同一份数据。）差别在 cold start 之后：MOAT 让 planner 和 grounder 交替看到对方的输出，并把对方的反馈写进下一轮训练。换言之，Agent Lumos 是「两个专家各自毕业」，MOAT 是「两个专家毕业后继续一起做项目」。

对照点

为什么「各自刷分」不能自动换来协作

因为两个模型的损失函数都不包含对方的推理行为。planner 的 DPO 偏好如果只来自人工标注或 ground-truth，它优化的是「人类觉得好的子目标」，不是「当前 grounder 能执行的子目标」。MOAT 把后者的信号显式接进来：用 grounder 的 PPL 当 reward，用 critic 过滤 grounder 的自生成动作。

03

Stage 1：用 grounder 的困惑度，给 planner 排偏好

PPL 在这里不是评估指标，而是 reward：越低，说明这串子目标越容易被 grounder 转成正确动作。

给定任务 x，planner 先采样 K 个候选子目标序列，记作 S = {s1, …, sK}。对每个候选，用 grounder 在正确动作序列 a 上的困惑度打分：PPL 越低，表示 grounder 越「跟得上」这串子目标（§4.1）。

PPLπg(a | x, I, s) = exp[ − (1 / |a|) Σi=1|a| log Pπg(ai | a1:i−1, x, I, s) ]
§4.1 · PPL 定义（原文未编号）；越低表示 s 越有助于 grounder 生成正确动作

记号说明：v1 PDF p.3 与 arXiv HTML 的原文都完整显示 PPLπg(a | x, I, s) := exp{ −(1 / |a|) Σi=1|a| log Pπg(s | a<i, x, I, s) }—— 对数项里被预测的变量写的是 s，不是 ai，疑为排印错误（typo）。本页上面的公式按标准困惑度记号写成 ai | a1:i−1, x, I, s，属于记号修正，不是逐字复制。

拿到 K 个 PPL 后，取最低的作为 sw（chosen），最高的作为 sl（rejected），构造偏好对，用 DPO 更新 planner。参考模型 πref 初始化为优化前的 planner。

LDPO = − E(x, (sw, sl)) ~ D [ log σ( β log( πp(sw|x) / πref(sw|x) ) − β log( πp(sl|x) / πref(sl|x) ) ) ]
§4.1 · DPO loss（原文未编号）；β 在原文中只称为 hyperparameter，§6.3 与 A.1 未给出取值

A.1 还加了一个稳定性过滤：如果 sw 与 sl 的 reward 差小于 0.1，这对样本不参与 DPO。也就是说，只有「明显更好」和「明显更差」的候选才被拿来当偏好对。

04

Stage 2：让 grounder 在 planner 的真实输出上练，但先过 critic 这一关

自生成数据不能直接用；critic 判定 + 修正，再按 1:1 混入初始数据做 SFT。

Stage 2 复用 Stage 1 采样出的全部 K 个子目标序列，而不是只用 PPL 最低的那一个。对每个 (x, s)，grounder 生成动作序列 a。因为 a 是模型自己生成的，可能出错；直接拿去做 SFT 会导致性能退化甚至训练崩溃（§4.2 引用了 Dohmatob et al. 2024 与 Shumailov et al. 2024）。

Algorithm 1 · Dataset Construction

critic 不是只打分，它还会改写

  1. 对每个任务 x 和每个候选 s，让 grounder 生成 a。
  2. critic 接收 (x, I, s, a, ã)，判断 a 是否能让任务到达最终答案。
  3. 如果判定失败，critic 参考 ground-truth ã 给出修正后的 â，把 (x, I, s, â) 加入 Dg。
  4. 如果判定成功，把 (x, I, s, a) 加入 Dg。
  5. 用 Dg 对 grounder 做 SFT。

论文原句：“This filtering and correction process ensures that only reliable supervision signals are used during grounding agent training.”（§4.2）这里的「可靠」指的是动作序列能到达与 ground-truth 相同的最终答案，不是子目标本身一定最优。

原文并列

critic 是否改写子目标，两处写法不同

Appendix A.3 的 critic prompt 要求模型在失败时输出 Corrected Subgoals 与 Corrected Actions；Algorithm 1 的失败分支（第 6 行）写入 Dg 的 pair 是 (x, I, s, â)，其中 s 仍是原始子目标，没有替换成 corrected subgoals；成功分支（第 9 行）写入原始 a。

两处并列：A.3 的 prompt 允许改子目标；Algorithm 1 的伪代码只替换动作。本页按 Algorithm 1 描述数据流，不替原文消解这个差异。

训练配置：两轮、K=15、6×A800

Cold start 用 Lumos 的公开 SFT 数据，planner 和 grounder 各训 2 epochs，学习率 2×10−5，batch size 128，最大序列长度 1024，线性 warmup 占 3%。 DPO 阶段用 accelerate + DeepSpeed：batch size 4，梯度累积 8，学习率 4×10−7，cosine scheduler，最大长度 1024。 Grounding 阶段再训 2 epochs，学习率 2×10−5，batch size 128，并与初始数据按 1:1 混合，防止遗忘。 全部实验在 6×A800 80GB 上完成；主实验 K=15、迭代 2 轮、采样温度 1.0，critic 用 DeepSeek-R1-Distill-Qwen-32B。 推断（依据：A.1 只写 initial fine-tuning “train two epochs”，未分角色列出；本页把它理解为 planner 和 grounder 各训 2 epochs。）

05

一次迭代，两个阶段，三条数据流

Cold start → Stage 1 更新 planner → Stage 2 更新 grounder → 下一轮；推理时仍是 planner → grounder → executor 的线性管线。

这张图里有两个容易被忽略的点。第一，Stage 2 用的是全部 K 个候选，不是只把 PPL 最低的那个喂给 grounder；这样 grounder 见到的是 planner 更完整的采样分布（K=15，§6.3），而不是被 planner 自己挑过的「最优样本」。第二，critic 的修正发生在写数据集之前：Algorithm 1 的失败分支写入 critic 修正后的 â，成功分支保留原始 a（第 6 / 9 行）；所以 SFT 目标并非一律是校对后的动作。

口径核对

摘要里的 3.1% / 4.4% 不是三模型平均

摘要写 “average improvements of 3.1% on held-in tasks and 4.4% on held-out tasks”。按 Table 2 复算，3.1 = 46.3 − 43.2、4.4 = 53.6 − 49.2，都只对应 Mistral-7B 这一个模型；Llama 是 +3.0 / +2.7，Qwen 是 +2.5 / +1.3。§7.1 也只拿 Mistral 举例说明 4.4%。

推断（依据：上述四个差值全部来自 Table 2；摘要没有给平均口径的公式）摘要的 3.1%/4.4% 是 Mistral 单模型的 held-in / held-out 点差，不是三个模型的平均增益。

Table 4 的 Mistral-7B PPL 分析给出了另一面：Math 的 grounding PPL 从 3.53 降到 2.56（相对下降 27.48%），Web 从 5.71 降到 5.02（12.08%），QA 从 1.41 降到 1.40（0.71%）。QA 的 PPL 几乎没动，但 StrategyQA 的 Exact Match 在三个模型上分别提高了 5.3 / 6.7 / 6.0 个百分点（Table 2）。推断（依据：Table 4 的 QA PPL 差距只有 0.01，Table 2 的 StrategyQA 增益却是六个任务里最大的之一）PPL 与最终指标值并非一一对应，PPL 更适合当同一任务内的相对信号，而不是跨任务的绝对标尺。

论文还在 Mistral-7B 上报告了两个趋势（§7.4）：Figure 3 显示采样数 K 与性能正相关，K=5 时 GSM8K 和 Mind2Web 会下降；Figure 4 显示性能随迭代轮数上升，但到第 3 轮增益已经边际化。Figure 5 则把 MOAT 与独立训练的同 epoch 数基线对比：MOAT 持续上升，独立训练基线出现退化，论文归因于过拟合（§7.6）。

07

它能补的是「两个智能体的分布差」，不是所有协作问题

文本、两角色、线性管线、固定工具集；多模态、澄清/协商、更多角色都不在覆盖范围内。

论文的 Limitations 写得很直接：“Our framework is currently developed and evaluated exclusively on text-based scenarios, without exploring multimodal learning settings.” 图像、视频、跨模态工具调用都没有涉及。

结构上也只覆盖 planner–grounder 这一种线性管线。论文明确说，选择 plan–ground–execute 是因为它在多数多智能体框架里被广泛采用（§1）；但这也意味着，需要 grounder 反问 planner、需要多个 planner 协商、或者需要 reflection / tool retrieval 角色的场景，MOAT 没有给出机制。推断（依据：§3 的 s → a 单向管线；论文未实验反问或协商。）论文在 Conclusion 里把 tool retrieval / reflection 等更多专用智能体列为 future work，而不是本文已验证的结果。

理论部分也要加限定。Lemma 5.1 的论证起点是 “Since PPL is negatively correlated with the true reward R(s,a)”；Lemma 5.2 则从「log-likelihood 提升 → PPL 降低 → reward 提高」推到非降。论文没有证明 PPL 与真实 reward 的负相关本身，也没有给出这种相关性的任务范围。推断（依据：Lemma 5.1/5.2 的原文把这两步当作前提直接使用，未附证明）因此「non-decreasing + 收敛」是建立在该前提上的结论，不是对任意 planner–grounder 组合的无条件保证。

数据规模也限制了外推。训练集只有三个 held-in 任务共 1800 条；held-out 是 SVAMP（1000）、WebShop（500）、HotpotQA（100），仍是数学、网页、问答三类，不是全新的领域。Table 2 的 Avg 可按三个任务指标值的算术平均复算（三个指标口径不同，不是同单位分数），未按样本量加权。推断（依据：Llama 的 held-in Avg 41.1 = (46.6 + 29.9 + 46.7) / 3；其余 Avg 同样按三项算术平均复算。）因此小样本任务（StrategyQA 300、Mind2Web 200）和大样本任务（GSM8K 1300）在 Avg 里权重相同；跨任务比较时要注意这一点。

什么时候别用

三个明确的边界

  • 需要多模态输入或跨模态工具调用：论文没有覆盖。
  • 需要 agent 之间澄清、协商、反问：MOAT 的交互是单向的 s → a，没有回传通道。
  • 没有可信 critic 或预算有限：Stage 2 的数据质量依赖 critic，弱 critic 会掉点，强 critic 增加成本。
