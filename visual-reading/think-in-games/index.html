Think in Games：把「这一刻该推哪路」变成一道能自动打分的语言题

传统 RL 智能体「知道怎么做」却说不清为什么，LLM「知道为什么」却在盘面里做不出动作。 论文用王者荣耀（HoK）真实对局把两者的目标压成同一个：给定 JSON 盘面，先在 <think> 里写分析，再在 <answer> 里选出 40 个宏动作中的 1–2 个； 专家动作只用来打二值分，GRPO 组内比较后回传。

Yi Liao, Yu Gu, Yuan Sui 等 8 人 · Tencent · 无公开代码仓库 arXiv 2508.21365 ↗ v1 HTML ↗
TL;DR · 30 秒抓住核心

这篇的「任务」很简单：动作预测——看主玩家此刻的盘面，说出他会做的 1–2 个宏动作（§2.2 称 K=40，附录 Table 5 实际列 id 0–43 共 44 项，id 25 = Enemy High-ground Minions 推断：K=40 与 44 项并存于原文，此处只并列、不裁断）。 难点不在分类器，而在动作是人可以写理由、机器可以判对错的离散标签，于是整个 RL 决策被重写成「结构化语言生成」。

训练分两段：SFT 数据蒸馏自 DeepSeek-R1（§4.2），让模型先学会「看盘面 → 写分析 → 给动作」的格式； 再上 GRPO（§3.2、附录 C），奖励是 答案集合与专家动作集合完全相等的二值信号，不加格式奖励，也不训奖励模型。

结果在离线动作预测上：Qwen-2.5-32B 只用 GRPO 160 步，从 66.67% 到 86.84%（+20.17 个百分点）；Qwen-3-14B 经 SFT+GRPO 2000 步到 90.91%，比 DeepSeek-R1 的 86.67% 高 4.24 个百分点。 但不是越训越好、也不是越多阶段越好——14B 在 480 步反而只有 77.92%（见 06）。

01

会背攻略不等于会打：缺的是「在哪个盘面上做什么」

读完这一节要明白：论文要的不是更强的分类器，而是把决策题目写成「可写理由、可判对错」的样子。

论文开头给了一个很具体的例子（§1）：LLM 从攻略里学得到「不要推线太深」，但「太深」的边界只能从实际对局里摸出来。 作者把这条差距命名为陈述性知识 vs 程序性知识——前者来自文本，后者只能来自与环境的交互。

传统 RL 智能体

知道怎么做，说不出为什么

§5 原文：「their decision-making processes are typically opaque」。同时依赖大量领域工程与训练量，换环境难迁移。

通用 LLM

说得清原理，盘面上做不出

§1：知识是静态的、来自网页，不是来自与游戏环境的直接交互；prompt 里塞攻略也「does not fundamentally transform declarative knowledge into procedural understanding」。

要弥合它，需要一个动作空间干净、反馈明确的场地。论文选了 MOBA（王者荣耀），并把动作抽象成 40 个宏动作：不是按哪个键，而是「打小龙 / 守中路塔 / 在中路抱团」这类团队目标（§2.2、Table 5）。 这一层抽象同时解决两件事：LLM 不用学手速，专家动作可以当标签，奖励可以写成一条规则。

一句定义

任务：f : (st, it) ↦ (at, ct)

输入当前盘面 st（JSON）与指令 it，输出动作集合 at ⊆ A（1–2 个）与推理链 ct（§2.3）。评估就是看 at 与专家动作对不对得上。

注意一个容易忽略的限定：动作是非互斥的（Table 1 提示词：「从不互斥的候选选项中选出最接近的1-2个建议」）。所以这道题本质是「预测一个 1–2 元动作集合」，而不是「在 40 选 1 里挑一个」。

02

前人两条路都只走了一半：一条会做不能说，一条能说不会做

本节对照的是论文 §1、§5 自己划的两条线，以及论文对 DeepSeek-R1 的预实验（附录 B）。

搜索 / 启发式 / RL

行为对，过程不透明

§1：搜索算法、手工启发式和 RL 在各自环境里成绩亮眼，但「rely on extensive domain-specific engineering and require massive amounts of training」，且过程「typically opaque」。

卡点：策略不是用语言写出来的，也就无法让人检查理由，更难直接迁移到新环境。

直接用通用 LLM（含 DeepSeek-R1）

懂机制，但没吃过对局

附录 B 对 DeepSeek-R1 的预实验列了两条限制：(1) Efficiency——模型太大，难以保证实时场景的响应；(2) Performance ceiling——分析能力「relies on the combination of data and strategy guides」，例如「avoid pushing the lane too far」里的「too far」需要实际经验。

卡点：上限由攻略文本决定，而不是由盘面交互决定；可惜论文没有给出这段预实验的量化数据。

论文的位置在两者中间：保留 RL「从反馈里学」的骨架（GRPO，附录 C 称 PPO 在高方差奖励与信用分配上吃力，GRPO 用组内相对优势缓解），把动作与解释都交给 LLM 用语言写完， 并用一件传统 RL 很难做的事打分段——把「专家做了什么」当成唯一的判卷人。

和标准 GRPO 的差别

附录 C 列了三条改动

  • 奖励换成针对宏动作对错的规则二值奖励，不用人类偏好、不训神经奖励模型；
  • 动作空间压成有限可解释集合，简化奖励计算与评估；
  • 去掉格式奖励，理由是「our model demonstrates strong structural adherence by design」。

手算两组：G=8 时每个回答的优势总体标准差（÷G），与上方交互逐位一致

A 组：奖励序列 r = [1,0,0,0,0,1,1,0]（3 个 1，5 个 0）

  • mean = 3 / 8 = 0.375
  • 总体方差 = [3 × (1−0.375)² + 5 × (0−0.375)²] / 8 = [3 × 0.390625 + 5 × 0.140625] / 8 = 1.875 / 8 = 0.234375
  • std = √0.234375 = 0.4841
  • 正确回答：Â = (1 − 0.375) / 0.4841 = 1.291；错误回答：Â = (0 − 0.375) / 0.4841 = −0.775
  • 若改用样本标准差（÷(G−1)），std = 0.5175，优势变成 1.208 / −0.725——本页不用这个口径。

B 组：奖励序列 r = [1,1,0,1,1,0,1,1]（6 个 1，2 个 0）

  • mean = 6 / 8 = 0.750
  • 总体方差 = [6 × 0.25² + 2 × 0.75²] / 8 = [0.375 + 1.125] / 8 = 0.1875
  • std = √0.1875 = 0.4330
  • 正确回答：Â = 0.25 / 0.4330 = 0.577；错误回答：Â = −0.75 / 0.4330 = −1.732

边界：G=16 且全部正确或全部错误时 std = 0，交互把优势记为 0.000；原文没有写这时 GRPO 如何处理，这一步是页面自定的保护，不是论文规则。

交互覆盖了什么、没覆盖什么按 SPEC §1.3-G 列出分支

04

数据靠重标注变密，训练靠两段接力

读完这节要知道训练信号从哪来、每段各用了多少步，以及硬件规模。

数据：专家对局 + 重标注，每分钟抽一帧

  • 数据来自匿名化的真实对局，胜负各半，只保留水平高于某阈值的玩家（§3.1）。
  • 每局抽取完整盘面序列，主玩家的动作为真值；由于转换会导致标签稀疏/不一致，用重标注算法加密（§3.1.1–3.1.2）：
  • 先在窗口 Lfill 内向前回填检测到的动作标签；再在 Loverwrite 窗口内，按 Table 5 的优先级用高优先动作覆盖低优先。
  • 重标注后每分钟随机抽一帧做训练样本。

注意粒度：Lfill、Loverwrite 的取值、优先级函数里的 criticality / time_window / game_impact 权重，原文都未给出数值。

07

它考的是「像专家」，不是「比专家强」，也不是「在线」

论文自己在 §7 列了四条限制，下面再补三条从数据里能读出来的。

限制 1 · §7

依赖底座模型

原文：「The effectiveness of TiG is inherently tied to the capabilities of the underlying LLM backbones.」复杂或实时场景下底座的短板会直接变成策略的短板。

限制 2 · §7

只在数字游戏里验证

原文：「The generalizability of TiG to other interactive domains—such as robotics or real-world tasks—remains to be thoroughly investigated.」论文全部实验只在王者荣耀完成。

限制 3 · §7

样本效率仍不是免费的

原文：「it still requires a substantial amount of environment interaction. This requirement may be prohibitive in scenarios where data collection is expensive or time-consuming.」注意：这里的交互来自 replay 数据，而非与引擎实时交互。

限制 4 · §7

理由未必忠实

原文：「In some cases, these explanations may not fully or accurately reflect the underlying decision-making process.」<think> 是联合生成的文本，不是对内部计算的审计。

补充 5 · 奖励设计

目标是模仿，不是赢

Eq. 4 只有「与专家动作集合是否相等」这一个信号，没有胜负、没有终局奖励，也没有对「理由写得好不好」的单独评分。模型学的是跟专家一致；能否超越专家或发现新策略，论文没有实验回答。

补充 6 · 标签质量

重标注 + 每分钟一帧会丢失盘面粒度

真值先经过回填与优先级覆盖，再每分钟抽一帧；动作集合是否「相等」又要精确比较。这两步都会把「玩家本来做什么」压成更粗的标签。Lfill、Loverwrite 未给数值，无法估计这种压缩的影响。

补充 7 · 训练曲线

步数与准确率不是单调关系

Table 2a 中 14B 的 480 步（77.92%）低于 360 步纯 GRPO（79.22%），而 3-14B 400 步（85.71%）到 2000 步（90.91%）才拉开。训练步数、checkpoint 选择和样本量对最终数字的影响在论文中没有被分离。

一句话：TiG 的卖点是「用语言写出决策 + 用规则自动判卷」，在离线动作预测上确实能把 14B 顶到超过大模型；但它不改变「监督来自专家」这个前提，也不等于在线交互训练。
