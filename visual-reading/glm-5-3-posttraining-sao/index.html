GLM-5.3 的官方材料是一篇 2026-08-14 的博客和 HF 模型卡；未找到 GLM-5.3 专门技术报告。博客明确写 same base model as GLM-5.2、every gain comes from post-training；SAO 是另一条线： 它解决异步长程 RL 的稳定性，训练对象是 Qwen3-30B-A3B，部署对象是 GLM-5.2。

SAO 把 GRPO 的 group-wise sampling 换成每个 prompt 一条轨迹。DIS 直接用 rollout logprob 算 rt = πθ / πrollout，落在 [1−εl, 1+εh] 之外的 token 整个从梯度中置零；critic 每次策略更新配 K=2 次更新， 冻结 attention、只训 MoE 投影，并用 skip-observation GAE 跳过环境观测。

01

长程 Agent RL 的浪费，来自等最慢的一条轨迹

先看同步 batch 的三个成本：长尾等待、跨版本 off-policy、以及和线上单轨迹反馈不兼容。

同步 RL 的流程是「采一整批 rollout，等齐，再优化」。长程 Agent 任务的轨迹长度差异很大： 短轨迹很快结束，长轨迹变成 straggler，GPU 集群在等最慢那条时大面积空转（SAO §1）。 这不是某个实现细节，而是 batch 语义本身决定的。

GRPO 把这个问题放大了一层。它对每个 prompt 采一组 G 条轨迹，用组均值做 baseline，因此必须等组内所有轨迹完成才能算 advantage； 等待时间由最慢的一条决定。论文把这种延迟称为 latency-driven off-policy：等得越久，用于更新的数据离当前策略越远（SAO §1）。 在线上或复杂 Agent 环境里，环境常常只返回单条轨迹反馈，group-wise sampling 还会直接和反馈形态冲突（SAO §1）。

异步训练能拆掉这个等待，但会引入 policy lag。一条轨迹的生成可能横跨多次模型更新， 精确追踪行为策略 πold 需要保存一串 checkpoint 历史；论文认为这在实践中不可行（SAO §3.1）。 如果直接用当前策略去更新很旧的数据，off-policy 偏差会变成训练震荡。

另一条路是单轨迹：每个 prompt 只采一条，完成即训练。它拆掉了组屏障，但也拆掉了 group baseline； 梯度估计退化成 REINFORCE 式的高方差（SAO §3.2）。所以问题不是「异步还是同步」， 而是「拆掉 group 之后，用什么补方差、用什么挡 off-policy token」。

利用率

等最慢的一条

同步 batch 必须等组内最长轨迹；长尾越重，空转越多。异步消费轨迹能缓解，但不自动解决稳定性。

稳定性

group baseline 会放大延迟

组均值减方差，但组必须等齐；等齐的过程本身制造 off-policy。单轨迹去掉等待，方差又升上来。

线上兼容

环境只回一条轨迹

真实沙箱与在线业务往往一次只给一条反馈；group-wise 采样和这种反馈形态不匹配。

02

GRPO 省了 critic，却把同步屏障留在组里

前人方案分别在「省显存」和「提吞吐」上用力；SAO 要同时处理稳定性和单轨迹反馈。

PPO 的 actor-critic 用独立 value model 估 advantage。论文 §2 指出，这相当于为 value function 再维护一份模型参数， 训练显存 footprint 近似翻倍；换来的是一定程度上的方差控制。GRPO 把这份成本省掉：它不训 critic， 用同一 prompt 的组内归一化奖励做 baseline（SAO §2）。

GRPO 的代价是组屏障。标准 GRPO 在这套 agentic RL 设置里约 160 步崩溃 （SAO §4.2）；它的分数是崩溃前的最后有效值。VAPO 换成长度自适应 GAE 与 value-based RL， 但没有 DIS 时 token-level clip ratio 接近 0，约 90 步崩溃（SAO §4.4、Figure 4c）。 也就是说，「看起来没在裁剪」不等于稳定。

异步系统走的是另一条路。AReaL、ROLL Flash、asynchronous RLHF 等工作把 rollout 与训练解耦，重点在吞吐与墙钟效率； 论文的判断是，这些工作对训练稳定性和任务效果的覆盖不足（SAO Abstract、§5.2）。 Decoupled PPO 进一步保留 πθ、πθold、πrollout 三个策略做重要性采样， 但当一条轨迹横跨多次更新时，πθold 的精确行为概率很难追（SAO §3.1）。

SAO §1–§3 的方案对照；「约 160 步」与「约 90 步」是论文报告的训练崩溃位置，条件为 Qwen3-30B-A3B 的 agentic RL 设置。

SAO 的赌注

用 critic 换掉 group，再把 critic 训好

单轨迹拆掉了组屏障，但把方差控制的担子全压到 value model。SAO 围绕 value model 的四个设计——K=2 的更快 value 更新、 冻结 attention、skip-observation GAE、扩大 value pretraining——都是围绕这一件事。 所以它不是「GRPO 加一个 mask」，而是把 baseline 从组均值换成了 critic。

03

单轨迹 + DIS：把 trust region 做成硬 mask，再用 critic 补方差

SAO 的关键不是「异步」本身，而是异步之后仍能把极端 off-policy token 挡在梯度外。

单轨迹的设置很直接：每个 prompt 只采一条 rollout，轨迹完成就送入训练缓冲区，不等待同组其他样本（SAO §3.2）。 这让训练节奏和线上单条反馈对齐，但也让 advantage 估计失去 group baseline。SAO 的选择是把 baseline 交给 critic， 并用 DIS 处理异步带来的 policy lag。

rt(θ) = exp( log πθ(at|st) − log πrollout(at|st) )
SAO Eq.2：直接用 rollout 阶段记录的 logprob；不再维护 πθold（§3.1）

DIS 的核心是「直接」：行为策略用 πrollout 代替，ratio 只算当前策略与采样策略的差。 论文的理由是，异步 rollout 可能横跨多次模型更新，精确的 πθold 既贵又容易错； 直接用 rollout logprob 可以省掉一次独立的 old-policy 推理（SAO §3.1）。

f(x) = x，若 1−εl < x < 1+εh；   f(x) = 0，其他
SAO Eq.3：区间外的 token 不是被 clip，而是整个 token 从梯度中置零（§3.1）

SAO Eq.1：token-level 目标；f 为 0 的 token 对梯度没有贡献

这和 PPO 的 clip 不是一回事。PPO 的 min/clip 会保留一个被裁剪后的项；DIS 直接把区间外的 token 置零。 论文的措辞是「masked from gradient computation entirely」，并说这让更激进的裁剪成为可能（SAO §3.1）。 区间也不对称：推理任务用 εl=0.3、εh=5.0；coding 任务用 0.8/3.0（SAO §4.1）。 上限比下限宽得多；论文没有解释这组取值的来源。

Value model：单轨迹的方差要用 critic 补

单轨迹没有组内对比，方差比 GRPO 高。SAO 的做法不是再加一个 group，而是把 value model 训好： 每次策略更新配 K=2 次 value 更新（§3.2）；冻结 value model 的 attention，只优化 MoE 投影（§3.2）； 用 skip-observation GAE 处理「模型动作 → 环境观测 → 模型动作」的轨迹；并扩大 value model 的预训练语料（§3.2）。

Â(ai,N) = δ + γλ Â(ai+1,0)      δ = rt + γ V(ai+1,0) − V(ai,N)
SAO Eq.4–5：跳过 ai,N 与 ai+1,0 之间的环境观测 token，把动作价值直接接到下一个动作（§3.2）

环境观测 oi 不是模型生成的，标准 GAE 跨过 oi 去算 V(oi,start)， 等于让 value model 预测一个外部环境状态的价值；论文认为这会引入噪声（§3.2）。 skip-observation 的改法是把 Bellman target 从「动作 → 观测 → 动作」改成「动作 → 下一个动作」， advantage 只在模型自己生成的 token 上传播。论文在 Appendix A.1/Table 5 还比较了 step-level 与 token-level： 同样训练 400 步时，step-level average 是 85.8 / 60.5、last-token 是 87.3 / 62.8、token-level 是 89.8 / 66.8 （AIME2025 / BeyondAIME，Accuracy %）。

这个模拟覆盖了什么：只做 batch 的算术拆分，覆盖 G=1 与 G=8 两种论文设置；不模拟 rollout 长度分布、调度策略、吞吐或 GPU 空转比例。

更新次数上，论文 §3.2 把 K 的单位写成「每次策略梯度更新」，§4.1 与 §4.3 的实验描述写成「每 batch」。 两处单位不同，本页只按原样并列，不把 2 次/更新换算成 2 次/batch。 能确定的是：K=2 是实验设置，目的是让 value 估计在策略漂移之前跟上（§3.2）。

成本也在这里。PPO 式 critic 让训练显存 footprint 近似翻倍（§2）；SAO 仍然需要 critic， 冻结 attention 只是减少可训练参数，论文没有给出显存账本。所以「省掉组等待」不等于「省掉 critic 的显存与训练时间」。

05

采样、缓冲、训练解耦；轨迹完成即入队

算法上是一条轨迹立即训练；工程上要靠 rollout、training、buffer 同一条 dataflow 才能不重建训练栈。

逐步拆开：一条轨迹从生成到更新

  1. 生成。Rollout 引擎对每个 prompt 生成一条轨迹，记录 token-level logprob。SAO 的 batch 是 G=1，所以不需要等同一 prompt 的其他样本（§3.2、§4.1）。
  2. 入队。轨迹完成即进入训练缓冲区；这是「单轨迹异步」和「分组同步」的分界点（§3.2、Figure 2）。
  3. 算 ratio。训练侧用当前策略与 rollout logprob 算 rt；不维护 πθold（Eq.2）。
  4. mask。落在 [1−εl, 1+εh] 外的 token 置零；区间内的 token 保留原 ratio（Eq.3）。
  5. 估 value。critic 以 K=2 更新，冻结 attention、只训 MoE 投影；skip-observation GAE 跨过环境观测，算动作到动作的 advantage（§3.2、Eq.4–5）。
  6. 更新与同步。策略按 Eq.1 更新，更新后的权重回到 rollout 侧。GLM-5.3 博客称 slime 把训练、rollout、buffer 放在同一条 dataflow 上，训练侧 Megatron、采样侧 SGLang（§slime）。

稳定性方面，标准 GRPO 约 160 步崩溃；SAO 训练到 1000 步（Abstract）；SAO 与 GRPO (+ DIS) 在约 400 步后才出现明显分化（§4.2）。VAPO 在约 90 步崩溃（§4.4）。这些是论文报告的训练动态，不是收敛性证明。

一个反直觉的数字在 Table 1：未做 TIR SFT 的 Qwen3-30B-A3B，AIME2025 在 w/ python 时是 14.6，w/o python 时是 85.0； SFT w/ python 才回到 80.4。 推断（由 Table 1 反推）：工具本身不是增益，模型要先学会在推理里调用工具； 未对齐的基座把 python 当成额外噪声。

frozen attention 的代价也不均匀：AIME 掉 6.7 个百分点， BeyondAIME 只掉 0.3 个百分点（Table 4）。 同一个改动在不同 benchmark 上的代价差了一个数量级，不能用一个平均分概括。

不要相加

SAO 的 +13.1 和 GLM-5.3 的 +23.7 不是同一把尺

SAO 的 AIME/BeyondAIME/HMMT/IMO 数字来自 Qwen3-30B-A3B、reasoning-with-Python、Pass@1；SWE-Bench Verified 来自 OpenHands、Pass@1；GLM-5.3 的数字来自官方博客、开放权重模型（博客称 open-weights）与各 benchmark 自己的 harness。 模型、数据、评测协议都不同。本页把它们并排，是为了看清「后训练 scaling」的两层证据，而不是做加法。

07

省掉的是等待，不是 critic 的成本

SAO 的适用边界由 value model、logprob 基础设施和实验覆盖决定；GLM-5.3 的证据强度则由官方博客决定。

方法边界

  • critic 是方法的一部分。PPO 式 critic 让训练显存 footprint 近似翻倍（§2）；SAO 冻结 attention、只训 MoE 投影，但论文没有给出显存账本。省掉的是组等待，不是 critic 的显存与训练时间。
  • 依赖 token-level rollout logprob。DIS 的 rt 直接来自 rollout 阶段记录的 logprob；Appendix B 明确说部署需要能可靠保留行为概率的基础设施。
  • 单轨迹的方差更高。没有 group baseline，梯度估计接近 REINFORCE；SAO 用 critic 补，但 critic 冷启动需要扩大的 value pretraining 语料（§3.2）。
  • frozen attention 不是无损正则。AIME 掉 6.7 个百分点，BeyondAIME 只掉 0.3 个百分点（Table 4）；代价依 benchmark 而变。

实验边界

  • 只测 Qwen3-30B-A3B。Appendix B 说结论不一定迁移到更小模型、非 agentic RLHF、dense reward 或更短 rollout。
  • online learning 是模拟。§4.5 用写作风格切换（cute → chuunibyou → classical）和 GLM-4.7 judge 做在线学习仿真；不是真实线上部署。
  • 稳定步数不等于收敛证明。1000 步是论文报告的训练长度；论文没有给出长期收敛或跨规模外推的证明。

来源边界

  • GLM-5.3 的证据是博客；未找到专门技术报告。已核实的官方材料是 2026-08-14 的博客与 HF 模型卡；HF 模型卡引用 GLM-5 技术报告（arXiv 2602.15763v2，2026-02-24），其中未提 GLM-5.3；未找到 GLM-5.3 专门技术报告（检索日 2026-11-06）。
  • 参数量口径存在差异。博客与 SAO 论文未给 GLM-5.3 参数量；HF 模型页元数据显示 753B 总参数（753,329,940,480），未给激活参数。笔记的 743B/40B 中，743B 与 HF 的 753B 不符；40B 未作为 GLM-5.3 的激活参数出现；SAO 论文中的 40B 属于 GLM-5.2（750B-A40B）。
  • 「50% improvement」与 Max effort 绝对值的关系未说明。博客给出 GLM-5.2 23.4%（96K）与 GLM-5.3 34.5%（~75K）；50% 的具体口径未说明，本页不替它换算。
  • SAO 只到 v1。本页以 arXiv 2607.07508v1（2026-07-08）为准；论文部署的是 GLM-5.2，不是 GLM-5.3。

什么时候别用

  • 短 rollout、同步 batch 已经够用。GRPO 更简单，不需要 critic；SAO 的目标场景是长程、长尾、单轨迹反馈。
  • 没有 critic 的显存/训练预算。SAO 把成本从组等待转移到 value model；论文没有给出 critic 训不起来时的降级方案。
  • rollout 引擎不能保留 token-level logprob。DIS 的 ratio 没有可靠输入，方法的核心假设不成立。
  • 需要同行评审级别的 GLM-5.3 证据。目前只有官方博客与模型卡；benchmark 数字是官方报告值，不是独立复现。
一句话

SAO 用 critic 换掉 group 屏障；GLM-5.3 用后训练换掉新基座

两者都是 scaling 的账本：SAO 把成本记在 critic 和 logprob 基础设施上，GLM-5.3 把成本记在环境、数据与 RL 系统上。 看清账本，再决定要不要把这套 stack 搬到自己的模型和任务上。
