MemAgent：用固定长度记忆，把 8K 上下文拉到 3.5M

长文本处理的「不可能三角」是无限长度、无损性能、线性成本。MemAgent 不在注意力结构上改，而是把文档切成块，让模型每读一块就覆盖一次固定长度的记忆；记忆更新被当成 RL 动作，用 Multi-Conv DAPO 端到端训练。 代价是：它把「读长文」变成了「串行地写摘要」，省的是注意力，不是总延迟。

Hongli Yu, Tinghong Chen, Jiangtao Feng, Jiangjie Chen, Weinan Dai, Qiying Yu, Ya-Qin Zhang, Wei-Ying Ma, Jingjing Liu, Mingxuan Wang, Hao Zhou · Tsinghua AIR / ByteDance Seed / SIA-Lab arXiv 2507.02259v2 ↗ 博客笔记 ↗
TL;DR · 30 秒抓住核心

做法只有三步：把长文切成 K 个块；每读一个块，模型把「问题 + 旧记忆 + 当前块」压成一段固定长度的新记忆，覆盖旧记忆；读完后只用「问题 + 最终记忆」回答。 因为记忆长度固定，每一步的上下文窗口恒定，端到端计算量随块数线性增长。

难点在于「覆盖」是离散操作，不能直接反传。论文把每次记忆更新当成一个独立对话，把最终答案的奖励广播给所有前序对话，得到 Multi-Conv DAPO：损失从 (group, token) 扩成 (group, conversation, token)。

结果：Qwen2.5-14B 在 8K 窗口、1024 token 记忆、5000 token 块的设置下训练，v2 Table 1 里 7K 到 3.5M 从 80.47 降到 71.09，差 9.38 个百分点（相对 11.7%）。 论文摘要说「loss of less than 10%」；按百分点读成立，按相对值读不成立。笔记里的 83.59 → 78.12 是 v1 的旧行，v2 已改。

01

上下文窗口不是「存不下」，而是「算不起、用不好」

先拆开三个约束：长度、性能、成本；再看为什么现有路线总得放弃一个。

论文把长文本处理的目标写成三件事：能处理任意长度；长度增加时性能不明显下降；解码复杂度随长度线性增长。三者同时满足很难，因为标准 Transformer 的完整注意力是 O(n²)：文本翻倍，注意力计算约翻四倍（§1）。

现有路线各占一角。位置编码外推（YaRN、NTK-aware RoPE 等）加继续预训练，能把窗口拉长，但极长文本下仍有性能衰减和 O(n²) 的计算；稀疏注意力、线性注意力能降复杂度，却往往要重训，且线性注意力并行训练困难、稀疏模式依赖人工设计；上下文压缩（token 级或外挂记忆模块）能缩短输入，但外推能力有限，还要改生成流程（§1）。

论文的切口

不改注意力，改「模型每一步能看到什么」

MemAgent 把长文看成一个受控的证据流：每一步只让模型看「下一个文本块 + 一段固定长度记忆」。记忆是普通 token，放在上下文窗口里，所以基座模型的生成过程不用改；记忆长度不增长，所以每步计算恒定，总复杂度随块数线性增长（§2.1）。

这相当于把「一次读完」换成「边读边记笔记」。论文的类比是人类处理长文时会记要点、丢冗余；但要注意，模型的「笔记」仍是一段文本摘要，不是结构化数据库，也没有显式的检索或遗忘操作（§1、§2.1）。

02

三条长文本路线，加上 GRPO/DAPO：缺的是「多段独立对话」的优化

MemAgent 的 novelty 不在某个单点技术，而在把记忆更新建模成跨多个独立上下文的 RL 问题。

长度外推

改位置编码 + 继续预训练

通过移位位置嵌入、YaRN 等方法扩展窗口；配合长文本继续预训练。

卡点：极长文本仍有性能衰减；完整注意力仍是 O(n²)（§1）。

高效注意力

稀疏 / 线性注意力

稀疏注意力只算部分 token 对；线性注意力把复杂度降到线性。

卡点：常要重训；线性注意力并行训练难，稀疏模式依赖人工设计（§1）。

上下文压缩

token 压缩 / 外挂记忆

把长文压成短表示，或外接记忆模块；RAG 也属于外部检索路线。

卡点：外推能力有限；要改生成流程，兼容性和并行化受影响（§1）。

训练算法侧，论文以 DAPO 为基础。DAPO 从 GRPO 改进而来，用组内相对优势、裁剪和动态采样做 RLVR。但标准 DAPO 的损失结构是 (group, token)：一个样本对应一条轨迹。MemAgent 一次处理长文会生成多条上下文独立的对话（每次记忆更新一条，最后回答一条），这些对话不共享注意力，不能简单拼成一条多轮轨迹（§2.2）。

所以论文把每条对话当成独立优化目标，损失扩成 (group, conversation, token)；最终答案所在对话给出奖励，优势广播到同一样本的所有对话。这个改动是整篇论文的方法核心，而不是「换一个更强的基座」（§2.2、Figure 3）。

03

固定记忆 + 覆盖写 + 奖励广播：三个部件咬成一个循环

先看工作流，再看 Multi-Conv DAPO 的目标函数，最后看训练配方。

工作流：每读一块，覆盖一次记忆

设文档被切成 K 个连续块 c¹, …, c^K，每块长度不超过 C；记忆长度固定为 M。读完第 k 块后，模型生成新记忆 m^k，覆盖旧记忆 m^{k-1}。因为 |m^k| = M 恒定，每一步的计算与显存是 O(C+M)，总复杂度 O(N)（§2.1、§2.3）。

推理分成两个模块：Context-Processing 循环读块、更新记忆；Answer-Generation 在流结束后只拿「问题 + 最终记忆」生成答案。论文强调，位置嵌入没有被重新缩放或打补丁，两个模块共用同一套 tokenization 和注意力布局，因此不需要架构修改（§2.1）。

p(x1:N) = Σm1:K−1 ∏k=1K p(ck | mk−1) · p(mk | ck, mk−1)
Eq.4 · 读（read）与写（write）的分解；m0 = ∅。记忆是潜变量，RL 优化的是一条读—写轨迹

Multi-Conv DAPO：把最终奖励广播给所有记忆更新

对每个问题 q_i，策略采样一组 G 个样本；每个样本 i 生成 n_i 条对话 (oi,1, …, oi,n_i)，每条对话再分解成 token。最终答案只在最后一条对话里，奖励是二值的：答案等价得 1，否则 0（Eq.3）。

优势不按每条对话单独算，而是用样本级奖励减去组内均值，然后原样广播到该样本的所有对话、所有 token：

Âi,j,t = Ri − mean({Ri}i=1G)
Eq.1 · 所有 j、t 共用同一个 Â；论文遵循 Dr. GRPO，不除以标准差

损失在「组 × 对话 × token」三个维度上归一化，并对每条对话的每个 token 做 PPO 式裁剪：

JDAPO(θ) = E[ (1 / ΣiΣj|oi,j|) ΣiΣjΣt ( Ci,j,t − β DKL(πθ || πref) ) ]
Eq.2 · Ci,j,t = min(r·Â, clip(r, 1−εlow, 1+εhigh)·Â)；r 是当前策略与旧策略的 token 概率比

这个设计的关键不是「把奖励分给每一步」这么简单，而是让模型学到一种跨对话的信用分配：某一次记忆更新写得好不好，要看它是否让最终答案正确，而不是看它自身是否像某条参考摘要。论文把它解释为优化一个读—写记忆轨迹的 MDP（§2.3）。

训练配方：两阶段课程，8K 窗口

基座是 Qwen2.5-7B-Instruct 与 Qwen2.5-14B-Instruct；框架基于 verl。训练故意把上下文限制在 8K，以测试外推。8K 的分配是：查询 1024 token、文本块 5000 token、记忆 1024 token、输出 1024 token，剩余留给 chat template（§3.1）。

课程分两阶段：Stage I 用 32,768 条合成 QA，每条约 32K token，基于 HotpotQA 并按 RULER 方法在大量干扰段落中嵌入金段落；Stage II 用 2,560 条最长 60K token 的困难长文 QA，来自 DocQA-RL-1.6K，并与 Stage I 数据混合。Stage I 收敛约 400 步后切到 Stage II（§A.3）。

04

线性的是 FLOPs，不一定是你感受到的延迟

固定窗口把每步成本压平，但串行读块意味着总延迟仍随块数增长。

标准完整注意力的计算随上下文长度平方增长；MemAgent 每一步只看 C + M 个 token，记忆不增长，所以每步成本恒定，总 FLOPs 随块数 K 线性增长。论文用 verl 的 FLOP estimator 在 8K–4M 长度上对比，Figure 10 显示基线是 O(n²)，MemAgent 是 O(n)（§B、Figure 10）。

从 8K 训练窗口到 3.5M 测试长度，长度约是窗口的 437.5 倍（按 3,500,000 / 8,000 计；3.5M 见 §3.2/Table 1，8K 见 §3.1）。这个倍数能成立，靠的是「每步窗口不变」，而不是模型学会了 3.5M 位置的注意力（§2.1、§3.1）。

成本边界

论文只给了 FLOPs，没给墙钟时间

论文没有报告 GPU 型号、卡数、总 GPU 小时，也没有给不同长度下的端到端延迟或吞吐。FLOPs 线性不等于延迟线性：每个块要等上一块写完记忆，串行依赖无法并行。对低延迟场景，这可能比「一次前向」更慢，尽管总算力更低（§B；Appendix 未给墙钟指标）。推断（依据：§B 只讨论 FLOPs；全文未给 wall-clock 或 GPU 小时）。

另一项成本是记忆管理的「信息取舍」：记忆固定 1024 token，读 3.5M token 意味着极大的压缩比。压缩比越高，早期关键信息被覆盖的风险越大；论文用 RL 训练来缓解，§3.3.3 的 probe 是检验位置鲁棒性的诊断实验，不是缓解机制，也没有给出「信息丢失率」这类直接指标（§3.3.3、Table 4；Table 4 未完整转录）。

消融与探针：RL 必要，记忆长度不敏感，位置效应不单调

RL 消融（NIAH 见 Figure 5，RULER-HQA 见 Figure 6，LongBench-QA 见 Figure 7）：没有 RL 的 MemAgent 在短文本上可能优于基座，但随着长度增加仍明显下降；RL 之后曲线更平。论文的措辞是 RL 训练对「generalizable and robust memory abilities」必要，但没有给逐点数值表，只有图（§3.3.1、Figure 5、Figure 6、Figure 7）。

记忆长度消融（Figure 8/9）：在 256–4096 token 范围内，论文称 1024 是「reasonable sweet spot」，且性能对记忆大小较稳健；§3.3.2 只给 Figure 8/9，Appendix D.1 的 Table 8/9 有逐点消融数据（14B/7B × m4096/m3072/m2048/m1024 × c1928/c2952/c3976/c5000；Table 8 各长度 / Table 9 各基准）。Table 8/9 未完整转录。

上下文分布探针（Table 4）：把两组关键信息放在 (0%,100%)、(20%,80%)、(40%,60%)、(0%,20%)、(80%,100%) 五种位置组合，14B 在部分设置上高于 random，部分设置上低于 random。例如 (0%,20%) 在 14K 上 −3.91、在 224K 上 +4.69。论文的结论是「没有灾难性下降」，而不是「所有位置都无损」；页面按这个限定呈现（§3.3.3、Table 4；Table 4 未完整转录，仅摘此两例）。

07

它把「长文 QA」做成了流式记忆，但不是通用长文理解

论文自己承认的限制，加上从实验设置能看到的边界。

边界一

评测集中在可验证的 QA 与摘要

主实验是 RULER-HQA（合成多跳 QA）、LongBench-QA（NarrativeQA、Qasper、HotpotQA、2Wiki、MuSiQue）和 LongBench-SUM（GovReport、QMSum），奖励是答案等价的 0/1。没有开放式写作、多轮对话、代码库理解或需要全局抽象的任务（§3.1、§3.2）。

边界二

串行读块：FLOPs 线性，延迟不一定

每读一块都要等上一块写完记忆，块与块之间有串行依赖。论文只报 FLOPs（Figure 10），没有报墙钟延迟、吞吐或 GPU 小时；对低延迟应用，线性 FLOPs 可能仍比一次前向慢（§B）。推断（依据：§B 只讨论 FLOPs；全文未给 wall-clock 指标）。

边界三

固定 1024 token 记忆，压缩比极高

3.5M token 的文档最终只留 1024 token 记忆，压缩比约 3418:1（3,500,000 / 1024；3.5M 见 Table 1，1024 见 §3.1；该比值是页面推算）。早期关键信息一旦被覆盖，后续无法找回；论文用 RL 训练缓解，§3.3.3 的 probe 检验位置鲁棒性，不给信息丢失率或可恢复性指标（§3.1、§3.3.3、Table 4；Table 4 未完整转录）。推断（依据：记忆固定 1024 token；§3.3.3 只给准确率探针，没有信息保留率）。

边界四

基座与训练数据范围窄

只验证了 Qwen2.5-7B/14B-Instruct，训练数据是 HotpotQA 合成的 RULER 风格 QA 加 DocQA-RL-1.6K；没有跨模型家族、跨语言、跨领域的实验。论文的「any moderately context-sized LLM」是设计主张，不是已被多基座验证的结论（§3.1、§A.3）。

什么时候别用：如果任务需要精确引用原文、逐字定位、或对整篇文档做全局结构推理，固定长度摘要记忆会丢细节；如果任务本身短于训练窗口，分块反而增加串行开销；如果应用不能接受「读完整篇才能回答」的延迟，MemAgent 的流式循环也不合适。推断（依据：论文的任务与指标集中在 QA/摘要；未覆盖精确引用与低延迟场景）。
