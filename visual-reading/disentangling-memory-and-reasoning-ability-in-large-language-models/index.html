Disentangling Memory and Reasoning：把 LLM 的「回忆」和「推演」拆成两种可训练动作

LLM 回答多跳问题时，既在回忆事实，也在做逻辑推演。现有 CoT 把两者混在一段连续文本里，答错了很难判断是「记错」还是「想错」。 论文给每一步加一个控制 token——⟨memory⟩ 或 ⟨reason⟩——用 GPT-4o 造带标签的数据，再用 LoRA 把这两个 token 教给学生模型。

TL;DR · 30 秒抓住核心

LLM 在多跳问答里既要回忆事实，又要做逻辑推演。现有 CoT 把两者混在一段连续文本里，答错了很难判断是「记错」还是「想错」。

论文的做法是给每步加一个控制 token：⟨memory⟩ 后面跟回忆出的事实，⟨reason⟩ 后面跟推演。教师模型 GPT-4o 生成带标签的 CoT，并把 memory 步改写成事实问题交给知识模型作答；学生模型用 LoRA 学这套序列。

LLaMA-3.1-8B 在 TruthfulQA 上达到 86.6%，比 GPT-4o CoT 的 85.4% 高 1.2 个百分点；但三数据集平均 82.3%，比 GPT-4o CoT 的 84.2% 低 1.9 个百分点。

更值得带走的是错误归因：StrategyQA 有 98.3% 的错误来自推理，CommonsenseQA 和 TruthfulQA 约 78% 来自推理——模型多数时候「知道」，但「用不对」。

01

问题：一段 CoT 里，「查知识」和「做推理」没有边界

先建立共同认知：不是模型不知道，也不是模型不会推，而是两者混在一起，错了无法归因。

多跳问答要求模型在每一步先回忆相关事实，再基于事实做推演。论文在 Appendix C.1（Dataset）用 StrategyQA 的「亚里士多德用过笔记本电脑吗」举例：模型得先回忆亚里士多德生活的年代、笔记本电脑发明的时间，再比较两者。任何一步出错，最终答案都可能错。

问题在于，现有 LLM 的输出是一条连续 token 流。模型可以在同一段 CoT 里既回忆又推演，但没有任何显式标记说明哪一段是回忆、哪一段是推演。论文在 §1 把这种状态称为「不透明的过程」：

“However, despite these advancements, existing inference frameworks often operate as an opaque process without explicit separation between knowledge retrieval and reasoning steps.”（§1）

这会带来两类失败：一类是记忆错误——模型回忆出错误或过时的事实；另一类是推理错误——事实是对的，但推演链断了。没有步骤标签，错误分析只能看最终答案，无法区分这两类。

失败 A

记错了

模型 recall 出的事实本身不对，后面推得再顺也会错。论文把这类问题归到 memory。

失败 B

想错了

事实 recall 对了，但模型在比较、归纳或多步传递时出错。论文把这类问题归到 reason。

论文要回答的两个问题因此很具体：能不能让模型在生成时显式区分 memory 和 reason？以及这种区分能不能同时带来准确率和可解释性？后面的两个 token、数据合成和消融，都是围绕这两个问题展开的。

02

已有两条路线，各修一半

一条路补知识，一条路补结构；论文认为两者都没有把「知识召回」和「逻辑推演」分开。

Memory-based

RAG：把外部知识取进来

RAG 等方法重点解决「模型参数里的知识不够或过时」：先检索，再把检索结果放进上下文。

强项：能补外部事实，尤其是长尾知识。

没解决：检索是独立模块；取回来的知识怎么进入推理、什么时候该取，仍然混在模型的连续生成里。推断（依据：§1 把 RAG 归为 memory-based 路线，重点是补外部知识；§4 指出参数记忆研究没有回答「how to better elicit the parametric knowledge」，本页把这一点推广到 RAG 属于推断。）

Reasoning-based

CoT / Planning token：把步骤结构起来

CoT、ToT 和 planning token 等方法重点解决「推理步骤怎么组织」：让模型分步想，或用可训练 token 标记任务阶段。

强项：把长链条拆成短步骤，提升可读性。

没解决：步骤结构有了，但每一步仍然同时包含事实召回和逻辑推演；planning token 规划的是任务阶段，不是「这一步在回忆还是在推理」。

“Despite the effectiveness, these methods intertwine reasoning and memory usage, which may limit the full potential of the models.”（§4；these methods 指引入可训练 token 的 tuning-based 方法）

§4 对 prompt-based 方法的判断则更直接：“the models might not know when to reason or use their memory.” 两条路都没有把「这一步在回忆还是在推理」变成训练信号；上面那句批评针对的是 tuning-based 方法，不是 RAG。

论文的切入点不是再做一个检索器，也不是再设计一种提示词，而是把「这一步在做什么」变成训练信号：每一步要么是 memory，要么是 reason。这样模型在生成时就必须先选动作，再写内容。

03

核心：把每一步标成 ⟨memory⟩ 或 ⟨reason⟩

不是改模型结构，而是改训练序列的格式：两个特殊 token 把「回忆」和「推演」变成两种可学习的动作。

论文把一条训练实例写成三段：问题、带标签的中间步骤、答案。中间步骤里，memory 段以 ⟨memory⟩ 开头，后面跟回忆出的事实 token；reason 段以 ⟨reason⟩ 开头，后面跟推演 token。

T = Q ⊕ ⟨memory⟩ K ⊕ ⟨reason⟩ S ⊕ A
§2.2 的序列结构：Q 是问题，K 是事实知识 token 序列，S 是推理 token 序列，A 是答案；为便于阅读，这里把交错的多个 memory/reason 块各合并成一项

两个 token 不是普通文本，而是可训练的 out-of-vocabulary token。论文在 §2.2 明确说，模型用标准自回归方式做 LoRA 微调；训练目标仍是 next-token prediction。论文没有为 memory/reason 另设一个分类 loss。推断（依据：§2.2 只描述标准自回归 LoRA 目标，全文未出现额外的分类损失。）token 的作用是给模型一个可学习的「动作开关」。

关键细节

memory 后面跟的是「事实」，不是「问题」

数据合成时，教师模型先把 memory 步里的知识改写成事实问题，让知识模型作答；答案再回填到原步骤。所以训练序列里的 ⟨memory⟩ 后面是陈述性事实 K，而不是问题本身（§2.1）。

这套格式把「模型知不知道」和「模型会不会用」拆成两个可观察的量：memory 段对应知识召回，reason 段对应逻辑推演。后面的错误分析之所以能把错误归因到 memory 或 reason，前提就是这两个标签在训练时已经进入了序列。

1

生成

推理 LLM 写 CoT，并给每一步打上 ⟨memory⟩ 或 ⟨reason⟩。

2

补知识

memory 步改写成事实问题，知识 LLM 作答，答案回填。

3

微调

学生模型在标准自回归目标下学整条序列，两个 token 参与训练。

04

怎么训：LoRA + int8，一张 RTX 6000 Ada

训练配置不复杂；真正的成本在造数据，以及推理时 retrieval-based processing 带来的额外计算时间（§6 / Appendix F.2）。

模型

三个学生模型

LLaMA-2-7B-chat、LLaMA-3.1-8B-Instruct、Qwen2.5-7B-Instruct（§3.1）。

教师与评估器：GPT-4o 负责推理和知识生成，并完成错误归因（§3.4.3、Appendix E.2）；GPT-4o-mini 负责准确率/解耦评估（§3.1、§3.4.1）。Appendix E.2 正文有一处把 Figure 17 的 prompt 误写成 GPT-4o-mini，图题本身写的是 GPT-4o。

配置

LoRA + int8

learning rate 2e-4，warmup 1000，cosine schedule，adamw_torch，gradient accumulation 16，int8 训练（Appendix D.1，Training Configuration）。

特殊 token：N_PREFIX=3、N_SPECIAL=4；全部微调在单张 RTX 6000 Ada 上完成（Appendix D.1）。

训练轮数按数据集不同：StrategyQA 通常 10 个 epoch，CommonsenseQA 约 5 个 epoch 收敛，TruthfulQA 需要 15 个或更多（Appendix D.2 / Figure 14）。数据生成阶段需要两个 GPT-4o 角色多次调用（§2.1）；§6 / Appendix F.2 还指出，retrieval-based processing 会增加推理时的计算时间。

流程：教师模型造数据，学生模型学动作

Figure 1 的流程可以拆成两段：先用两个 GPT-4o 角色合成带标签数据，再用 LoRA 让学生模型学会这套序列。

下面用论文 Appendix A.2 / Figure 7 的 MMA 例子走一遍。每一步都对应 §2.1 的一个动作；这是流程级示意，不是论文 prompts 的逐字复现。

原始问题

StrategyQA：Is MMA totally original from the Roman Colosseum games?

正确答案：False。要回答它，模型得先回忆 MMA 和罗马角斗，再比较两者的关系。

流程里哪些是原文，哪些是页面简化覆盖 / 未覆盖分支

覆盖：推理 LLM 生成 CoT 并逐步打标；memory 步改写成事实问题；知识 LLM 作答；答案回填；训练序列由 Q + memory/reason 块 + A 组成；学生模型用 LoRA 学标准自回归目标（§2.1、§2.2）。

07

边界：标签分开了能力，但没有替你补上能力

论文自己列了限制；结合实验范围还能看出几条适用边界。

边界一

教师和标注质量是上限

训练数据由 GPT-4o 生成：它写 CoT、打标签、回答 memory 问题。教师模型的知识盲点或错误标签会被学生继承。推断（依据：Appendix F.2 指出训练数据中缺失或代表性不足的知识会导致回答不准确或不完整；论文未直接量化教师标签错误向学生的传播。）论文在 §6 说，方法依赖训练数据的质量与覆盖面，知识在训练数据中缺失或代表性不足时，检索可能不完整（Appendix F.2 同样指出这一点）。Appendix B.1 用 Jaccard 相似度低于 10% 论证提升不只是知识蒸馏，但这仍是间接证据，不消除对教师的依赖。

边界二

二元标签对复杂推理可能不够

论文在 §6 承认，多跳或深层嵌套逻辑不一定能干净地拆成离散的 memory/reason 步；这种情况下，两个标签的边界会变模糊。论文未报告这类任务的定量结果。

边界三

步骤越多，计算开销越大

§6 / Appendix F.2 指出，把 memory recall 与 reasoning 拆开、引入 retrieval-based processing 会增加计算时间，这对实时应用是限制；原文没有报告序列长度或显存占用的具体测量。数据生成阶段还需要两个 GPT-4o 角色多次调用（§2.1）。

边界四

评测范围只有三类 QA

实验覆盖 StrategyQA、CommonsenseQA、TruthfulQA 三个数据集，指标是准确率，评估由 GPT-4o-mini 完成（§3.1、Appendix C.2，Evaluation Metric）。没有数学、代码、长文本生成或开放式对话任务；论文也未报告显著性检验。推断（由 §3.1 的实验设置与 Table 1–7 的覆盖范围归纳）

一句话：这套方法买的是可检查的中间步骤，不是无条件的准确率提升。当任务能自然拆成「事实召回 + 逻辑推演」，并且你愿意承担教师模型造数据的成本时，它最合适；如果任务本身不可分解，或者你需要的是一次调用、低延迟的答案，两个标签可能帮不上忙。推断（依据：§2.1 的流程要求每步可标为 memory 或 reason；§6 / Appendix F.2 指出 decomposition 会增加计算时间。）
