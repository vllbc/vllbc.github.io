LearnAct：让智能体自己写工具，而不是只改提示

LLM 智能体的动作空间通常是写死的：规划层说“把杯子搬过去”，执行层只有“移动、抓取、放下”。 LearnAct 让一个更强的学习者 LLM 把常用动作组合写成 Python 函数，再在失败轨迹上迭代修函数或补使用说明。 每个任务只拿 3 个训练实例，剩下的实例用来测泛化。

Haiteng Zhao, Chang Ma 等 · 北京大学 / 字节跳动 / 香港大学 arXiv 2402.15809v2 ↗
TL;DR · 30 秒抓住核心

论文把瓶颈定位在“能做什么”，而不是“怎么想”。ReAct 是提示框架（Table 1 的 Learnable 为 ✗）；Reflexion（ReAct+Reflexion）学的是自然语言层面的策略：下一步该想什么、该怎么改提示。动作空间本身没有变。LearnAct 换了一个作用点：让智能体把若干原子动作封装成新的 Python 函数，再用环境返回的失败信息修改这些函数。

学习循环分两段。ActionCreation 先生成动作函数，并为每个函数写描述和使用示例；ActionLearn 在训练实例上跑出失败轨迹，选出错误案例，让学习者 LLM 改函数或补说明。每轮改 K=4 份候选，逐个在训练集上评估，按 μ = psucc + pstepacc 选最好的一份。

在 GPT-4 上，Robotic Planning 平均成功率 82.8%，比 ReAct+Reflexion 的 66.7% 高 16.1 个百分点，比 Voyager 的 72.1% 高 10.7 个百分点；AlfWorld 平均 72.2%，比 Voyager 的 58.0% 高 14.2 个百分点。

但收益不是无条件的：换成 GPT-3.5 当被测模型，Robotic Planning 平均只剩 23.2%；逐任务看也有反例，GPT-4 的 AlfWorld Look 上 Voyager 反而高 4.1 个百分点。所谓“学习”也主要是改已有函数（86% / 92% 的修改是 Function Updating），动作数量几乎没涨。

01

动作空间是写死的，规划再聪明也只能用同一套扳手

先分清两件事：策略学习改的是“怎么选”，动作学习改的是“有哪些可选”。

语言智能体的典型结构是：LLM 生成下一步动作，环境执行后返回观察或错误信息，循环到任务结束。动作集合 A 由开发者预先给定，通常是很底层的原语：move()、pick()、drop()。论文在引言里用调酒举例：如果要做一杯 Old Fashioned，标准做法是 muddle sugar；但环境里只有糖浆，没有方糖。智能体如果能改写动作，就可以把“加糖浆”封装成一个新动作推断（依据：§1 的 Old Fashioned 例子；原文说要调整预设动作以避免反复失败，未直接写“封装”）；如果动作空间固定，它只能在原有原语上反复失败（§1）。

论文把固定动作空间带来的问题归成两类（§1）：

错位

常识规划与底层动作对不上

LLM 的规划是在“把饮料调好”这个抽象层做的，可执行动作却只有“移动到某处、抓住某个瓶子”。中间的抽象层要由模型自己在推理里补齐，步骤一长就更容易断。

失败

前置条件不满足、策略无效

原语动作往往有前置条件：手上已经有东西时不能再抓；容器没打开时不能倒。每一步都要模型记住并检查这些条件，错误会沿着长序列累积。

作者的判断是：这些失败不全是“想得不够好”，而是“工具不够用”。如果智能体能从失败经验里造出更贴合任务的动作，规划层需要覆盖的步骤会变短，错误暴露面也会变小。这就是论文标题里的 Action Learning。

论文的立场

动作学习与策略学习不是同一层

论文 §5.4 的原话是：“Action learning outperforms the verbal policy learning... possessing proficient skills is essential for the agent to fully realize its potential.” 它没有否认提示和反思的作用，但认为这些手段主要在规划层加码，不能替代动作空间的扩展推断（依据：§5.4 称 verbal policy 与 prompt 对规划的帮助有限、proficient skills 才让智能体充分发挥；原文未直接断言“不能扩展工具”）。

02

前人改“怎么想”，很少有人系统改“能做什么”

四条路线放在同一张表里，差别主要在两点：动作是不是代码，以及学习是不是闭环。

论文在 Table 1 里把代表性方法按五个维度摊开。“Closed Loop”指有没有环境反馈驱动的闭环学习；“Action Type”指动作是自然语言还是代码；“Learnable”指动作本身能不能被学习；“Transferable”指学到的动作能否迁移；“Learnable Module”指学习发生在策略层还是动作层。

两条对照最值得注意。第一条是 ReAct+Reflexion：它有闭环，但学到的产物是自然语言策略，动作类型仍是 Natural language，学习模块写的是 Policy。Reflexion 的反思会改进下一次尝试，却不会沉淀成一个可调用的新动作。第二条是 Voyager：动作类型已经是 Code，学习模块也是 Action，但 Table 1 把它的 Transferable 标成 ✔、Learnable 带 MineDojo 脚注；论文用这张表把“能学代码动作”和“能在不同任务间迁移”分开。

CodeAsPolicy 则是另一头：动作是代码，但没有闭环学习（Closed Loop 为 ✗）。它说明“把动作写成代码”本身不够，代码必须进入“执行—失败—修改”的循环，才会随经验变好。

LearnAct 的位置很清楚：动作类型用代码，学习模块放在动作层，学习过程闭环。它要验证的假设是：把学习对象从提示换成函数，智能体的能力边界会随经验扩张，而不只是把同一套动作用得更好。

03

把动作写成函数，再用失败案例改函数

核心只有两个动作：先生成动作函数，再按失败轨迹迭代修改；采样是为了过滤掉改坏的那几次。

ActionCreation：先造函数，再写说明书

训练开始时只有原始动作集 A0 和基础指令 π0。学习者 LLM F 先读任务说明，生成一组新的动作函数 A′。这些函数是普通 Python 代码，可以调用 pick()、move() 这类原语，也可以使用条件、循环和断言。论文强调的正是后者：代码让动作能表达“如果手上有东西就先放下”这类逻辑，而不只是固定顺序的宏（§4.1）。

函数生成后，还要生成使用说明 πA′。每份说明包含两件事：函数描述（它做什么、需要什么前置条件）和使用示例（在什么场景下调用、参数怎么填）。这两部分会和原始指令一起拼进被测智能体的提示。论文把这一步拆成两个子步骤：先生成描述，再生成示例（§4.1、Appendix）。

ActionLearn：从失败轨迹里选一个案例来改

每轮迭代，被测智能体带着当前动作集在 M 个训练实例上执行。论文的选择规则是 SelectErrorCase：从失败结果里挑出一条轨迹，把状态序列 s1:T、动作序列 a1:T 和失败信息交给学习者 LLM。学习者有两条修改路径：

路径 A

Function Updating

直接改函数体。例如发现“手上已有物体时不能再抓”，就在函数里加一个前置检查。论文观察到绝大多数修改走这条路。

路径 B

Note Writing

函数逻辑不改，只补使用说明。适合“代码没写错，但调用场景不对”的错误。改完的说明会和函数一起进入下一轮提示。

这两条路径是二选一：§4.1 写 “LLM F is free to choose one of them”，Table 4 里两项占比在每个环境都恰好加和为 1（0.86 + 0.14、0.92 + 0.08）。论文还允许学习过程新增函数，所以动作集可能变大。

为什么要采 4 份候选：一次改写可能改坏

论文指出，学习者生成的修改并不总是有效，有些只是“看起来像修复”的表面改动。为了降低单次改写的方差，ActionLearn 会独立采样 K 次，得到 K 组候选动作集和说明。每组都在同一批训练实例上跑一遍，算一个分数：

μk = psucc,k + pstepacc,k
Eq. 3 · psucc 是训练实例上的成功率；pstepacc 是成功执行的动作步数占总步数的比例，用来衡量动作是否可执行。两项直接相加，没有权重。原文 Eq. 3 写作 μ = psucc + pstepacc，没有下标 k；页面按 Algorithm 2 的 K 份候选样本加 k 索引。

分数最高的那组进入下一轮。K 在实验里取 4（§5.3）。这个选择标准同时看“任务有没有做完”和“动作有没有频繁执行失败”。推断 只看成功率可能选中靠反复试错蒙对的版本；把 step accuracy 加进来，会偏向动作本身更可执行的版本（依据：§4.1 对 pstepacc 的定义；论文未单独消融这一选择标准）。

这套流程不是策略梯度：没有奖励模型，也没有对 LLM 参数做更新。所谓“学习”，是在代码空间里做带执行反馈的搜索，产物是一个新的动作库和一份新的使用说明。理解这一点，才能解释后面“动作数量几乎没变、成功率却上去了”的结果。

小样本的代价：每个任务只有 3 个训练实例，任务规则和原始动作空间在训练集与测试集之间保持一致，变的是场景和目标。推断 这个设定把“记忆训练实例”排除在外：如果智能体只是背下 3 个案例，测试集上不会涨（依据：§5.3 训练实例与测试实例不相交）。反过来说，推断 3 个实例也不足以覆盖任务的所有分支；论文每个任务重复三次并报告平均，但没有报告标准差，也未说明重复的目的（§5.3）；推断 重复是为了降低单次运行的波动。

05

一条循环：造动作 → 跑训练集 → 选错误 → 改动作 → 再跑

LearnAct 没有新网络，流程是 Algorithm 1 的主循环，加上 Appendix A.1 的 Algorithm 2 里的采样与选择。

Algorithm 1 的循环体只有三步：在训练集上执行、选出错误案例、让学习者改写。真正让流程转起来的是环境反馈：失败信息既是“哪里出错”的信号，也是下一轮改写的输入。测试阶段不再更新动作，只把最终动作集 Alast 和使用说明 πA_last 带到未参与学习的实例上。

摘要里的 32% 是什么口径：论文摘要写 “by 32% in AlfWorld compared to ReAct+Reflexion”，未注明模型与口径。这里的 32% 推断 是 GPT-4 上的相对提升（依据：摘要未注明模型与口径；由 Table 3 GPT-4 列复算，(72.2 − 54.7) / 54.7 = 32.0%）；绝对差是 17.5 个百分点（72.2 − 54.7）。GPT-3.5 上这两个数是原始成功率：LearnAct 35.8%、ReAct+Reflexion 18.6%，绝对差 17.2 个百分点、相对提升 92.5%；不能把 GPT-4 的 32% 套到 GPT-3.5 上。

07

它解决不了：学习者能力、过拟合、离散环境与技能库

这些限制决定了 LearnAct 适合什么场景，以及什么时候不该用。

限制 1

学习者与被测模型都未单独消融

实验里所有 ActionCreation 与 ActionLearn 都由 GPT-4 完成，论文没有做“换成更弱学习者”的消融；A.6.2 只说这出于 “necessity for substantial model capacity”，没有给弱学习者的对照结果。被测模型换成 GPT-3.5 后，Robotic 平均只剩 23.2%——这是被测模型能力的证据，不是学习者消融。推断 框架的收益至少部分取决于被测模型能否正确调用新函数（依据：Table 2 / Table 3 的模型间差值；论文未单独验证这一机制）。

限制 2

迭代多了会过拟合

Figure 3（右）显示 2 步达到最好结果，继续增加步数会下降；作者把原因解释为对训练案例的过度优化和对任务规则的误解，并在 Figure 10 给了失败案例。训练集只有 3 个实例；推断 这会让上述过拟合风险更值得注意（依据：§5.3 每任务 3 个训练实例，§5.5 把退化归因于对训练案例过度优化；论文未做实例数对照）。

限制 3

只在离散模拟环境验证

Robotic Planning 与 AlfWorld 都是文本化、离散状态的模拟环境。真实机器人面对连续控制、传感器噪声和执行器误差；论文没有做 sim-to-real 实验。

成本没有对账。每轮至少 12 次完整执行（4 份候选 × 3 个训练实例），而论文没有报告 token、墙钟或 API 成本。与只做推理的 ReAct 相比，LearnAct 多出了训练阶段的执行与改写开销；这个开销是否值得，取决于任务重复次数和部署规模。

技能库管理没有涉及。Table 5 的动作数量只从 3.75 增到 3.83、3.44 增到 3.50，规模很小。论文没有讨论当动作达到几十、上百个之后如何索引、检索、组合和淘汰；也没有讨论不同任务学到的函数如何共享。这意味着它目前更像“每个任务现场造几个工具”，还不是一个可维护的技能库推断（依据：Table 5 的动作数量只有 3.44–3.83 个；原文未讨论大规模动作库的索引、检索、组合与淘汰）。

什么时候别用：如果动作空间由外部 API 固定、代码执行有安全风险、或者没有更强的学习者模型可用，LearnAct 的前提就不成立。如果任务只需要一次性推理、没有可重复的训练实例，闭环学习也缺少输入。反过来，在动作原语稳定、任务类型重复、允许执行代码并读取失败信息的场景里，它的方法最直接：把失败轨迹变成函数修改，再把修改后的函数留在动作库里。
