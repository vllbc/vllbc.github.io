Self-Aligned Reward：奖励“离开问题就说不出来”的答案

RLVR 只回答“最终答案对不对”，无法区分简洁正确与冗长正确；长度惩罚又常把必要步骤一起扣掉。SAR 比较同一答案在有 query 与无 query 两种条件下的困惑度，把“问题帮了多少忙”变成连续奖励。Qwen3-4B 上，SA-GRPO 把五基准平均准确率从 69.07 提到 71.41，同时把平均长度从 1030.6 降到 894.0。

Peixuan Han、Adit Krishnan、Gerald Friedland、Jiaxuan You、Chris Kong · UIUC / AWS 原文 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

二值奖励只看最后一格答案。只要答案对，143.5 token 的简洁解和 236.0 token 的冗余解在 GRPO 里拿到同样的优势值 0.5；模型没有理由少写。

SAR 把同一个答案分别放进“有 query”和“空 query”两种上下文，计算困惑度的相对下降：答案越依赖问题、越不像一段可独立背出来的通用文本，奖励越高。它不惩罚长度本身，惩罚的是“把 query 拿走后仍然成立”的内容。

在 4 个模型、5 个数学基准上，SA-GRPO 相对 GRPO 的准确率与平均长度同时改善；Qwen3-4B 是 69.07→71.41、1030.6→894.0。代价是每个答案多一次前向，更新阶段耗时几乎不变。

01

二值奖励看不出：两个都对的答案，一个啰嗦一个简洁

先建立共同认知：可验证奖励只判断最终答案是否包含 ground truth，不判断推理过程里有多少内容是必要的。

论文把 RLVR 的奖励写成 Eq. 5：答案里出现 ground truth 就得 1，否则得 0。这个信号足够训练出会做题的模型，但它对“过程质量”完全沉默。一个 143.5 token 的简洁解和一个 236.0 token 的冗余解，只要最后答案都对，奖励相同；在 GRPO 的组内归一化之后，它们的优势值也都是 0.5。模型没有任何梯度去偏好前者。

Table 2 用 200 道数学题、6 类答案把这个盲区量化了。SAR 给“正确且简洁”的答案是 1.15，给“正确但冗余”是 1.00；“部分正确但最终答案错”是 −0.01，而不是传统二值奖励的 −0.5；“完全错误或无关”是 −1.44。更反直觉的是“正确但没思考”（直接给答案、只有 5.0 token）拿 −0.04：SAR 不奖励背诵式答案，即使它又对又短。

这就是这篇论文要补的信号：正确性之外，还需要一个连续的、内容感知的“这个答案有多依赖问题”的分数。

02

长度惩罚能压 token，却把“必要步骤”和“废话”一起压掉

已有两条路线：直接惩罚长度（O1-pruner、Efficient Reasoner），或奖励低熵/高置信度；它们都拿到效率，但常常用准确率交换。

Table 1 把不同奖励设计拆成 5 个维度：是否连续、是否只用模型内部信号、是否内容感知、是否保留正确性、是否鼓励简洁。长度惩罚在“简洁”一列打勾，但在“内容感知”和“正确性”两列是叉——它不知道哪些 token 是必要推理。

两条长度基线分别是 O1-pruner 与 Efficient Reasoner。O1 的奖励是 RO1 = clip((mean[len(a1..N)] − len(ai)) / len(ai), −1, 1)：比同组平均短的答案得分高。ER 只对正确回答生效，用正确回答长度的均值与标准差做 z-score，再经 sigmoid 映射到 [−1, 1]；错误回答直接给 0（Appendix B.2, Eq. 9–10）。两者都只看长度，不看内容。

代价在 Table 3 的 Average 列很直接：四个模型上，GRPO-O1 与 GRPO-ER 的准确率都低于同模型的 GRPO。长度确实短了，但“短”不是免费的。

03

SAR 奖励的是“问题让答案从意外变得不意外”的相对幅度

核心公式只有一行：同一答案在无 query 与有 query 下的困惑度相对差，裁剪到 [−1, 1] 后与正确性奖励相加。

RSA = clip( ( ppl(a) − ppl(a|q) ) / ppl(a), −1, 1 )
Eq. 6：Self-Aligned Reward；R = RVR + αRSA。
ppl(a) = exp( −(1/|a|) Σj=1..|a| log P(aj | a1..j−1) )
ppl(a|q) = exp( −(1/|a|) Σj=1..|a| log P(aj | q, a1..j−1) )
Eq. 7：ppl(a) 是答案独立出现的困惑度；ppl(a|q) 是给定 query 后的困惑度。

可以把 RSA 读成一句话：“如果把问题拿掉，这个答案会变得多不可能？” 一条为问题量身定做的推理，很多 token 只有看到 query 才容易预测，ppl(a|q) 远低于 ppl(a)，相对下降大；一段可以独立背诵的通用文本，有没有 query 都差不多，相对下降小。由于 ppl > 0，RSA 恒小于 1；实现里再把下界裁到 −1（§3.2 脚注）。

论文还把它拆到 token 级（Eq. 8）：RSA = 1 − ppl(a|q)/ppl(a) = 1 − exp( −(1/|a|) Σ log [P(aj|q, a<j) / P(aj|a<j)] )，与前面的 1 − ppl(a|q)/ppl(a) 一致。定义 v(aj) = log P(aj|q, a<j) − log P(aj|a<j)：第一次从 question 里取信息的 token（Figure 2 的例子是 “Janet”“duck”“16”）v 高；重复已经生成过的信息（第二次说 “Janet”）v 低甚至为负。这解释了 SAR 为什么偏好短答案：答案越往后，能新引入的 query 信息越少。

1）ppl(a)=10.0，ppl(a|q)=4.0，α=0.20，答案正确：RSA=(10−4)/10=0.600；R=1+0.2×0.6=1.120。

2）ppl(a)=10.0，ppl(a|q)=13.0，α=0.20，答案错误：RSA=(10−13)/10=−0.300；R=0+0.2×(−0.3)=−0.060。

滑块范围 ppl∈[1,50]、α∈[0,0.5]；RSA 先裁到 [−1,1] 再乘 α，因此答案错误时，若 ppl(a|q) 远大于 ppl(a)，总奖励只会到 −α，不会无限变小。

04

只多一次前向：更新阶段 15.13 → 15.20 GPU 小时

SAR 的工程卖点是“便宜”：ppl(a|q) 在 GRPO 里已经被 KL 项和重要性采样算过，真正新增的只有 ppl(a) 的一次前向。

论文在 Appendix B.1 给了具体做法：先把 query 换成空问题（仍保留 system prompt），把答案 token 拼回去并修正 position ids，让答案位置连续；然后用当前 policy 对这条“无 query 序列”算一次 log-probs，得到 ppl(a)。ppl(a|q) 则直接复用 rollout 时已有的 log-probs。也就是说，SAR 的额外成本是一次前向，不是两次。

Table 7 报告 Qwen3-4B 前 200 步的 GPU hours（训练时间 × GPU 数）：SA-GRPO 的总耗时是 46.64，GRPO 是 48.08，反而少 1.44；Update 阶段从 15.13 到 15.20，只多 0.07；Rollout 阶段从 32.95 降到 31.44，少 1.51。论文的解释是答案变短后 rollout 本身更快，抵消了额外前向。

05

一个答案，两条前向，先算相对下降再裁剪

把公式放回训练循环：采样 → 复用 ppl(a|q) → 空 query 前向算 ppl(a) → 合成奖励 → GRPO 更新。

Step 1

采样与正确性

每个 query 采样 N=8 条 rollout（Table 9）。先用规则 verifier 判断最终答案是否包含 ground truth，得到 RVR ∈ {0,1}。

Step 2

复用 ppl(a|q)

GRPO 本来就要算每条 rollout 的 log-probs（KL 惩罚与重要性采样），ppl(a|q) 直接由这些 log-probs 归约得到，不额外跑模型。

Step 3

空 query 前向

把输入改成 System:{sys_prompt}\nUser:\nAssistant:，保留 system prompt，拼回答案 token，修正 position ids；再算一次 log-probs，得到 ppl(a)（Appendix B.1）。

Step 4

合成奖励与更新

每个答案算 RSA，总奖励 R = RVR + αRSA；GRPO 做组内归一化得到 advantage，PPO 走 critic/value。SA-GRPO 默认 α=0.2。

这个顺序也解释了为什么 SAR 不会改变原有 RL 算法的骨架：它只是把每个 rollout 的标量奖励从 RVR 换成 RVR + αRSA，后面的 ratio、clip、KL 与 advantage 计算都不动。

07

它在数学与逻辑上成立，但还不是通用奖励

SAR 的边界由三件事决定：不能脱离 verifiable reward、只在文本推理上验证、以及“简洁相关”未必是创意任务的目标。

不能单独用

RSA 单独训练会塌成短而错的答案

Table 5 的 R_SA only 只有平均准确率 20.96、长度 84.4。没有 ground truth 信号，模型可以靠极短、极依赖 query 的答案拿高分，但答案不对。SAR 的定位是 RVR 的补充项。

绝对置信度不够

Entropy 奖励既降准确率也降效率

REM 的平均准确率 55.46、长度 1228.8；RVR + αREM 也只有 69.85 / 936.4。论文的对照说明：SAR 的有效性来自“条件于 query 的相对下降”，不是“越低熵越好”。

评测范围也有限。训练集是 GSM8k、MATH、NuminaMath 的 train split；GSM-symbolic 与 AIME 只在评测出现（§5.1、Table 8）。逻辑域只测 LogicBench 与 ProntoQA。创意写作、开放式对话、需要发散思维的任务都不在评测里；“简洁 + 与 query 强相关”在这些任务上是否仍是好目标，论文没有回答。

多模态迁移并不稳。Table 10 中 Qwen2-2B-VL 上 SA-GRPO 平均准确率 23.86，低于 GRPO 的 24.80；Gemma3-4B 上 SA-GRPO 60.47，GRPO 60.83。论文 §E.2 正文却写 Gemma3-4B 的 SA-GRPO 平均准确率是 72.64%，并说比最好的 GRPO 变体高 1 个百分点以上；这与 Table 10 的 60.47 / 60.83 并列，页面不替原文消解。

最后是 α。SA-GRPO 默认 α=0.2，GRPO-O1/ER 默认 α=0.05（Appendix B.3）；Figure 3 扫了不同 α 的准确率-长度曲线，但没有给出跨模型、跨任务选择 α 的规则。实际部署时这仍是一个需要验证的超参数。

笔记勘误（只改页面，不动笔记）：

  • 笔记写 SAR「仅需模型本身进行两次前向传播（一次带问题，一次不带）」。论文 §6.3 与 Appendix B.1 的实际做法是：两次前向中有一次复用 GRPO 已有 log-probs——ppl(a|q) 在 GRPO 中已由 KL 项/重要性采样的 log-probs 得到，SAR 只额外算 ppl(a)，即一次额外前向；构造空 query 序列时仍保留 system prompt。
  • 笔记写「GRPO-ER 准确率 67.38、长度 579.0」与「SA-GRPO 准确率 71.41、长度 894.0」。两组数都是 Qwen3-4B 的 Average 列，数值正确；笔记第 89 行已注明「以 Qwen3-4B 模型为例」，90–92 行同一 blockquote 全部是 Qwen3-4B，两组数确实同模型。
  • 笔记说 SA-GRPO「在几乎所有模型和数据集的组合上都取得了最佳或接近最佳」。Table 3 至少有 7 个单元格不是该列最高：Qwen3-1.7B 的 GSM-sym 67.66（SA-PPO 68.02）与 AIME 13.50（GRPO 13.93）、Phi-3.5-mini 的 GSM-sym 72.72（GRPO 73.76）、NuminaMath 16.08（SA-PPO 17.43）与 AIME 3.22（PPO 3.85）、Gemma3-1B 的 GSM-sym 34.52（GRPO 34.70）与 AIME 2.14（GRPO-O1 2.35）。「接近最佳」仍成立，页面按逐格数值列出。
  • 笔记说 SA-GRPO 是「唯一一个」同时提升准确率与降低长度的方法。该句位于第 89 行「以 Qwen3-4B 模型为例」的 blockquote 内（第 94 行）：Qwen3-4B 上 SA-GRPO 71.41/894.0 对比 GRPO 69.07/1030.6，确实是唯一同时提升准确率、降低长度的方法。若把「唯一」扩展到所有模型/方法，则只能限定在 GRPO 变体内部（GRPO-O1/ER 在四个模型上都降准确率）；笔记的 Qwen3-4B 语境下成立。
