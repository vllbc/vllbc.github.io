SLM 是智能体的未来：一篇只摆论据、不做实验的立场论文

智能体系统里绝大多数模型调用是重复、范围有限、非对话的子任务，却几乎都由同一类通用 LLM 端点承接。 论文给出的立场是 SLM 足够强、更适合、也更便宜，并把 SLM 定义成一个运行性条件（能装进常见消费电子设备、单用户低延迟）。 代价是：全文没有任何新实验，最接近效果的只有附录里三个开源智能体的专家估算。

Peter Belcak, Greg Heinrich, Shizhe Diao, Yonggan Fu, Xin Dong, Saurav Muralidharan, Yingyan Celine Lin, Pavlo Molchanov（NVIDIA Research；Yingyan Celine Lin 另属 Georgia Institute of Technology） arXiv 2506.02153v3 ↗
TL;DR · 30 秒抓住核心

论文的 SLM 不是「参数小于 X」这种规格描述，而是能力描述：能装进常见消费电子设备、单用户推理延迟可接受（§2.1 WD1）。按这个口径，作者称 2025 年「大部分 10B 以下的模型都可以算 SLM」。

在此基础上作者提出三个论点：V1 足够强、V2 运行上更适合、V3 必然更便宜，并用 A1–A7 七条论据支撑，逐一回应三个替代观点。这里必须强调：全部是作者主张，论据大多引自被引论文自报的数字，本文没有做实验。

工程上最实用的是第六节的 S1–S6 迁移算法：在非人机接口的模型调用点加日志，攒到 10k–100k 条样本后清洗、聚类、选型、用 LoRA/QLoRA 微调，再周期性迭代。这条路径的前提是「智能体把复杂任务拆成子任务」本身就成立。

能被当成「效果」读的只有附录 B：三个开源智能体里作者估计约 60% / 40% / 70% 的 LLM 查询可由专用 SLM 承担。这是定性评估，不是实测。推断（依据：全文没有其他替换比例或精度变化数字，附录 B 是唯一给出这类估算的地方）

01

被外包出去的是一个杂货铺，但接单的是一家大商超

论文要建立的共同认识只有一句：智能体对模型的请求大多很简单，却按最贵的通用规格买单。

论文引用行业调研说明智能体部署的体量：超过一半的大型 IT 企业在主动使用 AI 智能体，其中 21% 是「过去一年内才采用」的受访企业占比（不是提升幅度），引文 [14]（§1）。截至 2024 年末，智能体 AI 赛道已有超过 USD 2bn 的创业融资，估值 USD 5.2bn，预计到 2034 年增长到接近 USD 200bn（§1）。

这些智能体的核心部件几乎都是（非常）大的语言模型：由 LLM 提供「何时、如何调用工具」「如何控制流程」「如何拆解任务」的基础智能，智能体本身只是向集中托管在云端的 LLM API 端点发请求（§1）。这个运行模型又支撑着估算 USD 57bn 的集中算力投资，后者预期在 3–4 年内收回（§1）。

作者的核心判断

LLM 在智能体设计中的主导地位既过度、又与多数用例的功能需求不匹配

论文把缺陷拆成两条（§2.3）：重复、范围有限、非对话的子任务占多数，它们需要的是高效、可预测、便宜的模型；而把这些子任务全部交给通用 LLM，是经济上低效、大规模下环境不可持续的计算资源错配。

如果这个前提成立，问题就不再是「哪个模型更强」，而是「该为哪一种调用付哪一种规格的钱」。论文的整个立场都建立在这一步重述上，这也决定了它后面不会拿出精度-成本的实验曲线——它要争的是优先级，不是某个指标。

02

先把定义从参数规格换成运行条件，论点才有对象

已有方案在这里是「行业默认做法」，本文的「方法」则从定义开始——定义一换，可比较的东西也换了。

论文用两条工作定义划出两拨模型（§2.1）：

WD1 SLM：能装进常见消费电子设备，且服务单用户智能体请求时延迟足够低
WD2 LLM：不是 SLM 的语言模型
§2.1 工作定义 · 论文明说这一定义「对立场本质影响很小」，并补充：2025 年「大部分 10B 以下的模型」按此口径可视为 SLM

选这样定义的理由在附录 A：参数数、FLOPs 这类硬件指标会很快过时——今天「小」的规模明天可能算「大」；而「能部署在消费者设备上、就近提供低延迟服务」抓住的是训练小模型的原始动机。定义挂在使用条件上，就能随硬件进步自动漂移。

把定义放进三个论点，论文的立场陈述是（§2.2）：

论点原文表述（§2.2）负责支撑的论据
V1SLM 原则上足够强，能承担智能体应用的语言建模杂务（原文 "language modeling errands"）A1、A4（v3 原文：A4 "supports items V1 and V2"）
V2SLM 在智能体系统中运行上更适合A3、A4、A5、A6、A7
V3因体积更小，SLM 对智能体系统中绝大多数使用都必然更经济A2、A3

A1–A7 各自带 supports/aligns 标注；A8–A10 由段首领句指向 V2、A12/A13 由领句指向 V3（A11 无支撑标注）。

论文特意区分了「陈述」与「建议」（§2.2）：当自然优先级被遵循时，由 SLM 与 LLM 的差异推出的未来结果是必然后果；作者不给出时间表，也不对第三方强加义务。换句话说，作者在四、五两节里也承认反例的存在，立场并不是「已经赢了」。

03

三个论点各自最硬的一条论据

从七条论据里挑出每个论点最有分量的一条：V1 靠清单与数字，V2 靠架构的「窄接口」，V3 靠规模折价加可迁移微调。

V1 · A1：性能对齐清单。论文按「常识推理 / 工具调用与代码生成 / 指令跟随」三类能力列举了 SLM 的公开成绩，并附作者原话中的效率数字：

数据来自 §3.1 的引述文本，均为被引论文自报结果；本文没有复现。该节还提到 Toolformer（6.7B）借助 API 优于 GPT-3（175B）。

V2 · A5：接口只接受一种格式。智能体与代码之间有频繁交互——工具调用要符合参数的顺序、类型与语义，输出要被调用方的代码解析。一个应用通常只选一种约定（JSON / XML / Python 之一用于工具调用，XML / YAML / Markdown / LaTeX 之一用于输出），所以模型根本不需要兼容多种格式；而偶尔「换个格式回复」的幻觉，在多格式模型上更难根治。用一次格式决策在后训练中固化下来的 SLM，在这个语境里优于通用 LLM（§3.5）。

V3 · A2：规模折价，加上「一夜之间」可加的微调。论文引用的数字是：7B SLM 的服务成本比 70B–175B LLM 便宜 10–30 倍（延迟、能耗、FLOPs 三个口径）；LoRA / DoRA、低资源微调以及全参数微调都只需「几 GPU 小时」，新行为可以在一夜之间加上或修好，而调整大模型要按几周计（§3.2）。后一条是 A3 灵活性的来源：微调便宜，才买得起「多个专家、每个专家一份格式决策」的查表式架构。

V2 · A6 / A7：异构与日志

架构允许替换，调用现场又天然生成训练数据

A6：每次智能体代码调用模型都可以在原则上选用任意模型，所以按任务复杂度分层用模型不需要改造架构（图 1）。A7：工具调用与模型调用的接口上可以挂一个监听器，收集专门的指令数据，过滤掉失败工作流后，就能造出代替 LLM 的专家 SLM——论文把这称为智能体架构天然提供的数据通路。

替代观点怎么回应？AV1 / AV2 / AV3，点开看三段回应

AV1「LLM 通用理解永远更强」（§4.1）。论文的回应分三点：A8，通行 scaling law 推导假设同代模型架构不变，而近期研究表明不同规模用不同架构有明显收益；A9，SLM 可以针对任务 T 微调，达到所需可靠性，scaling law 研究没算这一步；A10，小模型的 test-time compute 扩展开销低，推理时间可以继续换可靠性。针对 CA2，作者认为这个论点「too arcane」不足以攻击 V2；A11 的理由是语义中枢只在输入复杂时有用，而智能体系统会主动把复杂问题拆成子任务。

AV2「集中式 LLM 靠规模经济更便宜」（§4.2）。作者承认这是一个有效观点，经济性高度取决于具体案例，并说「评审团仍在审议」。支撑 V3 的是两条趋势：A12，推理调度与推理系统模块化的进步削弱了「专家端点难做负载均衡」的质疑；A13：近期关于 AI 训练与推理经济性的分析显示，受底层技术推动，成本呈持续下降趋势（[82,4]）。

AV3「两个世界等价，但 LLM 世界已领跑」（§4.3）。作者承认这是另一种可能，但坚持 A1–A7 的优势「有可能」推翻现状。

04

论证与证据都是引用式的：没有新实验，只有引用和自己估的数

本文没有「怎么训练」，第四节要看清的是它的证据结构：每个数字从哪来、作者为它加了什么限定。

论文把 SLM 的性能证据直接挂在被引论文上（§3.1 开头：逐项引用各项工作的对比，并「在作者给出时」附上效率提升），把经济性证据挂在行业分析与成本观察上（§3.2）。本文自身产生的量只有三类：经验界（10B，原文明确是作者的主观判断）、工程经验区间（10k–100k 样本）、附录 B 的替换比例估算。阅读时值得区分这三类证据的强弱：第一类是引文事实，第二类是经验法则，第三类是基于专家判断的定性评估。

论文对自身主张的限定也写得相当克制，下面几处容易在转述时丢失：

  • 置信度不对齐。AV1 的回应是作者「believe（相信）」；AV2 是明确承认「jury is still out（评审团仍在审议）」；AV3 只是「maintain（坚持）」立场。三个替代观点里，最常被引用的那条（LLM 通用理解更强）回应最依赖局部经验与未量化论证。
  • 10–30× 是引文区间。§3.2 原句是 "Serving a 7bn SLM is 10–30× cheaper (in latency, energy consumption, and FLOPs) than a 70–175bn LLM"，带引文 [70, 68, 36, 53]；论文没有自己测，这个引文区间恰好与规模比（70 ÷ 7 = 10，175 ÷ 7 = 25）同量级。推断（依据：引文倍数与参数比同量级）——它更像量级引用，不是一个实测的端到端成本乘数。
  • 数据量是「经验法则」。10k–100k 样本「足以微调小模型」在 §6 S2 里被表述为 rule of thumb，并引用了两篇微调数据效率相关工作。
  • 算力底座同样依赖假设。USD 57bn 的集中推理基础设施投资与 3–4 年回本都来自行业报告，作者的身份（NVIDIA Research）与这一立场的利害关系没有任何讨论（§5 只列了行业层面的障碍）。

还有一个结构上的特点：论文没有给出任何「换成 SLM 后精度掉多少」的数据。所有精度数字都是被引工作的自报值，而替换是否成立恰恰取决于替换后是否掉精度——这要到附录 B 的估算才有触碰，且仍然是估计。

手算对账：排序会改变什么？两组参数 → 结果，总体标准差 ÷3

下面的柱状图只改变展示顺序，不改数值；读数里的统计量取自附录 B 三个估值。标准差统一用总体标准差（÷3），样本标准差（÷2）仅作对照。

参数组 A：原序 [60, 40, 70]。

  • 均值 = (60 + 40 + 70) ÷ 3 = 170 ÷ 3 = 56.666…
  • 离差平方和 = (60 − 56.666…)² + (40 − 56.666…)² + (70 − 56.666…)² = 11.111… + 277.777… + 177.777… = 466.666…
  • 总体方差 = 466.666… ÷ 3 = 155.555…；总体标准差 = 12.4722
  • 样本标准差（÷2）= √(466.666… ÷ 2) = √233.333… = 15.2753

参数组 B：升序 [40, 60, 70]。

  • 均值 = 170 ÷ 3 = 56.666…（不变）
  • 离差平方和 = (40 − 56.666…)² + (60 − 56.666…)² + (70 − 56.666…)² = 277.777… + 11.111… + 177.777… = 466.666…
  • 总体标准差 = 12.4722；样本标准差 = 15.2753
  • 排序后相邻差值：60 − 40 = 20，70 − 60 = 10，最大间距 20

两组读数在页面上都显示为 均值 56.67 · 总体标准差 12.47（保留两位），与上面手算逐位一致；可见「升序」只改变观感，不改变统计量。

07

它证明了该往哪花钱，没有证明换过去不掉精度

边界分三类：论文自己承认的、论文结构性缺失的、以及读者需要自己补的。

作者承认

三个替代观点没有被驳倒

AV2（集中化规模经济）被论文明确称为「still a valid view」，经济性「高度取决于具体案例」；AV3（LLM 世界领跑）被承认为「另一种可能」。V3 在这里是有条件的信念，不是已证结论。

结构性

没有替换后的精度数据

所有精度证据都是被引工作的自报值，没有一个是在同一智能体上把 LLM 换成 SLM 前后的对照。附录 B 的比例是估算，衡量的是「适合」，不是「不掉分」。

读者自补

路由与运维成本没有被计入

论文在 S6 才引用「路由模型」，前文未评估路由误差与维护开销。推断（依据：§3.6 与 §4.2 未讨论路由；CA4 提出的基础设施与人才成本被作者列为「趋势在下滑」，非实证）这正是「多专家组合」最容易反转胜负的地方。

论文自己列的采纳障碍（§5）值得单独读：B1 对集中式 LLM 推理基础设施的大额前期投资；B2 SLM 的设计、训练与评估仍在追随 LLM 的通用基准（作者引 Hymba 论文指出，若只看衡量智能体效用的基准，所研究的 SLM 容易超过更大的模型）；B3 缺乏公众认知。作者主张这三条都是实践性障碍而非技术缺陷；对 B1/B2 给了趋势性论据，对 B3 未给量化支持（§5 未附时间表）。

更实际的判断标准是看瓶颈在哪里：智能体的多数调用是重复、带固定格式、结果可校验时，SLM 替换的收益最确定；如果关键路径上的调用依赖长上下文或开放式推理，或者路由本身的出错代价高于成本节省，那么论文的论据（尤其是 A5 依赖「单格式」前提、A11 依赖「语义中枢的作用只在输入复杂时显现」这一前提）就不再成立。这篇论文能帮你写出一份内部论证的骨架，但不能替你补上那份「替换前后精度差多少」的测量。
