Memento：不微调 LLM，让 Agent 靠案例库持续学习

静态工作流部署后就停止学习；微调 LLM 又要付出算力、数据与灾难性遗忘的代价。 Memento 把「学习」从模型参数挪到外部案例库：成功与失败轨迹都写成 (state, action, reward)， 规划时检索相似或高价值的案例，只在线训练一个轻量 Q 函数。代价是推理链路更长、案例库会饱和。

Huichi Zhou 等 · UCL / Huawei Noah's Ark Lab arXiv 2508.16153v2（以 v2 为准）↗ 代码 ↗
TL;DR · 30 秒抓住核心

论文要回答的是：Agent 能不能在部署后继续变强，但不更新底层 LLM？它的答案是 M-MDP： 把案例库 M 作为状态的一部分，策略同时依赖当前状态 s 和记忆 M； 写操作追加 (s,a,r)，读操作决定参考哪条旧经验。

两种读法对应两种记忆。非参数化 CBR 按 SimCSE 语义相似度做 TopK； 参数化 CBR 用 Q(s,c;θ) 预测「这条案例对当前任务有多有用」，再做 TopK。 Q 是两层 MLP，用二分类交叉熵在线更新，LLM 始终冻结。

在 DeepResearcher 的七个 QA 数据集上，Memento 平均 F1 66.6 / PM 80.4， CoT+RAG 是 37.7 / 43.2：F1 绝对高 28.9 个百分点（66.6 − 37.7）， 相对提升 76.7%（28.9 / 37.7）。但 §5.5.3 说案例库约 3k 数据就饱和， Table 4 的后续迭代收益递减；推理侧 token 成本也随任务难度上升。

01

部署之后，Agent 的学习就停住了

先分清两种「不会学」：工作流不会更新，微调更新的是模型而不是经验。

很多 Agent 的能力来自固定的提示、工具编排和反射流程。它们在窄任务上可用，但部署后是静态的： 既不会把新环境的信息写回系统，也不会从失败轨迹里改进行为。论文把这类方法归为 「fixed workflows and hard-coded reasoning」（§1）。

另一条路是更新 LLM 本身：SFT 或 RL。它更灵活，但需要大量算力、数据和长程 rollout； 论文还点名灾难性遗忘的风险（§2.1）。对需要持续上线的 Agent 来说，每次环境变化都重训一遍并不现实。

RAG 也不是答案。RAG 检索的是静态文档语料，缺少「从自己的成功/失败中持续适应」的机制（§2.1）。 Memento 要检索的是 Agent 自己的经历：一条案例是 (s,a,r)，s 是任务/状态， a 是计划，r 是成功或失败。

论文的中心问题

能不能只学经验，不动权重？

“How can we build LLM agents that learn continuously from a changing environment without the prohibitive cost of fine-tuning the underlying LLMs?”（§1）

论文的回答不是「更好的 prompt」，而是把记忆做成决策过程的一部分。

一个具体的场景是 deep research：任务需要多步搜索、爬取、读文件和写代码，单步答案对不对很难提前判断。 如果每次失败都只留在上下文里，下一次还要重新踩坑；案例库把失败也存下来，下一次规划可以直接避开。

02

三条路：工作流不学、微调太贵、RAG 只读静态文档

论文的定位不是「又一个 Agent 框架」，而是换掉学习发生的位置。

路线 A

固定工作流 / 反射提示

ReAct、Reflexion 一类方法靠预定义启发式改进行为；它们能在单次任务内反思，但没有真正的持续学习。

论文的措辞是 “pre-defined heuristics and do not achieve true lifelong learning”（§2.3）。

路线 B

参数微调 / Agentic RL

SFT、RL、GRPO 一类方法更新 LLM 参数；任务保真度高，但计算、数据、灾难性遗忘的代价高（§2.1）。

长程任务还要大量 rollout 和人工标注问题。

路线 C

RAG / 静态知识库

RAG 从静态文档里取事实；CBR 从动态经验库里取「过程」。

论文把两者在 §2.1 明确区分：RAG “query static document corpora and lack mechanisms for continual adaptation”。

Memento 走的是另一条路（不是 RAG）：LLM 冻结，学习发生在外部记忆的写入与读取上。 它借的是 Case-Based Reasoning：从旧案例检索、复用、修正、保留，再把这次的结果写回库（§3）。

03

把「学什么」变成「读哪条案例」

M-MDP 定义问题，两种 Read 定义方法；真正的区别是「相似」还是「有用」。

M-MDP 在标准 MDP 上加了一个记忆空间 M = (S × A × R)*。时刻 t 的案例库是 Mt = {ci}，每条 ci = (si, ai, ri)。 执行一步后，新案例被追加：Mt+1 = Mt ∪ {(st, at, rt)}（Eq.12）。

π(a | s, M) = Σc∈M μ(c | s, M) · pLLM(a | s, c)
Eq.1 · 整体策略 = 检索策略 μ 对 LLM 动作似然的加权和；LLM 本身不更新

检索策略 μ 是唯一要学的东西。论文用最大熵 RL 推出最优检索策略是 Q 值的 softmax（Eq.7）：

μ*(c | s, M) = exp(Q*(s, M, c) / α) / Σc'∈M exp(Q*(s, M, c') / α)
Eq.7 · α 是熵温度；α→0 退化为贪心选 Q 最高的案例

但直接学 Q 很难，因为状态和案例都是自然语言。论文给了两条实现路径：

Non-Parametric

按「像不像」读

Read 直接用冻结编码器的余弦相似度做 TopK（Eq.13）。它假设「相似的问题有相似的解」，不学任何检索参数。

ReadNP(st, Mt) = TopKci∈Mt sim(enc(st), enc(si))

编码器用 SimCSE，相似度是余弦（§5.3）。

Parametric

按「有没有用」读

Read 用 Q(s,c;θ) 做 TopK（Eq.16）。Q 预测「在当前状态下参考案例 c，最终成功的概率」，因此可以选出表面不像、但结构上有用的案例。

ReadP(st, Mt) = TopKci∈Mt Q(st, ci; θ)

Q 是两层 MLP，用 SimCSE 初始化句子表示（§5.3）。

在 deep research 实现里，CBR 只用于规划，所以整个 M-MDP 被简化成单步：TD 目标坍缩为即时奖励， Q 直接用二分类交叉熵训练（Eq.15）。这是论文明确说的简化，不是页面替它补的（§4.2）。

L(θ) = E(s,c,r)[ −r log Q(s,c;θ) − (1−r) log(1−Q(s,c;θ)) ]
Eq.15 · r∈{0,1}；Q 被当作「案例 c 对状态 s 有用」的概率

注意：Eq.7 的 softmax 是理论上的最优检索分布；实际 Read 用 TopK 取 Q 最高的 K 条，以减少随机性（§4.2）。

04

训练只发生在一个两层 MLP 上

LLM 冻结；要学的只有 Q(s,c;θ)，而且每条轨迹只写最后一步。

实现细节在 §5.3：非参数化 CBR 用 SimCSE 编码句子、余弦相似度排序；参数化 CBR 也用 SimCSE 初始化句子表示， Q 函数是一个两层 MLP。整个训练过程不更新 GPT-4.1 / o3 / o4-mini 的参数。

案例写入不是把整条轨迹塞进库。论文只保留每条轨迹最后一步的 (s,a,r)， 避免状态里继承的前文造成冗余（§5.3）。这让案例库保持紧凑，但也意味着中间步骤的过程信息不会单独成为案例推断（依据：§5.3 只写 final step 的 (s,a,r) 入库）。

参数化 CBR 的 Write 同时做两件事：追加案例，和用 Eq.15 更新 Q。因为 deep research 的奖励是二元的 r∈{0,1}，论文把 MSE 换成交叉熵，理由是 MSE 在 0/1 附近梯度会消失（§4.2）。

实现边界

Algorithm 1 是多步版，落地走单步版

Algorithm 1 给的是完整 M-MDP 版本：TD 目标、目标网络、kernel-based episodic control。 实际 deep research 实现走的是单步简化版：CBR 只在规划时用，TD 目标坍缩为即时奖励，kernel 估计被去掉（§4.2）；单步设定下目标网络也不需要推断（依据：没有 bootstrap，TD 目标不含下一状态 Q）。

页面按 §4.2 的单步实现讲；Algorithm 1 的多步分支未被这个实现覆盖。

成本账要分开看。训练侧只更新两层 MLP 和写案例库，没有 LLM 梯度；推理侧每个规划步都要检索， planner-executor 交替调用工具，token 消耗随难度上升（Figure 6）。论文报告的是 token 成本，不是 wall-clock 时延。

05

Planner 读案例，Executor 调工具

Figure 3 的主循环：规划阶段查 Case Memory，执行阶段查 Tool Memory，完成后写回案例。

Memento 是 planner-executor 架构。Planner（GPT-4.1）负责把任务拆成子任务； Executor（GAIA 用 o3，其他数据集用 o4-mini）通过 MCP 协议调用搜索、爬取、代码、文件处理等工具。 两者交替，直到 planner 判断任务完成。

三类记忆分工不同：Case Memory 存向量化的 (s,a,r)，供规划检索； Subtask Memory 存当前子任务与执行结果；Tool Memory 存每个子任务的工具调用日志。 只有 Case Memory 是跨任务持续增长的。

一个容易忽略的点：planner 的「规划」不是一次性输出完整计划，而是每轮根据 Subtask Memory 里的执行结果重新评估； 任务完成后才写案例（§4.1）。所以案例库记录的是完整任务的最终状态-计划-奖励，而不是每个子任务的中间步骤。

反直觉

慢思考 planner 反而更差

Table 6 的 GAIA validation pass@1：GPT-4.1 planner + o3 executor 70.91，o3 planner + o3 executor 63.03， 差 7.88 个百分点（70.91 − 63.03）。这里只转录这两行；原表还有 Qwen3-32B 等配置（如 53.94 / 40.61），未转录。

论文的解释是 o3 planner 有时直接答题、跳过规划，或生成过长的计划，反而误导 executor（§6.3）。 在模块化系统里，简洁、结构化的规划比「想得更久」更重要。

07

它省的是梯度，不是推理

案例库会饱和、工具会引入噪声、不同基准的条件不能混着比。

第一，记忆规模。论文自己说 Case Bank 在约 3k 训练数据后很快饱和（§5.5.3）； Table 4 的五轮曲线也在 Iter 3 后趋缓（§5.5.3 称 rapid convergence）。论文的实验规模停留在约 3k 训练数据，百万级案例下的检索效率不在本文实验范围内。

第二，推理成本。Figure 6 的 token 统计：GAIA Level 1 平均 26k 输入 / 4.7k 输出，Level 2 48k / 6.9k， Level 3 121k / 9.8k。论文的结论是主要负担来自整合多步工具输出，而不是生成长回答（§6.2）。 但论文报告的是 token 成本，不是端到端时延；检索、planner-executor 交替和工具调用的 wall-clock 开销不在 Figure 6 的范围内。

第三，奖励假设。实现里 reward 是二元的 r∈{0,1}，CBR 只用于规划，所以 M-MDP 被简化成单步（§4.2）。 论文的实验都建立在二元奖励上；概率化 reward 与 memory update 被列为 future work（§3）。

第四，工具不是越多越好。DeepResearcher 的 Offline→Online 反而掉了 18.0 F1 个百分点（Table 5c）， 论文归因于数据污染。这条对「多接工具总没坏处」的直觉是一个反例。

第五，条件不能混。GAIA 的 87.88 是 validation 的 Memento 行、标了 Pass@3，同表其余行未标 Pass@3； Table 6 的 fast/slow 对比是 pass@1；DeepResearcher / SimpleQA / HLE 用 o4-mini；Table 4 的表注未标注指标定义。 把 87.88、70.91、66.6 放在一起比较会混淆口径。

最后，GAIA Level 3 仍是短板：validation 上 Memento 61.54，Alita 76.92；test 上 Memento 71.43。 总体排名靠前，不代表长程任务已经解决。

什么时候别用

先确认你的场景满足这些前提

  • 如果任务分布固定、案例极少，且可以接受离线批处理，固定工作流或一次性 RAG 更简单。
  • 如果奖励不是二元、或者你需要严格的端到端低延迟，先别把 Memento 当成即插即用方案。
  • 如果你需要模型内化的新能力（而不是检索经验），参数微调仍是另一条路。
