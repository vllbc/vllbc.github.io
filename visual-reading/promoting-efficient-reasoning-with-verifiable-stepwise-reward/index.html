VSRM：把「这一步有没有用」变成一次可验证的采样

RLVR 只用最终答案的对错发奖励，模型于是用更长的推理链换正确率。VSRM 把推理链按特殊词切成子轨迹，让每个中间状态各自答五次，用平均正确率的相邻差当步骤奖励；差太小就向未来看几步，按 γ 折扣把收益传回来。代价是训练时要为每条主轨迹额外采样大量答案。

Chuhuai Yue 等 · 数学推理 · 2025 arXiv 2508.10293v2 ↗
TL;DR · 30 秒抓住核心

RLVR 的二元结果奖励只看最后答案，模型学会了「宁可多写，不可写错」。论文把过度思考定位在推理链中段：大量步骤既不提高正确率，也不帮助模型走到正确答案。

VSRM 不训练 PRM。它用 however / thus / so / but / wait 等特殊词把主轨迹切成子轨迹，每个子轨迹补一个 </think> 后让模型再答 N=5 次，用平均正确率 Ai 代表这个中间状态的价值。

单步奖励取相邻 Ai 的差；差的绝对值 |d| 小于 ε 就向未来看最多 Lmax=4 步，用 γ=0.7 的折扣把未来收益传回来。最终得到一条与 response 等长的奖励向量，直接接 PPO / Reinforce++。

01

过度思考不是「写太长」，而是中段大量步骤不改变正确率

读完这节应知道：论文把 overthinking 定位在推理链中段的无效步骤，而不是单纯的长度。

RLVR 的常见做法是只看最终答案：答对给 1，答错给 0。论文认为这会塑造一种偏好——宁可多写，也不要写错。

“the binary reward function used in R1 encourages the model to over-generate content in the pursuit of correctness, fostering a preference for being overly redundant rather than potentially wrong.”§1 Introduction

论文在 MATH-500 上让 DeepScaleR 和 DS-Distill-1.5B 各生成 500 条回答，随机抽 10% 人工标注，论文发现推理过程可分为三个阶段：问题重述、逐步解答、答案总结。过度思考主要发生在「逐步解答」阶段。

“the reasoning process of LRMs can generally be divided into three stages: problem restatement, step-by-step answering, and answer summary. The overthinking issue mainly occurs during the step-by-step answering stage.”§3 Rethink the Essence

为了把个案变成统计，论文让 DeepSeek-R1 检测全部 500 条回答里的无效步骤，并与人工标注对照。R1 不能精确标出所有无效步骤，但被认为能识别过度思考现象，因此这些数字是粗粒度统计。

两个模型都在超过一半的样本里出现明显无效步骤。论文由此把优化目标定为：鼓励提高正确率的中间步骤，惩罚不改变正确率的步骤。

关键区分

惩罚「无效」，不是惩罚「长」

论文的论点是：长度惩罚可能连带压掉必要的长步骤。VSRM 的奖励直接看「这一步之后，模型答对的估计概率有没有变」，因此长步骤只要有用就可以保留。

02

两条主流路线都要先猜长度，PRM 又要先训一个不稳定的裁判

前人不是没想到过程监督，而是过程监督要么依赖预估，要么依赖一个难训的奖励模型。

路线 A

预设 token budget

给任务设输出长度约束，模型在固定预算内作答。论文的论点是：预算要事先猜，猜错就会在简单题上分配过多计算，面对动态场景也缺乏灵活性。

路线 B

difficulty-adaptive reasoning

先判断题目难度，再分配推理模式或预算。看起来更合理，但论文指出它仍是隐式的 token budgeting，同样依赖对任务的预评估。

论文把这两类方法共同的问题总结为：需要预评估任务来确定输出目标，既依赖预估准确率，也缺乏对动态场景的灵活性。

过程监督

PRM：给每个阶段打分

PRM 把推理链分解成阶段并逐步打分，在数学推理上有成功案例（Lightman et al. 2023）。但论文引用 DeepSeek-R1 的经验：PRM 难训练，可靠性无法保证。于是作者绕开 PRM，改用规则切分加子轨迹采样验证。

此外，还有一类做法是在奖励里加长度惩罚。Table 3 的对照显示，显式长度惩罚并没有带来更强的压缩：DS-Distill-1.5B 的 AIME24 长度是 7533，而 VSRM-PPO 是 7065；MATH-500 是 2615 对 2400。论文的推测是，复杂的结果奖励会干扰过程级奖励。

03

把「这一步值不值」变成一次可验证的采样

VSRM 用规则切分和子轨迹采样，把「这一步值不值」变成一个可计算的准确率差，再用折扣传播把稀疏信号变密；整条链路不需要额外的奖励模型。

第一步：用特殊词把主轨迹切成子轨迹

先从 response 中用正则取出 <think>…</think> 里的推理正文。跳过开头一段（Cmin=200）避免把问题重述切碎；然后用预定义的特殊词表匹配切点，例如 “however”“thus”“so”“but”“wait”。为了让每一步语义完整，论文加了两条规则：相邻切点至少间隔 Imin=100 个 token；切点对齐到包含该特殊词的完整句子的句首。

切分结果是切点集合 P={p1,…,pK}。Appendix D 的 Algorithm 1 给出了完整伪代码。

第二步：每个子轨迹各自答 N 次

对每个切点 pi，把「问题 + 从开头到 pi 的推理前缀」拼成新 prompt，末尾补一个 </think>，让当前策略生成 N=5 条候选答案（每条最多 768 token）。这个子轨迹的平均正确率就是 Ai：

Ai = (1/N) · Σj=1N I[ IsCorrect( LRM(Ti)j ) ]
Eq. 1 · N=5；I 是指示函数，答对为 1、答错为 0。原文 Eq.1 求和下标印作 j=i；按正文 N 条候选答案，页面按 j=1 呈现。

论文把 Ai 称为中间状态价值的 proxy：它不直接判断「这段推理写得好不好」，而是看「从这段推理出发，模型能不能答对」。

第三步：奖励取相邻两步的准确率差

如果直接把 Ai 当奖励，所有位置都非负，无法惩罚无效步骤。论文改用相邻差：

di−1 = Ai − Ai−1
Eq. 2 · 边界情况 rk 用 AT − Ak，AT 是完整主轨迹的平均准确率

一个步骤提高正确率就得到正奖励，不改变就得到 0，降低就得到负奖励。问题在于：真实推理里，正确率往往连续多步不变，相邻差大多是 0，奖励非常稀疏。

第四步：向未来看几步，按 γ 折扣传回来

当 |di−1| < ε 时，论文在最多 Lmax=4 步的窗口内找第一个超过阈值的变化 |di+q−1| ≥ ε。找到就把未来收益按 γq 贴现给当前步骤：

ri−1 = sgn(di+q−1) · |di+q−1| · γq
Eq. 3 · γ=0.7，Lmax=4，ε=10−5；窗口内找不到超过阈值的变化则 ri−1=0

如果一路看到序列末尾都没有超过阈值的变化，论文用 Eq. 4 把最终准确率与当前准确率的差按剩余步数贴现：

ri−1 = sgn(dk) · |dk| · γk−i+1
Eq. 4 · 序列末尾没有超过阈值的变化时的处理

这就是「衰减传播」：它把稀疏的 0 变成有方向、有折扣的密集信号。

第五步：和结果奖励拼成一条与 token 对齐的向量

最终奖励不是单个标量，而是一条与 response token 数等长的向量：各切点位置放步进奖励，最后一个位置额外加结果奖励 rresult 和格式奖励 rformat，其余位置为 0。

RT = [ …, r1, …, rt, …, rk, …, rTresult + rTformat ]
Eq. 5 · 向量长度与总 response 长度一致，直接交给 PPO / Reinforce++ 做 advantage 估计

04

奖励向量能接 PPO，但采样开销是真的

工程上它不需要改 RL 算法，只需要能接收逐 token 奖励；代价在 rollout 阶段。

实现基于 VeRL。VSRM 输出的奖励向量长度与 response 一致，因此可以直接接支持 stepwise reward 的 PPO 和 Reinforce++，不需要额外的奖励模型。下文的 VSRM-R++ 指 VSRM 接 Reinforce++。

训练数据来自 DeepScaleR 数据集：1984–2023 年历史 AIME、2023 年前的 AMC、Omni-MATH 与 Still。

为什么能直接接

奖励不是标量，而是逐 token 的向量

论文称 VSRM 与支持 stepwise reward 的 PPO / Reinforce++ 兼容；逐 token 奖励向量可直接进入这些实现的 advantage 估计。标准 PPO 也可用标量结果奖励，页面不声称 PPO 本身必然要求逐 token 奖励。

代价也在这里：每个训练样本要额外跑 10–20 次子轨迹生成，每次 5 条答案。论文报告 8×A100 上每个训练步约 20 分钟，并说明 “as training progresses, the time required for each step gradually decreases”。

05

奖励落在切点，末位才加结果与格式分

流程分两段：先把轨迹切碎并采样出 A_i，再把 A_i 的差传播成奖励向量。

上半段是「测量」：切分、子轨迹采样、平均正确率。下半段是「记账」：相邻差、折扣传播、拼奖励向量。两段之间没有额外的奖励模型，步进奖励的裁判是答案正确性。

切分规则

规则化，可解释

特殊词表、C_min、I_min、句首对齐都是显式规则；不需要另一个模型来识别步骤边界。

奖励位置

与 token 对齐

步进奖励落在切点对应的 token 位置，结果与格式奖励只落在末位；其他位置为 0。

数学域外，VSRM 仍依赖一个可判定的答案

VSRM 的奖励建立在「答案可以被判定对错」上；这既是它的可验证性，也是它的边界。

边界一

实验范围只有数学

Table 2 的实验覆盖六个数学基准：MATH-500、AIME24、AIME25、AMC23、Minerva、OlympiadBench。摘要与引言说的是 mathematical reasoning；本页所读版本没有代码、法律、创意写作等答案不易自动判定任务的实验。

边界二

切分依赖特殊词表

正文只给出 however / thus / so / but / wait 等示例；Appendix D 的 Algorithm 1 把特殊词匹配模式 H_p 作为输入，本页所读 v2 没有展开完整词表，也没有给出词表选取依据或跨语言消融。模型表达风格变化时，切分点会跟着变 推断（依据：切分完全由特殊词表与句首对齐规则决定）。

边界三

训练开销与部分基准上的准确率下降

每条主轨迹 10–20 个子轨迹、每个子轨迹 5 条答案，合计 50–100 条候选答案；8×A100 上每步约 20 分钟，论文说明 “as training progresses, the time required for each step gradually decreases”。按 1.5B → 7B → DeepScaleR 的顺序，AIME24 压缩幅度依次为 44.0%、36.6%、20.8%；但这三个基座并非准确率单调变强：7B 在六个基准上的 pass@1 都高于 DeepScaleR，不能把压缩率排序当成准确率强度排序。DeepScaleR（1.5B，已 RL）的 AIME24 pass@1 从 40.7 降到 39.2（−1.5 个百分点；原文 Table 2 该格标 ↓1.4，按表中数值相减为 1.5，页面按算术值呈现，同一注见第 06 节）。

边界四

代理指标可能被优化

论文明确把子轨迹答案正确率称为中间状态的 proxy。推断（依据：proxy 只看子轨迹最终答案是否正确，不检查中间推理是否真实有效）：模型可能学会生成「更容易被答对」的子轨迹，而不一定是更好的推理。本页所读版本没有报告针对这一点的压力测试。

一句话：VSRM 的前提是答案可自动判定；在 Table 2 里，压缩幅度按 1.5B → 7B → DeepScaleR 的顺序缩小，DeepScaleR 的 AIME24 出现准确率下降（原文标 ↓1.4，页面按算术值呈现），但 AMC23 / Minerva 上也有上升，不能当成普遍规律。任务没有可靠判定器时，Eq. 1 的平均正确率无法计算。
