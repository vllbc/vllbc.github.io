AgentGym-RL：把「最大交互轮数」做成课程，7B 智能体从零训起

多轮 Agent 的 RL 训练有两种常见死法：轮数一开始就给大，模型陷入冗余推理和无效动作，训练崩溃；一直给小，探索变窄，性能撞天花板。 这篇论文把最大交互轮数做成单调递增的课程，并把环境、Agent、训练三块解耦成一个可并行 rollout 的框架。 代价是：规则清晰的模拟环境收益最大，开放网页和深度搜索仍落后顶级闭源模型。

TL;DR · 30 秒抓住核心

AgentGym-RL 想做的是：不用 SFT 预热，直接让 Qwen2.5-3B / 7B 在五个环境里多轮交互，用终局奖励做 RL。 五个场景分别是 WebArena、Deep Search、TextCraft、BabyAI、SciWorld。

核心不是新损失函数，而是课程：先把最大交互轮数压小，让模型学会在少量轮次内完成任务；再按 ht+1 = ht + δh 逐步放开，逼它探索更长决策路径。 论文把这套方法叫 ScalingInter-RL。

结果分两类：ScalingInter-7B 在 TextCraft 上 91.00 对 o3 的 93.00，接近；在 BabyAI 和 SciWorld 上超过 o3； WebArena 和 Deep Search 仍有明显差距。论文摘要的说法是 “match or surpass commercial models on 27 tasks”，不是全面超越。

边界同样清楚：只在域内、数字环境、单智能体验证；Chem-Mix 这类任务对论文自己的三个模型仍是 0； 论文未报告 GPU 小时数，样本效率无法判断。

01

多轮 Agent 的 RL，难在「轮数一多就学崩」

先建立共同认知：奖励只在轨迹末尾给出，轮数越多，信用分配越难，探索空间越大。

论文把 agentic task 建模成部分可观测马尔可夫决策过程（POMDP）：给定指令 u，Agent 根据当前状态 s 生成动作 a，环境返回观测 o 并转移到下一个状态；经过 N 轮交互后， 环境给出一个终局奖励 r(τ) ∈ [0,1]。中间轮次没有逐步奖励。

这把监督信号压到一条轨迹的末尾：同一个终局奖励要归因到几十个动作上，方差大；轮数越多，动作空间和观测空间越大， 稀疏奖励越难命中。论文的初步实验给出两种失败模式，正好对应两个极端。

失败模式 A

大轮数开局

一开始就给较大的最大交互轮数（例如 10），模型会进入冗余推理和无效动作的循环，最终训练崩溃、性能下降。

原文：“beginning with a large number of interaction turns often leads the model into redundant reasoning and unproductive actions, ultimately causing training collapse and degraded performance.”（§3.3）

失败模式 B

小轮数到底

一直限制在较小的最大交互轮数（例如 5），探索被压窄，模型学不到多样化的交互模式，后期遇到性能天花板。

原文：“constraining the number of interactions to remain consistently small tends to narrow exploration and limits the agent’s ability to master diverse patterns.”（§3.3）

所以问题不是「有没有 RL 算法」，而是怎样安排交互预算：让策略先学会基本技能，再逐步扩展决策路径。 这也是 Section 03 的课程方法要解决的核心矛盾。

02

已有两条路：提示闭源模型，或模仿专家轨迹

两条路都能做出 demo，但都没有让模型通过与环境交互自己变强。

路线一

Prompting / workflow

用 GPT-4o、o3 等闭源模型做规划、反思、角色分工，靠 prompt 和外部 workflow 把任务串起来。

卡点：底层模型没有被训练，能力不会随交互演化；依赖强大的闭源模型，成本高，也无法把能力沉淀到开源模型里。

路线二

SFT / 模仿专家

收集专家轨迹，逐步模仿专家的动作，学习 API 调用、规划和反思。

卡点：专家数据昂贵、难规模化；专家没覆盖的情况学不会；论文的原话是 “the model struggles to self-improve through interactions with the environment”（§6）。

RL 路线已有单轮推理的成功案例（如 DeepSeek-R1 类工作），也有少量多轮 Agent 的尝试；论文认为后者受限于任务复杂度、 环境多样性，且优化稳定性不足（§1、§6）。在 test-time scaling 一侧，Zhu et al. [96] 探索了多种 agent test-time scaling 策略， 但没有研究 RL 中的 inference scaling；论文认为最接近的工作是 TTI [55]，它用 rejection sampling 教 Agent 把更多 compute 分配给交互，局限在 web navigation（§6）。

论文指出的缺口

缺少一个统一的、端到端的多轮交互 RL 框架

要同时满足：跨多种真实环境、不依赖 SFT 预热、支持主流 RL 算法、训练稳定可复现。AgentGym-RL 想填的就是这个缺口；ScalingInter-RL 则是为了让训练在长轮数下不崩。

03

ScalingInter-RL：把「最大交互轮数」当成课程

方法的核心是一条递推式：每 Δ 步把轮数上限加 δh，直到环境允许的上限。

论文的目标仍然是最大化终局奖励：J(θ) = Eτ∼πθ[r(τ)]。 一条轨迹写成 τ = (a0, o1, a1, …, aK−1, oK)， K 是交互轮数。课程给 K 加了一个上限 ht，并要求上限单调递增：

K ≤ ht      h1 < h2 < ⋯ < hn      ht+1 = ht + δh（每 Δ 个训练步更新）
§3.3 的课程递推。论文称 δh 是 adaptive increment，但没有给出具体的自适应规则或每环境取值。

早期 h 小：Agent 只能在少量交互内完成任务，迫使它学会高效利用（exploitation），先掌握基本技能和简单任务。
后期 h 增大：允许更长的决策路径，鼓励探索、规划、反思和策略性回溯；论文把这种现象类比为 RLVR 中的 length-scaling。

论文强调这不是靠大量超参搜索：阶段切换点按原 RL 过程的总优化步数设置（§4.2）。 Figure 7 在 Deep Search 上给了三种策略的对照：固定 10 轮早期奖励更高但快速崩溃；固定 5 轮稳定但遇到天花板； ScalingInter 逐步放开，长期性能更高。

04

从零开始：五个环境、GRPO 为主、每环境一套轮数上限

论文没有用 SFT 预热；训练细节大多在 Appendix B，页面把能查到的都列出来。

主实验的 backbone 是 Qwen2.5-3B 和 Qwen2.5-7B，从零开始做 RL，不做 SFT 预热。 主要算法是 GRPO；框架同时集成 PPO、RLOO、REINFORCE++，也支持 SFT、DPO 和 rejection sampling（AgentEvol）（§3.2.2）。 所有环境共用 KL 系数 1×10⁻³、采样温度 1.0；WebArena 每个 query 采样 4 条轨迹，其余环境 8 条。

工程上做了什么

  • WebArena：把默认的“每进程一个浏览器”改成基于子进程的架构，单台服务器可并发管理多个 Chromium；另提供 full-reset 接口，每个 episode 后把网站恢复到初始状态，缓解长训练中的状态不一致（§3.2.3）。
  • SciWorld：重写环境初始化和 reset，使多个实例可以并行创建与重置（§3.2.3）。
  • TextCraft：修掉 recursive crafting_tree 里列表结构冗余复制导致的内存泄漏（§3.2.3）。
  • SciWorld：修掉内部 clock 机制在长 rollout 中的内存累积（§3.2.3）。

硬件是 NVIDIA A100 GPU 和 Ascend 910B NPU（Appendix B）；训练可跨多节点、多进程分布式执行（Appendix A）。 论文未报告总 GPU 小时数、单次训练成本或样本效率；Appendix B 只交代了硬件类型。这一点会影响“7B 模型很便宜”这类推断——页面不替论文补这个数。

05

三块解耦：环境服务器、Agent 循环、训练管线

环境通过 HTTP server–client 并行跑 rollout，训练模块消费轨迹并更新策略；课程只改 rollout 的最大轮数。

论文把“可扩展、可复现”当作框架贡献的一部分：环境/Agent/训练三块可以独立替换，新的环境只需继承 BaseEnvClient 并实现 reset()、step()、observe()（§3.2.3）。训练管线支持多节点、多进程并行，并记录 policy entropy、KL divergence、 reward curve、rollout statistics 等诊断指标（Appendix A）。

五条值得记住的发现

  • 规则清晰的环境，增益最大。TextCraft 从 42.00 到 91.00（+49.00 分）；BabyAI 从 66.67 到 96.67（+30.00 分）；SciWorld 从 1.50 到 57.00（+55.50 分）。论文的原话是 “Environmental structure is a key determinant for the efficiency of reinforcement learning.”（§4.2）
  • 开放环境，增益有限且仍落后。WebArena 从 9.76 到 26.00，仍比 o3 的 34.00 低 8.00 分；Deep Search 从 18.75 到 38.25，仍比 o3 的 49.50 低 11.25 分。论文说 WebArena 的差距“almost entirely concentrated in the GitLab & Reddit sub-task”（§4.3）；该子任务上 ScalingInter-7B 是 20.00，o3 是 80.00，差 60.00 分（Table 1）。
  • 模型规模不是唯一变量。论文报告 ScalingInter-7B 的平均成功率约 58.6%，高于 Llama-3.1-70B 的约 47% 和 Qwen2.5-72B 的约 43%（§4.2、Figure 1 右）。这三个数都是论文转述，未在表中逐项展开。
  • 轮数预算不是越大越好。Figure 7 的 Deep Search 对照里，固定 10 轮早期奖励更高但快速崩溃；固定 5 轮稳定但遇到天花板；ScalingInter 逐步放开后长期更高。论文把崩溃归因于高方差、信用分配困难和过拟合到虚假行为（Figure 7 图注）。
  • GRPO 在低信号环境里更稳。Table 6 中，3B GRPO 在 TextCraft 得 75.00，高于 7B REINFORCE++ 的 73.00（+2.00）；BabyAI 是 93.33 对 84.44（+8.89）；SearchQA 是 25.75 对 24.00（+1.75）。论文的解释是 REINFORCE++ 用整条 episode 的 Monte Carlo return，长轨迹上方差大；GRPO 用组内相对优势（§5.2）。

论文在 §1 还报告了一个汇总数字：用该框架训练的 Qwen-2.5-7B 平均提升 33.65 分。 这个数字没有在 Table 1–5 中逐项展开，页面只按原文转述，不把它当作可复算指标。

07

边界：域内有效，开放网页和科学推理仍有硬骨头

论文自己的表、案例和 future work 划出了四条边界。

边界一

开放环境仍明显落后

WebArena 26.00 对 o3 34.00，差 8.00 分；Deep Search 38.25 对 o3 49.50，差 11.25 分（Table 1、Table 2）。WebArena 的差距集中在 GitLab & Reddit：20.00 对 80.00（Table 1）。论文自己写的是“a disparity almost entirely concentrated in the ‘GitLab & Reddit’ sub-task”（§4.3）。

边界二

Chem-Mix：论文的三个模型都是 0

Table 5 的 Chem-Mix 列里，AgentGym-RL-3B、AgentGym-RL-7B、ScalingInter-7B 全是 0.00；部分基线反而非零（o3 40.00、Llama-3.1-70B 40.00、GPT-4o 20.00 等）。§4.3 的文字却说 “every model ... scoring zero”。两处并列，页面不替原文消解。对论文方法而言，这个子任务是明确失败。

边界三

只验证了域内、数字世界、单智能体

论文的 future work 原文列出三条：域内 → 新环境/新工具的泛化与迁移；数字任务 → 更长时程、物理世界任务；单智能体 → 多智能体 RL（§7）。论文还写 “Most existing studies—including ours—focus on relatively simple digital tasks.” 这套结果不能直接外推到真实机器人、自动驾驶或多 Agent 协作。

边界四

代价与行为失败没有被完全解决

Appendix B 只写使用 A100 与 Ascend 910B，未报告 GPU 小时数或总计算量；因此无法判断“小模型 + 后训练更便宜”是否成立推断（依据：Appendix B 只列硬件类型，未列训练时长/能耗）。案例研究还展示了 over-interaction（Figure 16）和过早终止（Figure 15）等失败模式；论文说 RL 过程 “failed to instill the precision and efficiency required for optimal task completion”（§5.3）。

一句话总结：这篇论文给出的是一套在规则清晰的模拟环境里可复现的多轮 RL 训练配方，而不是一个在开放世界全面超过闭源模型的 Agent。 如果目标环境像 WebArena 一样开放，论文自己的数据说明提升有限且仍落后 o3；如果目标环境规则清晰、反馈可判定，ScalingInter-RL 的课程思路可以直接借鉴。
