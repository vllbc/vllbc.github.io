CausalPlan：让因果矩阵给 LLM 的「候选动作」打分，而不是让 LLM 自己守规矩

Overcooked 里的 7B–70B 开源模型会先「把洋葱放进锅」再「拿起洋葱」，或者干脆说出一个任务里不存在的动作。 CausalPlan 不微调模型、不改它的提示，而是在候选动作的采样概率上再加一项因果分； 这一项来自一张离线学好的矩阵 M，行是动作、列是「谁的状态 / 上一步动作」。 如果一个有效候选都没有，就直接查 M 取分数最高的那个动作。

Minh Hoang Nguyen, Van Dai Do, Dung Nguyen, Thin Nguyen, Hung Le · A2I2, Deakin University arXiv 2508.13721v1 ↗
TL;DR · 30 秒抓住核心

论文观察到的失败叫 causally invalid action：违反环境的物理约束或先后顺序（没拿洋葱就放洋葱），或执行了任务指令里不存在的动作。在 Overcooked 的 Cramped Room 布局里，Gemma-7B / Qwen-14B / Llama-70B 都持续产出大量这类动作（Figure 1a，四个种子平均）。

解法分两段。离线：拿一个现成策略（论文用 MEP）跑 200,000 步轨迹，把状态与动作拆成特征位，训练一个「上一步动作 + 当前双方状态 → 下一个高层动作」的结构化因果模型（SCA），读出矩阵 M，M[i,j] 就是「特征 j 导致动作 i」的因果分。

在线：LLM 先分析场景、再给出候选动作 A′ 及其概率 p_a；CausalPlan 用当前激活特征查 M 得到 p_c，按 p_f = γ·p_a + (1−γ)·p_c 融合后 softmax 采样。候选集为空时不走重规划，而是在全部合法动作里取 argmax p_c——这是论文的 Causal Backup Action。

代价很实：推理变慢（400 步 Llama-70B 从约 40 分钟到约 68 分钟），因果矩阵的质量取决于拿谁的轨迹来学（MEP 学的图里 pickup_onion → put_onion_in_pot 是 0.6，Llama-8B 学的图里是 0），CR 布局上它甚至输给 FCP。

01

LLM 会说「放大」，但不会守「顺序」

读完这节要知道：作者把 LLM 智能体在协作任务里的失败，归结为一个可观测的量——因果无效动作的数量。

Overcooked-AI 的规则很硬：两名玩家一起做洋葱汤，拿洋葱、放进锅、等锅煮好、把汤盛进盘子、端到出餐口，每成功上菜一次得 +20（§4.1；Appx. C.2）。语言模型看懂这个场景毫无难度，但做对顺序是另一回事。

论文点名的两类错误：顺序错（先放洋葱再拿洋葱、或执行任务说明里没有的步骤）与动作越界（输出动作空间 A 之外的动作）。作者认为根源是 LLM 依赖表层相关性而非环境里真实的因果关系，小型开源模型因为没有捷径可用，问题更突出。

Figure 1a

因果无效动作随模型变大而减少，但并没有消失

02

两条老路：RL 过拟合搭档，LLM 不会推理

读完这节要知道：为什么不能直接用已有的零样本协作方法或「让 LLM 自己想一想」。

RL 路线

SP / PBT / FCP / MEP / COLE

为「和没见过的搭档也能配合」而设计的经典方法：自博弈（SP）、种群训练（PBT）、配上虚拟搭档的 FCP / 最大熵种群的 MEP、以及做策略选择的 COLE（§2）。

卡在：容易过拟合训练搭档的行为分布，算得贵，学到的是黑箱策略，不利用任务本身的领域知识。论文用它们当基线与数据来源。

LLM 路线

ProAgent 一类提示式协作

论文的实验底座是 ProAgent：用知识库提示 LLM 分析局面并规划下一步，比 RL 更能零样本迁移，也能讲清理由。

卡在：论文的判断是 LLM 本身缺因果推理能力——原话是「a persistent limitation remains: LLM agents often lack robust causal reasoning」（§1）——而 RL 路线学的是策略，不是「哪些前提导致哪个动作」。

于是论文的切口是：既不要用 RL 学策略，也不要指望 LLM 学会因果，而是单独学一张「动作的因果表」，在候选动作这一层把它叠上去。要注意，这张表并不告诉智能体「只做这些」——它只调整 LLM 已经吐出来的候选动作的权重，外加一个没候选时用的兜底。

03

一个加权、一次 softmax，再加一个兜底

读完这节要知道：在线阶段只有两步计算，以及「融合」与「兜底」分别在什么条件下触发。

因果分怎么查

矩阵 M ∈ ℝA×(S+A)：行对应一个可能的下一动作，列对应一个状态特征或上一步动作特征（§3.3）。当前状态与上一步动作里「为真」的位构成激活列集合 J = Active(s_t, a_{t−1})，则

pc(a) = Σj∈J M[idx(a), j]
Eq. 23 · 「当前成立的这些前件，对该动作的因果权重之和」；构建时按双向边取小值置 0 以保持 DAG（§3.3）

论文 Figure 2 给的例子里，M 列是 empty_hand1、hold_onion1、hold_onion2、pickup_onion(上一步)、pot0，五列全激活时两行相加都得整数——本页把图里可见的值逐字抄进下面的模拟器。

当候选集非空：加权 → softmax → 采样

pf(a′m) = γ · pa(a′m) + (1 − γ) · pc(a′m)
Eq. 4 · 蓝色是 LLM 自己的采样概率，accent 是因果分；γ 越大越信 LLM
Pf(A′) = softmax( pf(a′1), …, pf(a′|A′|) )
Eq. 5 · 对 A′ 上所有 p_f 做 softmax 归一化；重复动作合并与 categorical 采样见 Appx. B.2（本页锚定的 v1 里 softmax 是 Eq. 5，Eq. 22 是重复动作合并 §3.4.1）

两点值得记住：因果分是以「和」的形式进入的，即「有多少前件支持这个动作」；下面的模拟器在 Eq. 4 之外额外加了一个逐候选相同的偏移 δ（p_f = γ·p_a + (1−γ)·p_c + δ，论文里没有这个 δ，是本页演示用的）；softmax 的结果对两个动作的 p_f 之差敏感，对它们的共同偏移不敏感——所以在模拟器里拖动「共同偏移」似乎改变不了最终概率，这不是 bug。

当候选集为空：不重规划，直接查表

at = arg maxa∈A Pc(a)
Eq. 7 · A 是任务允许的全部动作；Pc(a) = M(s_t, a_{t−1}, a)（§3.4.2）

作者的理由是：LLM 持续幻觉无效动作时，「暂停并重规划」的软干预会失败，而「回想过去真正可行的动作」更像人在不确定时的做法。这是贪心选择，不从分布里采。

04

因果表是离线学出来的：20 万步轨迹、50 万次迭代、约 3 小时

读完这节要知道：矩阵 M 从哪来、学的是什么、一次投入能否复用。

三件工程事实

  • 数据来源：缓冲区 B 由固定行为策略 πβ 与环境交互 200,000 步收集，每回合 400 步（Table A4）。为避开小 LLM 的冷启动，论文默认用预训练的 MEP 策略来采；也太试过 Llama-8B 采数据（Appx. C.4.3）。
  • 特征化：状态与动作拆成二值特征位，低层移动动作被回填成最近一次高层动作（Appx. B.1）；训练时只用被控智能体自己的上一步动作，不用对方的（Appx. B.1.1）。CR 布局最终是 21 个父节点、7 个子节点（Appx. C.4.5）。
  • 训练：每个动作位一个 MLP（四层隐藏层 64/256/256/64，Adam，lr 3e-4），生成参数 δ 与结构参数 η 交替优化（Algorithm 1），损失 L = L_causal + L_reg，L_causal 是下一动作的负对数似然（Eq. 2），L_reg 是邻接矩阵的负对数先验惩罚（Eq. 3，λ = 1e-7）。迭代 500,000 次。
一次投入，多模型复用

学图约 3 小时；真正贵的是在线推理

Appx. C.4.5：CR 的因果图训练约 3 小时，是离线一次性的，四种骨干模型共用同一张 M。在线 400 步的耗时（NVIDIA H100）：Gemma-7B / Llama-8B 约 5 → 15 分钟，Qwen-14B 约 16 → 41 分钟，Llama-70B 约 40 → 68 分钟。按 C.4.5 的分组口径，三组耗时分别变为原来的 15/5 = 3.0×（Gemma-7B 与 Llama-8B 合为一组，原文未拆分）、41/16 ≈ 2.6×（Qwen-14B）、68/40 = 1.7×（Llama-70B），即 1.7–3.0 倍。推断（依据 C.4.5）：每组「带 CausalPlan」约为「不带」的两倍，与每步多做一次 LLM 调用的解释一致，但原文未给这一拆解。这是论文自己未用「显著」二字描述的成本项。

还有一处容易被忽略的口径问题：γ 是逐布局、逐模型调的（Table A6）。除 Forced Coordination 外 5×4 表中都是 0.5，FC 上 Gemma-7B 0.6、Llama-8B 0.4、Qwen-14B 0.7；调参只在「γ = 0.5 时反而更差」的布局上做过（Appx. C.4.2，原文这句在图注与正文里说法不一致：正文写 0.5–0.7，Figure A5 图注写 0.4–0.8）。

边界一

场景太简单时，因果分会帮倒忙或白做工

CR 上 CausalPlan 输给 FCP 21.3 分；COR 上输给 MEP 4.1 分。作者的归因是 CR 不需要因果知识。更关键的是：若候选集只有一个动作（ProAgent 的提示要求 LLM 只规划一个最优技能，Appx. B.2.1），加权之后 softmax 照样是 1.0——此时真正有信息量的只有「兜底」推断（依据：softmax（Eq. 5）在 |A′| = 1 时恒为 1；但论文未统计 |A′| 的分布）——这也解释了为什么去掉 CBA 的版本（141.3 ± 12.9）低于完整版（150.7 ± 2.3），按论文自己的绝对口径差 9.4 点、按其表格列的「平均增益」差 6.7 个百分点。原文 §4.3 对同一组数字写的是「no CBA 仍比 2-Prompt 高 27%，但比完整版低 7%」——那是相对值：(150.7 − 121.3) / 121.3 = 24.2%推断，文中未给分母；而本页引的 9.4 / 6.7 是点差。原文把两种口径并排写出、没有注明，本页照原样转述并在紧邻位置点出，不替它改数。

边界二

格子的质量取决于谁在采数据

用 Llama-8B 采 20 万步数据后学的表，CR 上平均 125.3 ± 30.7；用 MEP 采则 150.7 ± 2.3（Table A3）。论文自己的解释是「更强的采集策略带来更好的因果表」。这意味着：要把它用到一个需要离线专家演示的新任务上，这个前提就得先满足。

边界三

它依赖「已知的状态/动作分解」和「噪声为零」

Appx. B.1.1 明说假设状态与动作空间已有已知分解；附录 C.4.4 的图来自 MEP，有难解释的边（特别是从对方状态出发的边）。另外所有实验都在 Overcooked 的确定性模拟器里做，人-机评测也只用 BC 代理（Figure 4），没有真实人类；论文 §5 自己也说还没在更大的闭源模型上评测。

一句话：CausalPlan 改的是候选动作的排序，不是 LLM 的因果理解；它把「顺序约束」从模型内部搬到了一张可以查、可以解释、也可以不再更新的表里。表更新靠谁、靠什么数据，就是它的天花板。
