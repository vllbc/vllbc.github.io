计划验证：用 Judge–Planner 对话清洗具身任务轨迹

人类演示的具身任务轨迹常有多余动作、冗余导航和漏掉的步骤。论文让一个 Judge LLM 逐条挑错、一个 Planner LLM 按批评修改，循环到 Judge 不再提新问题；全程只用自然语言 prompt，不接模拟器、不看视觉输入。TEACh 子集上最高 90% recall、100% precision，96.5% 的序列在 3 轮内收敛。

Ananth Hariharan、Vardhan Dongre、Dilek Hakkani-Tür、Gokhan Tur · UIUC · NeurIPS 2025 Workshop 原文 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

论文把“清洗具身任务演示”写成一个双智能体验证循环：Planning Agent 先给出计划 π；Judge LLM 按目标 g 逐条检查，用 #REMOVE 标多余/矛盾动作、用 #MISSING 标缺失步骤，并给自然语言理由；Planning Agent 按这些批评生成 π′；重复到 Judge 不再提新问题，或达到 5 轮上限。

方法不改模型参数，也不依赖环境模拟器或视觉输入；它把 LLM 当作零样本评审器，直接处理已有的 TEACh 人类演示。实验用 100 个 episode、15 个家务任务、1,408 个人类动作，人工标注错误动作作为 ground truth，比较 4 个 Judge LLM 与 4 个 Planner LLM 的 16 种组合。

结果是明显的 precision–recall 权衡：GPT o4-mini 做 Judge 时 recall 最高（单次 80%，迭代后 90%），但 precision 会降到 80%；DeepSeek-R1 做 Judge 时 precision 可到 100%，recall 只有 62–68%（与自家 Planner 配对时为 68%）；Gemini 2.5 的 F1 最稳，最高 93.9。收敛很快：62% 的序列第一轮后不再需要修改，3 轮累计 96.5%。

01

演示数据不是教科书：多余动作、矛盾动作、漏步都会污染模仿学习

读完这节应该知道：为什么具身任务需要“计划验证”，以及论文把哪些东西算作错误。

具身智能体通常从人类演示里学任务，例如 TEACh 数据集里的家庭交互。人类演示并不最优：可能拿起与目标无关的物品、来回走动、先把电器关掉再打开，或者因为指令理解错误而漏掉关键步骤。这些轨迹直接用于模仿学习，会把噪声写进策略。

论文把错误分成三类（§3.1）：

Redundant

多余 / 重复

不必要的重复动作，或互相抵消的操作。例如拿起一个目标不需要的物品，或把已经关掉的设备再关一次。

Contradictory

矛盾

与之前的动作或任务目标相反。论文把矛盾动作归入 REMOVE 处理，不单独设第三类修正类型。

Missing

缺失

完成任务所必需、但计划里没有的步骤。Judge 用 #MISSING 标出，Planner 负责补上。

形式化地，计划 π = (a1, …, aT) 是原子操作序列，例如 PickUp、ToggleOn、Place。目标是给定自然语言目标 g 和初始计划 π(0)，输出一个仍能完成 g、但长度更短的计划：

π* = arg minπ̃ |π̃|   s.t.   π̃ 完成 g
§3.1 的目标：允许插入必要步骤，但惩罚多余动作；论文把“完成 g”作为约束，把长度作为优化目标。

这个定义有两个隐含条件。第一，必须有一个“完成 g”的判定；论文用人工标注的动作级错误作为评估 ground truth，但没有在方法里给出自动的任务成功判定器。第二，长度最短不等于执行最优；论文主要评估 Judge 找错的能力，任务级成功率与长度缩减在 §3.2 说“另行报告”。

03

Judge 输出批评集合，Planner 确定性执行，合成验证算子 V = P ∘ J

方法本身是一个很薄的循环；真正决定效果的是 Judge 的批评质量与 Planner 的执行忠实度。

Judge 是一个函数 J，把目标 g 和当前计划 π 映射成批评集合：

J(g, π) = C = { (i, type, reason) }
type ∈ { REMOVE, MISSING }
§3.1：每条批评包含动作索引 i、修正类型和自然语言理由；矛盾动作被归入 REMOVE，不单独设类型。

Planner 是另一个函数 P，把计划与批评映射成新计划；两者复合得到验证算子 V：

P(π, C) = π′
V = P ∘ J   ⇒   π′ = V(g, π)
§3.1：论文假设 V 是保守的，即 E[E(V(π))] ≤ E(π)，其中 E(π) 是计划中的错误数；在这个假设下误差序列非增，并存在 δ > 0 使 E[E(k+1)] ≤ (1−δ) E[E(k)]。

迭代形式就是重复应用 V：

C(k) = J(g, π(k))
π(k+1) = P(π(k), C(k))
§3.1 / Algorithm 1：最多 5 轮；若 Judge 返回空批评集合，直接返回当前计划；否则 Planner 应用批评并重新编号，进入下一轮。

这里有两个容易被忽略的点。第一，“保守”是假设，不是定理：论文没有证明 Judge 与 Planner 一定满足 E[E(V(π))] ≤ E(π)，只把它作为收敛分析的前提。第二，Planner 被描述为“deterministically”应用批评，但实现上仍是 LLM 按 prompt 修改推断（依据：§3.1 与 Appendix A.2 的 Planner 是 LLM prompt，Algorithm 1 的 P.apply_critiques 没有确定性规则）；哪些批评被采纳、是否引入新错误，取决于模型。

评估口径

Judge 的输出与人工标注逐动作比较。正例是“错误动作”，包括 REMOVE 与 MISSING；矛盾错误被归入 REMOVE。指标是：

Recall = TP / (TP + FN)
Precision = TP / (TP + FP)
F1 = 2 × Precision × Recall / (Precision + Recall)
§3.2：recall 是所有真实错误动作中被标出的比例；precision 是所有被标出的动作中真正错误的比例；F1 是两者的调和平均。

这个口径只衡量“找错”，不衡量“改对”。一个 Judge 可以高 recall 地把所有可疑动作都标出来，但 Planner 可能改错；论文的 Table 2 同时报告 recall 与 precision，但没有单独的“修正后计划正确率”表。

零训练

可缓存

人工瓶颈

评估仍要人工标注 1,408 个动作；方法本身不提供自动 ground truth，也没有报告标注者一致性。

05

计划 → 批评 → 修改 → 再批评，直到空集或第 5 轮

流程图只有两个角色和一条回路；关键分支是 Judge 返回空批评时停止。

Judge 的角色

只看文本，不看执行

Judge 接收目标与动作序列，逐条分析每个动作是否服务于目标；它不调用模拟器、不检查前置条件是否真的满足推断（依据：§3.1 的 Judge 输入只有 g 与 π，Limitations 与 Appendix 都没有模拟器调用），也不看视觉场景。

Planner 的角色

执行批评，不重新规划

Planner 按 Judge 的 REMOVE / MISSING 修改计划，保留原格式；它不是从目标重新生成计划，因此输出质量受批评集合约束。

这套分工的优点是模块化：Judge 和 Planner 可以来自不同模型，Table 2 因此能逐格比较 16 种组合。缺点是错误会沿链路传播：Judge 漏掉的错误，Planner 不会主动发现；Judge 错标的动作，Planner 可能直接删掉。

模型风格：保守、激进、均衡

DeepSeek-R1：保守

Judge 侧 precision 在 98–100%，recall 只有 62–68%。它只在非常确定时标错，漏掉约三分之一的错误；优点是几乎不误删有效动作。

GPT o4-mini：激进

Judge 侧 recall 85–90%，precision 80–91%。它抓错多，但会把一些必要动作标成多余；在与 DeepSeek-R1 做 Planner 的组合里 recall 达到 90%，precision 掉到 80%。

Gemini 2.5：均衡

作为 Judge，F1 在 90.7–93.9，四个 Planner 列里都是最高；recall 84–89%，precision 96–99%。论文称它最稳。

LLaMA 4 Scout：中间

recall 75–81%，precision 89–93%，没有单项最高，但跨 Planner 波动较小。它做 Judge 时与自己的 Planner 配对 F1 最低（81.6），是“同模型配对更好”的一个反例。

论文的定性分析还列了三类系统性失败：Judge 对“很早拿起、很晚才用”的长程冗余不敏感；会把多步准备动作误判为多余；会把同一物体的第二次使用误删。这些错误说明当前 Judge 擅长表面逻辑，不擅长长程依赖与上下文敏感判断。

07

只在 TEACh 子集上验证，任务级结果在 v4 中没有对应表

论文的边界比结论更值得记住：单数据集、人工标注、零样本 Judge、无下游训练。

数据范围窄

15 个家务任务、100 个 episode

全部实验在 TEACh 子集上，覆盖 15 个常见家务目标；工业、医疗、户外等场景没有测试。论文自己在 Limitations 里说，泛化性未验证。

标注主观

ground truth 是人工判断

哪些动作算“必要”、哪些算“多余”，由人工逐动作标注；论文承认这会引入主观性与不一致，但没有报告标注者间一致性。

方法层面的限制更关键。第一，论文报告的是 Judge 与人工标注的逐动作对照；§3.2 说任务级结果（plan success rate、平均长度缩减）“另行报告”，但 v4 正文与附录没有给出对应的表。§4 另有一句“These results are obtained by manual annotations that assess the final Planning Agent output based on the action sequence accurately achieving the goal set by the Commander…”，字面上涉及最终计划是否达成目标；它与 §3.2 的“另行报告”并列时口径不清。页面因此只把 Table 1/2 当作找错评估，不把“清洗后数据更好”当作已验证结论。

第二，Judge 完全依赖文本，不接环境模拟器、不看视觉输入，也不检查动作前置条件是否真的满足。它能发现“看起来多余”的动作，但无法确认“拿起杯子”时杯子是否真的在桌上。论文把视觉 grounding 与物理模拟列为未来工作。

第三，零样本 LLM 的判断受偏见、知识截止与幻觉影响；论文建议用 fine-tuning 或混合外部知识库缓解，但没有给出这样的实验。Judge 与 Planner 同源时也可能共享同一盲区，Table 2 的对角线并不总是最好（LLaMA 4 Scout 做 Judge 时，配 GPT Planner 的 F1 83.5 高于自配 81.6）。

最后，迭代上限是 5 轮，但 96.5% 的序列 3 轮内已收敛；§4.2 称继续跑到第 4–5 轮只对 3.5% 的序列有边际收益（Figure 3 第 4/5 轮的标注为 98.5%/99.7%）。论文没有给“何时停止”的自适应准则，也没有分析第 4–5 轮是否可能引入新错误。
