ExRAP：把「探索」算进规划，让机器人持续跟随动态指令

持续指令跟随要求智能体在非平稳环境里反复核对条件：不探索会拿到过时记忆，盲目探索又会让每一步都变贵。 ExRAP 把指令拆成 query 与 execution，用带时间戳的 TEKG 存观察，再把信息增益作为探索价值，与 LLM 的利用价值一起加权选技能。

Minjong Yoo, Jinwoo Jang, Wei-jin Park, Honguk Woo · SKKU / Acryl arXiv 2509.08222v1 ↗ 博客笔记 ↗
TL;DR · 30 秒抓住核心

持续指令跟随不是一次性任务：多条条件指令同时生效，环境状态持续变化；智能体既要判断条件是否满足，又要在条件满足后尽快执行。 论文用 SR（任务成功率）与 PS（条件满足到完成的平均步数）两个指标衡量（Eq.1）。

ExRAP 的记忆是 TEKG：四元组 (se, re, te, t) 随时间累积；查询评估先用检索到的子图问 LLM， 再用时间一致性把「越旧反而越确定」的响应剔除。

规划时，LLM 给技能的利用价值 v_T 与信息增益近似的探索价值 v_R 加权求和； Table A.4 的默认权重是 w_R=1.0、w_T=0.01。

在 VirtualHome、ALFRED、CARLA 的 9 个「环境 × 非平稳性」设置里，ExRAP 的 SR 都高于 LLM-Planner； 消融显示时间一致性和探索项都影响结果。

01

持续指令不是一次性任务，难在「什么时候该去看」

先建立任务设定：多条条件指令、非平稳环境、两个指标。

论文把持续指令跟随定义为一组条件指令 I = {i1, …, iM} 在非平稳环境中同时、持续生效。每条指令拆成 query q（要验证的环境条件）与 execution e（条件满足后要执行的操作）；query 需要对着环境状态反复验证，而不是一次规划完就结束。

指标有两个：SR 是条件已满足的任务中完成的比例；PS 是从条件实际满足到任务完成的平均步数。Eq.1 把两者合成一个目标：最大化各步的 SR，同时最小化 PS 的期望。

π* = argmaxπ [ Σt SR(st, π(ot, I)) + Ei∈IC[ −PS(π, i) ] ]
Eq.1 · 任务完成与执行效率放在同一个目标里

两个朴素做法都不够好。第一种是 instruction-wise：每次按指令逐条检查，移动次数随指令数增长；第二种是只信旧记忆：环境已经变了，查询评估仍按旧状态回答。论文要处理的是这两者之间的张力——记忆的有效性 vs 探索负载。

非平稳性用环境条件变化的间隔控制：高 / 中 / 低分别每 4 / 6 / 8 个 timestep 变一次（Appendix B）。变化越快，旧记忆越容易失效，探索越重要。

核心张力

不探索会错，探索太多会慢

PS 直接把「等待」计入指标：智能体不能为了确认一个条件而无限绕路。ExRAP 的规划目标因此不是「探索最多」，而是「用尽量少的探索把记忆维持在足够可信的状态」。

02

已有 LLM 规划器会做任务，但不会主动维护环境记忆

两路对照：LLM 任务规划与 RAG / 探索；它们各自缺了什么。

LLM 规划器

把当前任务做对

ZSP 把指令翻译成技能序列；SayCan 用 LLM 的语言 affordance 与 RL 学到的 embodied affordance 打分；ProgPrompt 用代码式提示生成计划；LLM-Planner 检索 in-context 演示并逐步推理。

缺什么：它们主要优化「当前任务怎么完成」，观察信息通常以非系统化的方式塞进 prompt；很少显式处理多条持续指令，也没有把「去看一眼」当作一个可优化的动作。

RAG 与 RL 探索

检索信息或探索环境

RAG 从数据库检索任务相关信息；embodied RAG 用任务演示增强规划。RL 里的探索用内在奖励或互信息（如 DREAM）来收集信息。

缺什么：这些工作分别解决「检索什么」和「往哪探索」，但没有把信息增益直接接进 LLM 的任务规划，也没有处理记忆随时间衰减的问题。

ExRAP 的位置：用 TEKG 把环境观察变成可检索、带时间戳的记忆；用时间一致性修正查询评估；再把互信息近似的探索价值与 LLM 的利用价值合成一个技能选择规则。它不是把 RAG 当成静态文本检索，而是把「检索什么、什么时候重新检索」也纳入规划。

03

把「记忆是否可信」和「下一步去哪」写成两个可计算的量

四个部件：TEKG、查询评估、时间一致性、探索价值；最后合成一个技能选择规则。

TEKG：每条观察都带时间戳

TEKG 的每个事实是四元组 τ = (se, re, te, t)：源实体、关系、目标实体、时间戳。Gt 只包含 ti ≤ t 的四元组。

Gt = { τ1, …, τN },   τi = (sei, rei, tei, ti),   ti ≤ t
Gt+1 = μ(Gt, ot+1) = { τ ∈ Gt | c(τ, τ′) = 0, ∀τ′ ∈ ot+1 } ∪ ot+1
Eq.2–3 · c 检测语义矛盾（例如电视同时为 on 和 off）；更新时删掉与最新观察矛盾的旧四元组，再加入新观察

Appendix C.2 给了两条实现规则：与 agent 相关的四元组只保留最新时间步；对象状态相反，或同一对象同时出现在两个位置时，删掉旧四元组。这样记忆不会无限堆叠互相矛盾的旧状态。

查询评估：检索子图没变，就不重复调用 LLM

指令解释器 ΦI 把 I 映射为 queries Q、executions E 和条件函数 C，其中 C(qj) = ej（Eq.4）。查询评估器 ΦM 估计 P(q|Gt)：如果检索到的子图与上一步相同，就直接复用上一步的结果；否则把检索子图、上一步结果和时间 t 一起交给 LLM。

P(q|Gt) = ΦM(q, t, G1:t, P(q|Gt−1))
= R(q|Gt−1)    if  Ĝ1:t = Ĝ1:t−1
= ΦLLM(q, t, Ĝ1:t, R(q|Gt−1))    otherwise
Eq.5 · 检索子图没变就复用 prior；变了才把 prior 作为上下文重新评估

当 P(q|Gt) > θ 时，对应的 execution 进入待执行集合 Et（Eq.8）；默认 θ = 0.5（Table A.4）。

时间一致性：旧记忆不应该「越老越确定」

记忆越旧，查询响应的不确定性应该越高。论文把这条直觉写成约束：用 Gt−1 在 t 时刻算出的 prior 的熵，必须大于上一步的熵。

H(R(q|Gt−1)) > H(P(q|Gt−1))
Eq.6 · 不满足这条约束的响应被视为「旧记忆给出了过确定的答案」，丢弃

具体做法：对同一个 query 采样多次 ΦLLM，只保留满足 Eq.6 的响应，再取平均（Eq.7；Algorithm 1 第 10–18 行，最多 10 次）。这既是对信息衰减的建模，也是一种集成，降低单次 LLM 输出的方差。

探索价值：这个技能能减少多少查询熵

利用规划器 vT 用 LLM 在 in-context 演示下给技能打分（Eq.9）。探索规划器 vR 则看技能执行后能减少多少查询响应的不确定性：

vR(Gt, z) = I(Q; Gt+1) − I(Q; Gt)
= Σq∈Q H(P(q|Gt)) − H(P(q|Gt+1))
Eq.10 · 互信息增益 = 执行技能后查询熵的下降量

直接算 Gt+1 需要先执行技能，不可行。论文只对检索到的、与查询相关的知识做近似：

vR(Gt, z) ≈ Σq∈Q H(P(q|Gt)) · (1 − d(ΦR(Gtz, {q})) / d(ΦR(Gt, {q})))
Eq.11 · d 是检索四元组到当前 agent 实体的平均距离；Gtz 是执行技能 z 后的预测部分更新图，只改与 agent 相关的四元组

直觉：技能让 agent 在图上更靠近与 query 相关的区域，分母变小、括号变大，探索价值上升。这个近似依赖一个假设：TEKG 与真实环境完全同步时，查询评估器的熵为零（§3.4）。

技能选择：两项加权，权重不是 1:1

zt = argmaxz∈Z [ wT · vT(Gt, z) + wR · vR(Gt, z) ]
Eq.12 · 利用价值与探索价值的加权和；Table A.4 默认 wR=1.0、wT=0.01

Table A.4 固定 wR=1.0、wT=0.01；论文没有报告这两个权重的敏感性分析。两项的定义不同、量纲不同，不能把 1.0 与 0.01 直接读成重要性比例；它们只是论文实验设定下的缩放系数。推断（依据：原文只给固定权重，未报告权重敏感性或量纲归一化）。

04

没有训练阶段：每一步都是检索 + 多次 LLM 调用

工程账本：模型、超参数、耗时、硬件。

论文没有描述训练阶段；ExRAP 靠 LLM 的 in-context learning、TEKG 检索和一套固定的打分规则，在推理时逐步决策。默认 LLM 是 Llama-3-8B；Gemma-2B 和 Llama-3-70B 用于消融设置（Appendix C 的 Table A.4 原文只写 Ablation study；模型规模对比见 Table 6）。

05

两条链在每一步闭合：查询评估 → 规划 → 环境 → 记忆更新

按 Figure 2 重绘的简化流程图；看循环在哪里闭合。

循环的关键在于：规划选出的技能 zt 不仅改变环境，也改变下一步的 TEKG；查询评估的结果又反过来影响哪些 execution 进入 Et。ExRAP 把「维护记忆」和「完成任务」放在同一个循环里，而不是先探索完再规划。

它解决的是「记忆怎么维护」，不是「机器人什么都能做」

论文自己承认的限制，加上从实验设置能看到的边界。

边界一

计算开销不是零

TEKG 管理 + 时间一致性 + 每个 query 最多 10 次采样，比单次 LLM 规划更贵。论文 Limitation 明确说 computation effort 增加，runtime overhead 仍需研究；按 Appendix E.2 / Table A.8 复算得 13.9×（原文写 approximately 14 times），它是「检索 + 推理」相对「无检索推理」的比值，不是端到端延迟。

边界二

依赖 LLM 与结构化记忆

TEKG 用四元组表示对象状态、位置、房间邻接等；查询评估和规划都依赖 LLM 的常识与上下文能力。Table 6 显示 ExRAP 在 Gemma-2B 上仍有 52.75% SR，但论文仍把 LLM 能力列为限制。

边界三

只在模拟器里验证

VirtualHome、ALFRED、CARLA 都是模拟器；论文没有报告真实机器人实验。感知噪声、执行失败、传感器误差会不会破坏时间一致性假设，未验证。推断（依据：三个实验环境均为模拟器，论文未报告 sim-to-real 实验）。

边界四

超参数与长期规模未展开

θ=0.5、w_R=1.0、w_T=0.01 是固定值；论文没有给出敏感性分析。TEKG 长期运行时的规模、检索延迟、内存增长也没有报告。指令类型只测了 sentence-wise、summarized、object ambiguation 三类（Table 3；数值未转录），更开放、含糊或需要外部知识的指令不在评测范围内。推断（依据：Table 3 只列这三类，论文未声明覆盖其余指令类型）。

什么时候别用：如果环境变化慢、指令少、单次规划成本敏感，或者无法承担多次 LLM 调用，ExRAP 的探索收益可能覆盖不了开销。推断（依据：它的收益主要出现在非平稳 / 多指令设置，而开销来自每步的检索与采样；论文没有报告这一取舍的拐点）。
