Memp：把过去的轨迹，炼成可检索、可修正的程序记忆

LLM Agent 每次遇到相似任务都要重新试错，前面踩过的坑不会自动变成下一次的捷径。 Memp 把成功轨迹和从轨迹里提炼出的脚本存进一个外部记忆库，让新任务先检索「怎么做」，再用失败反馈修正记忆。 它不在模型参数里写记忆，改变的是任务开始前塞进上下文的那一段经验。

Runnan Fang et al. · Zhejiang University / Alibaba Group / Nanjing University arXiv 2508.06433 ↗ 代码 ↗ 博客笔记 ↗
TL;DR · 30 秒抓住核心

Agent 的瓶颈常常不是单步推理，而是每个新任务都从零开始。论文把「知道怎么做」的程序记忆做成一个外部仓库：过去的轨迹先被提炼成可复用的步骤或脚本，下一次任务开始时再检索出来放进上下文。

论文没有提出新的网络结构，而是把记忆的生命周期拆成三个可做消融的决策：Build（存 Script、Trajectory，还是两者相加的 Proceduralization）、Retrieve（Query 还是 AveFact 关键词做向量检索）、Update（Vanilla、Validation，还是失败后反思修正的 Adjustment）。

在 ALFWorld 上，GPT-4o 的 Test 成功率从 42.14% 到 77.86%，平均步数从 23.76 到 15.01；TravelPlanner 的 #CS 也从 71.93 到 79.94。但 #HC 反而从 12.88 降到 9.76——记忆不是每个指标都加分。

迁移实验里，GPT-4o 的记忆给 Qwen2.5-14B 用，TravelPlanner 的 Delivery 从 91.4 到 96.6，平均步数从 16.9 到 15.3；检索条数从 0 加到 10 时 Final Score 从 40.7 升到 82.5，继续加到 20 又回落到 79.3。

01

每次从零开始，Agent 缺的是「怎么做」的记忆

读完这节应该知道：论文要优化的不是「存什么」，而是「怎么把一次探索变成下一次任务开始时就能用的起点」。

在 ALFWorld 里找鸡蛋、用微波炉加热、再丢进垃圾桶，或者在 TravelPlanner 里排一条同时满足预算、时间和常识约束的行程，往往要几十步。Agent 在过程中会积累大量关于环境的知识：东西通常放在哪里、哪个动作会失败、哪条工具调用顺序能走通。但下一次遇到同类任务，这些知识大多没有被保留下来。

论文把一次任务写成一条轨迹（Eq. 1），并用环境给出的奖励判断它是否完成（Eq. 2）：

τ = (s0, a0, o1, s1, a1, o2, …, sT)
Eq. 1 · 状态、动作、观测交替出现；τ 是这次任务的完整探索轨迹
r = R(env, sT, τ) ∈ [0, 1]
Eq. 2 · 奖励由最终状态或整条轨迹决定；ALFWorld 给 0/1，TravelPlanner 给 #CS 与 #HC 得分

认知科学把这种「知道怎么做」的长时记忆称为 procedural memory，与「知道是什么」的 declarative memory 区分。论文借用这个概念，把 Agent 的程序记忆定义成一个可编辑的仓库：每条记忆 mp 由轨迹 τ 和奖励 r 经过一个 builder B 生成（Eq. 3）。

核心矛盾

轨迹里有很多信息，但轨迹本身不是可复用的技能

原始轨迹又长又具体，直接塞回上下文会占用大量 token；一旦环境细节变化，逐字复制的动作序列就可能失效。 如果只用一句抽象总结，又会丢掉「先做什么、后做什么、失败了怎么退」这些真正有用的步骤。 论文要在这两极之间找一个可操作的存储形态，并且回答：新经验进来时，什么时候该追加、什么时候该丢弃、什么时候该修正旧记忆？

更麻烦的是，记忆不是「越多越好」。检索错了会引入无关内容，更新错了会把错误经验写回仓库。 论文在 Introduction 里把这一点说得直接：

“Restarting from scratch every time is a punishing ordeal for present-day agents.”（§1）

所以问题不只是「给 Agent 加一个记忆模块」，而是给记忆的生命周期建立一套可比较、可衡量的策略。这正是 Memp 的切口。

02

已有记忆框架有仓库，却没有程序记忆的生命周期

前人分成两路：一路搭记忆架构，一路从经验里学习；两路都留下了「怎么建、怎么检、怎么改」的空档。

记忆框架

有缓冲区，缺生命周期优化

LangGraph、AutoGPT、Memory Bank、Soar 这类系统提供了粗粒度的抽象：buffer、rule chunk、production system。 它们能存东西，但论文指出，这些工作把程序记忆的生命周期操作——技能如何被构建、索引、修补、最终剪枝——基本留在了考察之外。

“leave the optimization of procedural memory life-cycle operations about how skills are built, indexed, patched, and eventually pruned, largely unexamined.”（§1）

从经验学习

有更新，缺系统对照

另一路用强化学习、experience replay、imitation learning、memory management 让 Agent 从交互中改进。 这些方法能更新行为，但常见问题是样本效率低、跨任务泛化差、学新东西时灾难性遗忘，而且专门针对记忆更新的机制很少。

“low sample efficiency, poor generalization across tasks, catastrophic forgetting when learning new information, and there are few features for memory update.”（§2）

在程序记忆这个更窄的圈子里，Voyager、AWM、AutoManual 已经用技能库或操作手册提升过同类任务的表现。 但论文认为，这些工作仍然缺少对「如何构建、如何检索、如何更新程序记忆」的系统分析：

“there still lacks a systematic analysis on how to construct, retrieve, and update such procedural memory”（§2）

Memp 的切口

不换模型，换的是任务开始前的那段上下文

Memp 是一个 task-agnostic 的框架，把程序记忆当成一等优化对象：记忆存在模型外部，模型参数不动；每次任务开始时检索记忆，任务结束后按策略更新仓库。 论文的主要贡献不是某个单点技巧，而是把 Build / Retrieve / Update 三个模块拆开，分别做可复现的对照实验。

03

把记忆拆成 Build / Retrieve / Update 三个可消融的决策

这一节是全页的核心：三种构建形态、三种检索 key、三种更新策略，以及它们各自的代价。

Memp 没有新的网络层。它把 Agent 的程序记忆写成一个集合（Eq. 3），每条记忆由 builder B 从轨迹和奖励中生成：

Mem = Σt=1T mpt      mpt = B(τt, rt)
Eq. 3 · 记忆库是逐任务构建出来的；B 的具体形态就是 Build 策略要选的东西

Build：存整条轨迹，还是存抽象脚本

论文比较了三种构建形态，外加一个完全不用记忆的基线：

Script让模型分析并总结训练集里的 gold trajectories，提炼成抽象的程序知识，任务开始前作为 prompt 提供。
Trajectory从训练集筛选 gold trajectories 原样存入；推理时按 query 向量检索 top-k 条，作为具体案例放进上下文。
Proceduralization把检索到的完整轨迹和高层 script 合并：既有抽象指导，也有可模仿的具体步骤。

这三种形态对应一个直接的权衡：Script 更抽象、更省上下文，但可能丢失操作细节；Trajectory 更具体，但占用更多 token，也更容易被表面相似的案例带偏。 Proceduralization 试图同时保留两者。

Retrieve：用什么 key 去向量库里找记忆

给定新任务 tnew，检索器要找一条最相似的历史记忆（Eq. 4）；实验里用余弦相似度（Eq. 5）：

mretrieved = arg maxmpi ∈ Mem S(tnew, ti)
Eq. 4 · 相似度函数 S 决定「哪条经验最值得参考」
S = ( φ(tnew) · φ(ti) ) / ( ‖φ(tnew)‖ · ‖φ(ti)‖ )
Eq. 5 · φ 是任务的向量编码；实验用余弦相似度

论文比较了三种 key 构造方式：

  • Random Sample：不做向量检索，随机抽几条记忆。
  • Key=Query：直接用任务 query 的描述做 key，靠 query 的语义相似度检索。
  • Key=AveFact：先用一个大模型从 query 里抽关键词，再计算这些关键词与记忆项的平均相似度。论文的说法是，这样做能把注意力集中到任务的核心要素上。

Update：追加、筛选，还是失败后反思修正

记忆库不是一次性写死的。论文把更新写成 Eq. 6，并进一步拆成增加、删除、修改三类操作（Eq. 7）：

M(t+1) = U( M(t), E(t), τt )
Eq. 6 · E(t) 是执行反馈，例如成功、失败、性能指标
U = Add(Mnew) ⊖ Del(Mobs) ⊕ Update(Mest)
Eq. 7 · 新记忆、待删除的过时记忆、待修正的记忆分别走三条路径

实验里对应三种策略：

Vanilla每 t 个任务，把这一组任务的所有轨迹都提炼成记忆，直接追加到仓库。
Validation每 t 个任务，只保留成功完成任务的轨迹，失败轨迹和噪声数据丢弃。
Adjustment当一条被检索出来的记忆导致执行失败时，把失败轨迹和原记忆放在一起，让模型反思并在原位修正，生成更新后的记忆。

论文在 §4.3 把这种反思式更新称作 reflexion-based update mechanism，并给出结论：在 Figure 3 的最后一组任务上，它是三种策略里最高的。 具体数字与原文表述的对照放在 06 效果。

04

没有梯度更新：记忆在任务流里在线生长

这一节回答工程问题：记忆从哪里来、什么时候写、每次任务要付多少上下文和 LLM 调用。

Memp 的方法里没有训练阶段；实验中的 backbone 参数保持不变。它的「学习」全部发生在外部仓库里：离线阶段从训练集构建记忆，在线阶段按任务流检索和更新。 实验的流程可以拆成四步：

  • 离线构建：从训练集筛选 gold trajectories；Trajectory 直接存，Script 让模型总结，Proceduralization 两者都存。
  • 在线检索：新任务到来时，用 Query 或 AveFact key 做向量检索，取 top-k 条记忆，拼进任务上下文。
  • 执行与反馈：No Memory 基线以 ReAct 方式交互；记忆条件把检索到的记忆拼进任务上下文后再执行。ALFWorld 由环境给 0/1 奖励，TravelPlanner 由最终计划与 gold plan 对比得到 #CS / #HC。
  • 周期性更新：每 t 个测试任务刷新一次记忆；Vanilla 写全部轨迹，Validation 只写成功轨迹，Adjustment 在检索记忆导致失败时反思修正。

成本结构

省下的是试错步数，付出的是构建与检索开销

构建：Script 与 Proceduralization 需要额外的 LLM 调用去总结轨迹；Trajectory 基本只做筛选和存储。
检索：每次任务要做一次向量编码和 top-k 检索；k 越大，上下文越长，噪声也越多。
更新：Vanilla / Validation 主要是存储操作；Adjustment 在失败时多一次反思调用，成本随失败次数增长。
模型：实验设置里没有训练阶段；不更新参数，也不需要 RL 或微调。

实验用三个 backbone：GPT-4o、Claude-3.5-sonnet、Qwen2.5-72B-Instruct；迁移实验的目标模型是 Qwen2.5-14B-Instruct。 两个 benchmark 分别是长程家居任务 ALFWorld（Dev / Test 成功率与平均步数）和长程信息规划 TravelPlanner（#CS / #HC 与平均步数）。 Figure 3 把测试任务分成 5 组（横轴 1–5），每组结束后刷新一次记忆。

论文没有标注的复现细节t、top-k 的取值

§4.3 说「每 t 个测试任务刷新一次记忆」，但没有在正文或附录给出 t 的具体数值；§4.2 说检索 top-k 条轨迹，也没有给出 k 的取值。 Figure 5(b) 单独扫描了检索条数 0–20，但那是分析实验，不是主实验的默认 k。 本页不替论文补这些数字；如果要复现，需要对照官方代码。

05

一个外部仓库，两条回路：离线构建 + 在线检索/修正

把 Figure 2 的模块关系拆成箭头：谁读仓库、谁写仓库、反馈从哪里回来。

这张图里有两个时间尺度：快回路是每个任务开始时的「检索 → 执行」，慢回路是每 t 个任务后的「反馈 → 更新 → 仓库」。 论文的消融实验分别改了快回路的入口（Build 形态、Retrieve key）和慢回路的规则（Update 策略），所以才能把三个模块的贡献拆开看。

主结果：ALFWorld 的提升最干净

原文的总结句与 Table 1 的若干单元格方向相反

§4.2 的总结句是： “all memory construction methods outperform the no-memory baseline, achieving higher scores on both datasets while also reducing the number of steps required.”

Adjustment 的增益：原文写 +0.7 / 14，Figure 3 末组读数不是「与第二名的差」

§4.3 的原句是： “it surpasses the second-best strategy by an impressive margin of +0.7 points and achieves a reduction of 14 steps.”

反直觉之四

检索 key 的收益主要落在 #CS，#HC 仍可能低于无记忆

Table 2 里，GPT-4o 的 Key=AveFact 在 #CS 上从 No Memory 的 71.93 升到 76.02（相对 Random Sample 高 1.43 分，1.92%；相对 Key=Query 高 2.64 分，3.60%）。 但同一行的 #HC 是 8.25，低于 No Memory 的 12.88；Claude-3.5-sonnet 的 AveFact #HC 29.61 也低于 No Memory 的 33.06。 检索策略把「常识合理」找得更准，并没有同步把「硬约束」找回来。

Table 2 的 Key=AveFact 三行与 Table 1 的 Trajectory 三行逐位相同（GPT-4o 76.02 / 8.25 / 14.64；Claude 65.76 / 29.61 / 17.72；Qwen 63.41 / 12.66 / 18.12）。 推断（由 Table 1 与 Table 2 的三组数值完全相同反推）：检索消融是在 Trajectory 构建上做的，AveFact 就是 Trajectory 条件的默认 key；原文没有在表注里写明这一点。

07

它解决不了：稀疏奖励、硬约束与黄金轨迹依赖

论文自己列了两条限制，Table 1 / Figure 5 又给出了三条数据层面的边界。

边界一

检索只走向量相似度，key 是手工设计的

论文 Limitations 明确写：检索限制在 vector-similarity search + manually crafted keys，BM25 这类更经典、可能更精确的方法没有纳入。 推断（依据：论文只列了这条限制，没有给出大记忆库或稀疏关键词下的检索实验）：记忆库很大、关键词很稀疏时，向量检索的召回不一定可靠。

边界二

依赖 benchmark 给的显式奖励

论文 Limitations 的第二条：框架依赖 benchmark 提供的显式奖励信号，因此在真实世界里奖励稀疏或缺失时，还不能判断任务是否成功。 Validation 和 Adjustment 都需要「成功 / 失败」这个信号；没有它，更新规则就无法触发。

边界三

构建前提是训练集里的 gold trajectories

Trajectory、Script、Proceduralization 都从训练集筛选的 gold trajectories 构建（§4.2）。 如果目标场景没有可靠的成功轨迹，或者成功轨迹本身带有偏差，这套流水线的前提就不成立。 论文在 §2 也提到，收集高质量训练数据本身可能很困难，并可能引入偏差。

边界四

硬约束不是记忆的强项

Table 1 的 #HC 列显示：GPT-4o 与 Claude-3.5-sonnet 的记忆策略都没有超过 No Memory；Qwen2.5-72B 的 Trajectory / Proceduralization 高于 No Memory（7.34 → 12.66 / 14.19），Script 与 No Memory 持平（7.34）。 如果任务的关键是「不能违反硬约束」，而不是「计划看起来合理」，单靠这套程序记忆不够，需要额外的约束检查或验证器 推断（依据：GPT-4o / Claude 的 #HC 在加入记忆后下降，而 #CS 上升）。

边界五

检索太多会反噬，迁移证据也只有一组

Figure 5(b) 在 k=10 之后回落；论文把原因归为上下文变长和低质量记忆的干扰。 迁移实验只展示了 GPT-4o → Qwen2.5-14B 这一组强到弱的方向；TravelPlanner 有具体数字，ALFWorld 只说 “similar gains”，没有给出具体值。 推断（依据：Figure 5(a) 只报告这一组模型对）：目前还不能把「强模型记忆能普遍迁移到弱模型」外推到任意模型对。

什么时候别用：任务没有可靠的 0/1 奖励、硬约束是主要矛盾、拿不到 gold trajectories、或者记忆库会膨胀到向量检索明显失准时，这套方法的收益会打折。
