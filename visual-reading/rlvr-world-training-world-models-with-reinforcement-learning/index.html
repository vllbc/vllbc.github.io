RLVR-World：用可验证指标直接后训练世界模型

世界模型的目标是预测“动作之后世界会变成什么”，但标准训练用的是 MLE：最大化真实下一个状态的似然。这个目标和真正关心的指标——状态是否完全正确、视频是否清晰——并不对齐。RLVR-World 把解码后的预测指标直接当奖励，用 GRPO 后训练；语言与视频统一成 token 序列。文本游戏（1.5B + task-specific）整体准确率 32.87→63.24，网页 F1 49.94→65.11，视频多步重复率 48.6→9.9。

Jialong Wu、Shaofeng Yin、Ningya Feng、Mingsheng Long · 清华大学 THUML 原文 ↗ 项目页 ↗
TL;DR · 30 秒抓住核心

论文把世界模型统一成自回归序列预测：状态与动作都 token 化，模型输入 q(s, a)，输出 o(s′)。后训练时，对同一输入采样一组预测，解码成状态后用一个可验证指标 D 与真实下一个状态比较，奖励是 sign(D)·D；再用 GRPO 更新。MLE 优化的是 token 似然，RLVR 优化的是任务指标。

语言侧，文本游戏用二元准确率或“全属性 + 变化属性 + 完全正确”的任务奖励；网页用预测变化的 F1。视频侧，奖励是逐帧 −[L1 + LPIPS] 的和，指标包括 MSE、PSNR、SSIM、LPIPS 与重复率。

结果：1.5B 文本游戏从 SFT 的 32.87 提到 63.24（任务奖励），7B 二元奖励 65.53，略高于 GPT-4 的 64.76；网页 F1 从 49.94 到 65.11，下游网页 agent 成功率从 12.06 到 14.29；视频多步重复率从 48.6% 降到 9.9%。RLVR 只跑几百步，而 MLE 预训练是数十万步。

01

MLE 让模型学会“像数据”，却没学会“预测对”

读完这节应该知道：为什么世界模型的训练目标与使用目标会错位。

世界模型要近似状态转移 p(s′ | s, a)：给定当前状态与动作，预测下一个状态。论文把状态空间扩展到语言、图像、视频与低维连续信号，并统一用 decoder-only Transformer 做 next-token prediction（§4.2）。标准做法是 MLE：最大化真实下一个状态序列的似然（Eq. 2）。

问题在于，MLE 奖励的是“每个 token 的概率”，而使用世界模型时关心的是“解码后的状态是否正确”或“画面是否清晰”。两者并不等价。论文举了两个表现：视频多步预测会出现重复帧——因为每帧约 20% 的 token 与上一帧相同，模型可以利用这个捷径；语言侧则可能生成格式正确但事实错误的状态。Abstract / 摘要 把这种错位写成 “standard training objectives such as maximum likelihood estimation (MLE) often misalign with task-specific goals of world models”。

核心判断

奖励必须作用在解码后的状态上

RLVR-World 不把 reward 加在 token 概率上，而是先把模型输出解码成状态 ŝ′，再与真实状态 s′ 用任务指标比较。这样奖励与评测口径一致；代价是解码与指标计算必须可执行、可验证，且通常不可微，只能走 RL。

02

两条已有路线 + 一条本文路线：MLE 预训练、偏好对齐、可验证奖励

页面按训练目标把已有做法归为三类推断；原文 §2 是相关工作总结，没有这张分类表。

MLE 预训练 + SFT 是语言与视频世界模型的主线：先最大化真实序列似然，再用少量示范微调。它的优点是稳定、可扩展；缺点是目标与任务指标错位。论文的 Base 与 SFT 行就是这条路线。偏好对齐（RLHF 一类）用学习出来的人类偏好模型做奖励，但论文选择“可验证奖励”，因为状态是否正确、F1 多少可以直接算，不需要再训练奖励模型。任务专用模拟器（如 SIMPLER）用手工模拟器做策略评估，是本文视频实验的对照，不在这张三段式卡片里；本文的视频世界模型走学习式模拟器路线，并在 Real2Sim 评估中与 SIMPLER 比较（§6.4）。

路线 A

MLE / SFT

优化 token 似然；稳定，但与准确率、感知质量不对齐。视频里会放大重复帧捷径。

路线 B

偏好对齐

用人类偏好或学习奖励模型；适合主观目标，但需要额外奖励模型，且可能被 reward hacking。

本文路线

可验证奖励

直接用任务指标当奖励；客观、可复算，但要求指标可程序化计算，且覆盖的任务范围有限。

03

把“预测下一个状态”当成一道可判分的题

读完这节应知道：输入输出怎么构造、奖励怎么算、GRPO 在哪里介入。

序列化。对每个转移 (s, a, s′)，用模板把 (s, a) 拼成问题 q(s, a)，把 s′ 拼成回答 o(s′)。文本游戏状态是 JSON 文本；视频帧经视觉 tokenizer 编码；连续动作按取值范围离散成 256 个均匀 bin（§4.2、§6.1）。这样语言与视频共享同一个 next-token prediction 接口。

奖励。给定 q，旧策略采样一组输出 {o_i}，解码成 {ŝ′_i}，与真实 s′ 比较：

Ri = sign(D) · D(ŝ′i, s′)

Eq. 3。D 是任务指标；若 D 越小越好（MSE、LPIPS），sign(D) = −1，否则为 +1。

优化。用 GRPO（Eq. 1）：组内归一化优势 Â，加上 PPO 式 clip 与 KL 惩罚；不需要 value function。论文说框架兼容其他 RL 算法，但实验都用 GRPO（§4.3；GRPO 见 §3）。

三种任务的 D。文本游戏有两种奖励：二元奖励只在三元组 (状态, 奖励, 完成标志) 完全正确时给 1；任务奖励是 α₁·acc_all + α₂·acc_changed + α₃·I(correct)，权重 0.1 / 1 / 0.2（Appendix A.1）。网页用预测变化集合与真实变化集合的 F1（§5.2）。视频用逐帧 −[L1 + LPIPS] 的和（Appendix A.4，Eq. 9–10）——注意不只是 LPIPS。

口径

论文里的 “+34.7%” 是百分点

§5.1 写 RLVR 在 1.5B 上带来 “+34.7% accuracy for unchanged and +8.9% for changed”。按 Table 1 的显示值，73.57−38.88=34.69、33.14−24.21=8.93，都是百分点。页面在引用时写“34.7 个百分点”，不把它当成相对提升。

04

怎么算：LoRA + GRPO，语言与视频两套超参

读完这节应知道：模型、数据、超参与 GPU 小时；这也是“几百步 vs 几十万步”说法的来源。

语言世界模型用 DeepSeek-R1-Distill-Qwen-1.5B 与 7B 作基座；文本游戏先用 DeepSeek-R1 生成的 4,237 条 SFT 数据微调（约 $40），再跑 RLVR。LoRA rank 32、α 16；文本游戏 SFT 10 epoch、网页 4 epoch；RLVR 学习率 1e−6、KL 系数 1e−3、group size 5、文本游戏 batch 128、网页 batch 64（Table 5、Appendix A.1–A.2）。

07

它解决的是“指标对齐”，不是“世界模型的一切”

§7 讨论五类挑战（算法 2 + 基础模型 3）；与本页边界最相关的三类，加两条页面补充。

§7 讨论五类挑战：算法侧 2 项——(1) 性能屏障：RLVR 通常几百步就收敛，如何继续提升需要分析模型、数据与算法瓶颈；(2) OOD 泛化：RLVR 在语言模型上能泛化到训练域外，但世界模型在反事实动作上的表现还没验证。基础模型侧 3 项——(1) 通用世界模型后训练：当前视频模型是“每个数据集单独预训练”的 138M 模型，不是通用视频世界模型；论文说等社区有了通用视频世界模型，才能走“多样域预训练 → SFT → RLVR”的完整范式；(2) 跨模型类别应用：RLVR-World 的核心洞察与模型类别无关，但扩散模型的 GRPO 工作超出本文范围；(3) 任务对齐奖励：MSE/LPIPS 这类指标比 MLE 更贴近任务，但仍不能完全刻画用户想要的质量，物理规则与时间一致性需要更复杂的奖励。与本页边界最相关的三类是性能屏障、OOD 泛化与任务对齐奖励。

页面补两点。第一，网页与文本游戏的比较对象主要是自己的 Base/SFT；网页侧因评测口径不同，没有与 WMA 直接比（§5.2 脚注）。第二，RLVR 不是万能的测试时放大器：Figure 4 显示，采样数增加到 100 时，Base 模型会追上并反超 RLVR 模型；论文把这列为当前 RLVR 方法的局限。

别用 1

想要通用视频模拟器

当前视频模型按数据集单独预训练（RT-1 / PushT / Rope / Granular），没有跨域通用性。

别用 2

奖励无法程序化

RLVR 要求 D 可计算、可验证；主观质量、物理规则、长期一致性目前没有可靠指标。

别用 3

靠大量采样取胜

测试时采样到 100 个，Base 会追上；RLVR 的优势主要在单次/少样本与训练效率。

读表注意。第一，Table 3 的 Δ 表注已定义 relative performance gains from RLVR；Repetition、MSE、LPIPS 越低越好，Δ 的“+”表示改善，读者仍要按箭头方向读。第二，Table 4 里 DINO-WM 的 Rope LPIPS 是 0.9，而 RLVR-World 是 2.08；论文说“整体相当、Granular 更好”，Appendix A.4.2 也明确 “Our model underperforms DINO-WM on the Rope dataset”，不是每个数据集都更好。
