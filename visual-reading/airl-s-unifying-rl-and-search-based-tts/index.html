AIRL-S：把 RL 训练中的奖励函数，直接当作搜索时的 PRM

只用最终答案的对错做 RL，奖励太稀疏；用静态 PRM 指导搜索，又要昂贵的逐步标注，还会随策略更新产生分布偏移。 AIRL-S 用对抗逆向强化学习，从「答对的参考轨迹」里学一个逐步骤判别器；这个判别器既是训练时的稠密奖励，也是推理时 Best-of-N、Beam Search、MCTS 的打分器。 但它的「免费」只指免过程标注，对抗训练本身的计算成本论文没有和「监督 PRM + RL」正面比较。

Can Jin, Yang Zhou, Qixin Zhang, Hongwu Peng, Di Zhang, Zihan Dong 等 · Rutgers / NTU / UConn 等 arXiv 2508.14313v5 ↗ 博客笔记 ↗
TL;DR · 30 秒抓住核心

论文把两条测试时扩展路线接在一起：RL 路线用结果奖励优化策略，但奖励稀疏；搜索路线用 PRM 给中间步骤打分，但静态 PRM 需要逐步标注，并且会与不断更新的策略错位。 AIRL-S 的切口是：训练中为了优化策略而学到的奖励函数，本身就是最贴近当前策略的 PRM。

具体做法是把正确参考轨迹放进 replay buffer，用一个 AIRL 判别器区分「参考轨迹」和「当前策略轨迹」；判别器的 log-odds 就是逐步骤奖励 rφ（Eq.1）。 策略同时最大化 AIRL 的稠密过程奖励（Eq.3）和 GRPO 的结果奖励（Eq.4），两者按 λ 加权（Eq.6）。

推理时不再训练新模型：同一个 rφ 直接给 Best-of-N、Beam Search、MCTS 的候选步骤打分，再用 PRM-Min-Sum 聚合选答案。 论文在 8 个数学、科学、代码基准上报告：7B 策略平均 57.5，GPT-4o 为 57.0；带 Best-of-N 的 PRM 平均 61.3，高于 PRIME 的 55.6 和最强静态 PRM 的 57.6。

读数字时要小心口径：论文写的「9% / 13% / 15%」都没有说明是相对还是百分点；按 Table 1 复算，它们分别接近 +8.6 / +12.8 / +15.3 个百分点。 「匹配 GPT-4o」也只是 8 项平均，逐项看 GPT-4o 在 5 项上更高。

01

结果奖励太稀疏，静态 PRM 太贵且会过期

先建立两条测试时扩展路线的各自代价，才知道 AIRL-S 想统一什么。

论文把提升 LLM 复杂推理的测试时扩展（TTS）分成两条主路。第一条是基于 RL 的 TTS：用结果奖励模型（ORM）或规则奖励判断最终答案，再用 PPO / GRPO 优化策略。DeepSeek-R1 证明只靠结果奖励也能获得很强的推理表现，但结果信号通常很稀疏，训练稳定性和样本效率会受影响（§1）。

第二条是基于搜索的 TTS：用 PRM 给中间推理步骤打分，再让 Best-of-N、Beam Search 或 MCTS 在候选中搜索。PRM 提供稠密的逐步指导，但训练一个好的静态 PRM 需要细粒度监督——人工标注，或用另一个 LLM 生成伪标签，成本都很高（§1）。

更麻烦的是分布偏移：静态 PRM 训练完之后就不再变化，而策略还在持续更新。固定裁判与不断变化的选手之间的差距，会让策略学会利用 PRM 的漏洞，也就是 reward hacking；这既削弱策略的可靠性，也让 PRM 作为搜索 verifier 的作用变得不可信（§1）。

核心矛盾

要稠密信号，还是要有标注的稠密信号？

论文的提法是：能不能既保留 PRM 的逐步稠密信号，又不依赖逐步标注，并且让奖励函数跟着策略一起更新？AIRL-S 的答案是把「奖励学习」放回 RL 训练循环里，用参考轨迹与当前策略的对抗来学奖励，而不是先离线训一个固定 PRM（§1、§3.3）。

这里的「参考轨迹」不是人工写的专家推理，而是从当前策略采样、最终答案正确的 rollout，或已有的高质量轨迹；只有结果奖励为正的轨迹才进入 replay buffer B（§3.2）。因此它免的是过程标注，不是参考数据本身。推断（依据：§3.2 明确写 sample from the current policy or utilize existing high-quality traces，并按最终答案正确性筛选）。

02

静态 PRM、隐式 PRM、GRPO：各有一半，但没接成一个循环

三路对照：监督 PRM、PRIME 的隐式奖励、纯 GRPO；AIRL-S 的差别在「逐步骤判别器 + 训练与搜索共用」。

静态 PRM

逐步标注，离线训练

Math-Shepherd、Llama3.1-8B-PRM-DeepSeek-Data 等用带步骤标签的数据训练 PRM；EurusPRM-Stage2 从 ORM 派生隐式 PRM。

卡点：过程标注贵；PRM 固定后与策略产生分布偏移，容易被 reward hacking（§1、§4.1）。

PRIME

从似然比拿 token 级奖励

PRIME 用两个模型的 log-likelihood ratio 构造隐式 token 级奖励，不需要过程标签。

差别：论文认为 PRIME 的奖励绑定在计算比率的模型上，而 AIRL-S 训练的是逐步骤判别器，并强调跨生成器、跨搜索算法的迁移（§2、§4.2、Appendix D.1）。

GRPO

组内相对优势，结果奖励

GRPO 对同一问题采样一组 CoT，用组内归一化的结果奖励作为优势，不需要 value model。

卡点：只有最终对错，缺少中间步骤的稠密指导；论文的消融显示纯 GRPO 在 MATH500 / AMC 上弱于混合目标（Table 8）。

AIRL-S 不是把三者简单相加：AIRL 判别器给出逐步骤奖励 rφ，这个奖励一方面进入 PPO 式的 AIRL 目标，另一方面与 GRPO 的结果目标按 λ 合成；同一个 rφ 在推理时又作为 PRM 给搜索打分。论文在 Appendix E 以 system-level novelty 讨论这种「训练信号与推理 verifier 是同一个模型」的统一设计（§3）。

03

判别器的 log-odds 就是逐步奖励，再与结果奖励按 λ 合成

四个部件：参考轨迹池、AIRL 判别器、复合 RL 目标、PRM 引导的搜索。

参考轨迹池：只收答对的 rollout

对每个问题 q，论文从当前策略 πθ 采样多条 CoT，或用已有的高质量轨迹；按最终答案给二值结果奖励，只有正奖励的轨迹进入 replay buffer B。训练过程中会周期性删掉低质量条目，并加入新发现的正确解，以维持参考数据的可靠性与多样性（§3.2）。

AIRL 判别器：区分参考轨迹与策略轨迹

判别器的输入是 state-action 对：state 是问题 q 加上前面的推理步骤 {C1, …, Ci−1}，action 是当前步骤 Ci。判别器定义为：

Dφ(Ci | q, C<i) = exp{ fφ(q, C≤i) } / ( exp{ fφ(q, C≤i) } + πθ(Ci | q, C<i) )
§3.3 · fφ 是学习的打分函数；判别器越大，说明当前步骤越像参考轨迹

逐步奖励取判别器的 log-odds：

rφ(Ci | q, C<i) = log( Dφ(Ci | q, C<i) / (1 − Dφ(Ci | q, C<i)) )
Eq.1 · 判别器的 log-odds 就是 PRM 的逐步奖励

判别器用交叉熵训练：参考轨迹的步骤要判为真，当前策略的步骤要判为假。对每条 CoT 的所有步骤求和：

LAIRL = Σi=1|C| [ −EC~πe[ log Dφ(Ci | q, C<i) ] − EC~πθ[ log(1 − Dφ(Ci | q, C<i)) ] ]
Eq.2 · πe 是 replay buffer B 的参考分布；更新判别器等价于更新奖励函数 rφ

复合目标：稠密过程奖励 + 稀疏结果奖励

AIRL 目标用 rφ 导出的优势 Ai 做 PPO 式策略更新：

JAIRL(θ) = Eq, C~πθ[ Σi=1|C| min( (πθ(Ci|q,C<i) / πold(Ci|q,C<i)) Ai, clip(·, 1−ε, 1+ε) Ai ) ]
Eq.3 · Ai 用 REINFORCE 风格估计（§3.4）

GRPO 目标负责最终答案正确性：同一问题采样 G 条 CoT，用组内归一化的结果奖励 Ak，并加 KL 正则：

JGRPO(θ) = Eq, {Ck}~πold[ (1/G) Σk=1G ( min( (πθ(Ck|q) / πold(Ck|q)) Ak, clip(·, 1−ε, 1+ε) Ak ) − β DKL(πθ || πref) ) ]
Eq.4 · πref 是冻结的参考模型；β 控制 KL 惩罚；KL 项定义见 Eq.5（本页未展开）

最终目标是两者的加权和：

J(θ) = λ JAIRL(θ) + (1 − λ) JGRPO(θ)
Eq.6 · λ 平衡过程奖励与结果奖励；论文主实验取 λ = 0.5（§4.1）

训练在「更新判别器」与「用复合目标更新策略」之间交替（Algorithm 1）。论文在 Appendix D.1 增加了 λ 的消融：λ=0.5 在 MATH500、AMC、MBPP 上综合最好；纯 GRPO（λ=0）和纯 AIRL（λ=1）都更弱（Table 8）。

推理：同一个 PRM 给三种搜索打分

推理时，rφ 直接作为 verifier：Best-of-N 从策略采样 N 条完整解，按 PRM 聚合分数选最高；Beam Search 每步展开 M 个候选、按 rφ 保留前 N 条；MCTS 用 UCT 在探索与 rφ 的节点价值之间平衡（§3.5）。

一条完整解 Ck 的分数取路径上的最小步骤奖励：s(Ck) = mini rφ(Cki)。最终答案 a 的分数是把所有通向同一答案的不同链求和：S(a) = Σk:A(k)=a s(C(k))，取 S(a) 最大的答案。这就是 PRM-Min-Sum 聚合（§3.5、Appendix B.1）。

迁移到更弱的生成器也成立。Table 7（Best-of-N 64）用 Math-Shepherd-Mistral-7B-RL（无搜索时 AMC 7.2、MATH500 28.6）做生成器：AIRL-S 的 PRM 把 AMC 提到 24.1（+16.9）、MATH500 提到 46.6（+18.0），比表内最强监督 PRM 分别高 1.1 和 2.4 个百分点（Table 7）。Table 9 在 Phi-4-14B 上做 MCTS：AIRL-S 的 PRM 在 AIME2024 / AMC / MATH500 分别为 23.3 / 65.1 / 86.2，比最强基线高 3.3 / 2.4 / 1.0 个百分点；Beam Search 下拿到最好的 AMC 62.7，原文正文称 AIME 与 MATH500 与最强基线持平，但 Table 9 显示 AIME 20.0 与 Llama3.1 的 20.0 持平，MATH500 85.2 高于最强基线 84.6（高 0.6 个百分点）——正文与表格不一致。Table 7/9 未完整转录，只引上述关键行。

论文还报告了一个消融趋势：MCTS 的增益大于 Beam Search，作者的解释是 MCTS 在 selection、expansion、backpropagation 中反复查询 PRM，更好的步骤估值会沿树累积；Beam Search 的剪枝更窄，后续修正机会更少（Appendix D.1）。这是作者的解释，论文没有做逐节点的误差传播实验。推断（依据：Appendix D.1 的定性解释，未给节点级测量）。

07

它解决「可自动验证的推理任务」，不是开放式生成

论文自己承认的限制，加上从实验设置能看到的边界。

边界一

任务限于有自动验证器的数学、科学、代码

训练依赖最终答案的对错来筛选参考轨迹，评测也集中在 AIME2024、AMC、MATH500、GPQA、HumanEval、Leetcode、LCB-v4、MBPP。Appendix F 明确说，扩展到开放式生成可能需要额外的评测协议；创意写作、对话、多轮交互没有实验。

边界二

「免标注」不等于「免算力」

参考轨迹由策略自己采样，省掉了过程标注；但 AIRL 判别器与策略要交替训练，还有 8 条 rollout / 题、8 张 A100、2 epochs。论文没有给总 GPU 小时，也没有和「监督 PRM + RL」做训练成本对照，因此无法判断端到端是否更便宜。推断（依据：§4.1 只有硬件与超参；Appendix F 未给成本对照）。

边界三

参考数据的质量与多样性仍是前提

replay buffer 只收最终答案正确的轨迹；如果参考轨迹风格单一、步骤有瑕疵或覆盖不足，判别器学到的奖励也会继承这些偏差。论文用周期性剪枝与新正确解来维持多样性，但没有做「参考数据质量下降」的受控实验（§3.2、Appendix F）。推断（依据：§3.2 只描述筛选与更新机制，未报告数据质量消融）。

边界四

搜索预算与聚合策略固定

搜索实验使用固定 rollout 预算和少量聚合策略；Appendix F 把 adaptive search budgets 与更高效的 verifier scheduling 列为未来方向。论文也没有报告 PRM 推理延迟、吞吐或不同搜索宽度下的成本曲线（Appendix F）。

什么时候别用：如果任务没有可靠的最终答案验证器，或者参考轨迹本身难以获得，AIRL-S 的「只用正确轨迹」前提就不成立；如果任务短、搜索预算很小，稠密 PRM 的收益可能覆盖不了判别器与搜索的开销。推断（依据：论文的收益出现在 8 个可验证推理基准与 Best-of-N / Beam Search / MCTS 设置；未覆盖开放任务与低预算场景）。
