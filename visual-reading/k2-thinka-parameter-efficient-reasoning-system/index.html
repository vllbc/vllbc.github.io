K2-Think：32B 模型，把六项技术拼成一套推理系统

论文没有提出新的注意力机制，而是把长链 SFT、RLVR、测试时规划、Best-of-3、投机解码和 Cerebras WSE 串起来。 底座是 Qwen2.5-32B；四个数学基准的 micro-average 为 67.99。代价是外部规划器/验证器的成本未完整披露， 安全维度也不均衡。

Zhoujun Cheng 等 · MBZUAI Institute of Foundation Models arXiv 2509.07604v3（以 v3 为准）↗ 推理代码 ↗ SFT 代码 ↗
TL;DR · 30 秒抓住核心

论文的起点是一个判断：前沿数学推理不必只靠参数规模。K2-Think 用 Qwen2.5-32B 做底座，先 SFT 学长链 CoT， 再用 Guru 的约 92,000 条可验证 prompt 做 RLVR，最后在推理时加规划和 Best-of-3。六项技术分别落在训练、测试时和部署三段。

真正把分数抬起来的是测试时脚手架。Table 2 中，SFT+RL checkpoint 在 AIME 2024 是 86.26；仅 Bo3 到 90.77；Plan+Bo3 到 90.83。论文表注说最大增益来自 Bo3， 但 HMMT25 上仅 Plan 的 71.87 高于仅 Bo3 的 71.16，不能把「最大」理解成每个基准都成立。推断

部署侧，WSE 上约 2,000 tok/s，32,000 token 约 16 秒；论文还报告了 25 PB/s 的片上带宽。 代价是这些数字绑定 Cerebras 硬件，v3 只给了 regular cloud provider 的 nominal 200 tok/s 基线，未点名 GPU 型号，也没有可比的硬件对照。

结果并不均衡。数学 micro-average 67.99 高于 GPT-OSS 120B 的 67.20 和 DeepSeek V3.1 的 64.43， 但 GPT-OSS 120B 在 AIME 2025 与 HMMT25 更高；代码和科学也有更大模型领先。 安全四维宏平均 0.75，其中网络安全与数据保护 0.56。

01

前沿推理的账单：参数、token 和延迟一起涨

先建立共同认知：长链推理把训练成本和推理成本同时推高，部署还要面对串行生成的延迟。

2025 年的前沿推理模型普遍用长链 CoT：先写很长的中间步骤，再给答案。长链带来能力，也带来成本。 论文 §1 把这条路线概括为 large-scale SFT + RL，并引用 Snell et al. 2025 的观点： 在某些区间，推理时多算可能比把模型做大更划算。这句是引用，不是 K2-Think 自己的实验结论。

但推理时多算不是免费的。Best-of-N 要生成 N 条完整链，验证器还要比较；长链本身又是串行解码， 受内存带宽限制。论文 §2.4 说，典型云环境的 nominal 吞吐约 200 tok/s，32,000 token 要几分钟； WSE 上约 2,000 tok/s，16 秒完成。

所以问题不是「32B 能不能接近大模型」这一句，而是三件事同时成立：后训练配方能补能力， 测试时脚手架能补分数，部署硬件能把延迟压到可交互。论文把这三段拆成六根支柱。

成本一

训练

长链 SFT 需要高质量 CoT；RLVR 需要可验证奖励。论文用现成的 AM-Thinking-v1-Distilled 与 Guru 数据集，避免从零造数据（§2.1–§2.2）。

成本二

测试时

Bo3 要把同一条 query 生成 3 条完整链，再两两比较；分数涨，token 也涨。论文最终选 N=3，称其在提升与成本之间合理（§2.3）。

成本三

部署

自回归逐 token 生成，受内存带宽限制。WSE 把权重放在片上内存，论文报告 25 PB/s 片上带宽（§2.4）。

论文的评估也围绕这三段展开：Table 2 拆测试时组件，Table 3 拆输出 token，Table 1 比最终系统。 这三张表是理解全文的主线。

02

两条旧路，外加最接近的 PlanGEN

论文的定位不是单点算法，而是把后训练、测试时和部署接成一条流水线；先看它对比的两条旧路，以及最接近的 PlanGEN。

路线 A

更大的模型 + 长链 SFT/RL

OpenAI o3、Gemini 2.5、DeepSeek R1/V3.1、GPT-OSS 120B 走的是这条线。能力强，但参数和训练成本高。

论文的目标是用 32B 的 Qwen2.5 底座接近这些模型（§1）。

路线 B

测试时 scaling

BoN、self-consistency、CoT with reflection、Mixture of Agents（MoA）都是常见做法。

论文实测 MoA 略好但成本显著更高，最终选 BoN；temperature 从 0.1 到 1.0、30 多个 system prompt 的收益都不明显（§2.3.1）。

最接近的工作

规划 + 验证

最接近的工作是 PlanGEN：它把 Best-of-N 与验证器用在 plan 上。

论文的差别是验证对象：K2-Think 用 BoN + verifier 选生成的 response（§4）。

论文的 novelty 不是发明 BoN 或 planning，而是把「Plan-Before-You-Think」与 response-level BoN 组合。§4 的原句是：

“Importantly, they use Best-of-N with verifiers on the plans: we use it for the generated responses.”（§4）

论文把 novelty 定位为组合（§4：“Our novelty is to combine…”）；但 §2.3 又说这套 test-time scaffolding “integrates an original approach”（Plan-Before-You-Think 是其中一部分）。两处并列，页面不替作者下「六项技术没有一项是全新的」这种判断；贡献还包括工程化和公开部署；硬件部署（Cerebras WSE）是六支柱/系统贡献之一（§1、§2.4），但不在 §4 的 novelty 原句中。

03

六个支柱里，测试时脚手架最可调

SFT 与 RLVR 决定底座能力；规划和 Bo3 决定同一条 query 能榨出多少分；交互可以逐基准看四项配置。

支柱 1

Long CoT SFT

Qwen2.5-32B + AM-Thinking-v1-Distilled，代码基于 LLaMA-Factory；先让模型学会写结构化长链（§2.1）。

支柱 2

RLVR

Guru 数据集约 92,000 条可验证 prompt，覆盖 Math、Code、Science、Logic、Simulation、Tabular 六域；verl + GRPO（§2.2）。

支柱 3

Plan-Before-You-Think

外部 instruction-tuned LLM 只提取关键概念、生成高层计划；禁止给直接答案或推理 trace（§2.3）。

支柱 4

Best-of-3

同一条 query 采样 3 条候选；独立 LLM 做两两比较，淘汰较差的一条，直到选出最终答案（§2.3）。

支柱 5

Speculative decoding

论文引用 Leviathan et al. 2023，把它作为部署侧的加速手段；v3 未给出 draft model 与接受率细节（§2.4）。

支柱 6

Cerebras WSE

权重放在片上内存，论文报告 25 PB/s 片上带宽；32B 模型因此能在 WSE 上跑到约 2,000 tok/s（§2.4）。

04

训练只做两件事：先学格式，再按可验证奖励改策略

SFT 把 Qwen2.5-32B 拉到会写长链；RLVR 用 Guru 的六域可验证 prompt 继续优化；部署侧的数字则绑定 WSE。

SFT 阶段，论文用 AM-Thinking-v1-Distilled 对 Qwen2.5-32B 做监督微调，代码基于 LLaMA-Factory（§2.1）。 训练早期（约 0.5 epoch）AIME 2024/AIME 2025 快速上升，之后分别稳定在约 79.3% / 72.1% pass@1； LiveCodeBench 较慢但稳定地升到 56.4%； AIME 2024 的 pass@k 在 k≈128 时饱和在 93.3%（§2.1.1）。 这些是 SFT checkpoint 的数字，不是最终系统。

RLVR 用 Guru 数据集，约 92,000 条可验证 prompt，覆盖 Math、Code、Science、Logic、Simulation、Tabular 六域； 实现是 verl + GRPO（§2.2）。论文报告：从 base 直接 RL 在 AIME 2024 上 “achieves nearly 40% improvement”，而从 SFT checkpoint 出发只有 “5% improvement”； 作者怀疑重度 SFT 限制了后续探索（§2.2.1）。原文没有说明这两个百分比是相对还是绝对口径。

论文还报告了一个负面结果：先限制到 16,000 token 再扩到 32,000 token 的多阶段训练， 没有恢复到 baseline SFT 的表现；作者明确说没有评估 32k→48k 的扩展（§2.2.1）。

部署侧，WSE 上约 2,000 tok/s，32,000 token 约 16 秒；对比典型云环境 nominal 200 tok/s， 是 10 倍。片上带宽 25 PB/s（§2.4）。这两个派生数字都可以直接复算： 32,000 ÷ 2,000 = 16 s， 2,000 ÷ 200 = 10×。

为什么还要看 token：规划不只会改分数，也会改输出长度。Table 3 比较 checkpoint 与完整系统的平均 token 数。 原文的降幅有三层口径：Table 3 表注写 “our response length decreases on average”，但没有给出平均降幅的数值； §3 正文写 “by up to nearly 12% in comparison to the post-training checkpoint”；§5.1 写 “response lengths are reduced by nearly 12%”。 两个 12% 不是六项算术平均：按 Table 3 原始 token 数复算，六项降幅从 2.12% 到 11.73%，算术平均为 7.03%；7.03% 是本页算的，不是原文给的。

安全、成本与泛化：系统强，不等于没有短板

成本

外部模型没有完整账单

硬件

延迟数字绑定 WSE

WSE 的数字是 2,000 tok/s、32,000 token 约 16 秒、25 PB/s 片上带宽；论文另给 regular cloud provider 的 “nominal 200 tokens per second” 作为基线，但没有点名 GPU 型号，也没有同硬件对照。论文没有给出可比数据，不能把 WSE 的 2,000 tok/s 与 16 秒直接外推到普通 GPU。推断（§2.4 未给出同硬件对照）

泛化

只验证了一个底座

论文只报告 Qwen2.5-32B 一个底座，未报告 Llama/Mistral 等其他架构的迁移实验（§2）。

论文明确 SciCode 未跑 Plan-Before-You-Think（§3），39.2 不含该步骤，不能当作完整系统的 SciCode 成绩。推断

训练

负面结果没有被隐藏

从 base 直接 RL 的 AIME 2024 增益远大于从 SFT checkpoint 出发；多阶段 16k→32k 没有恢复 baseline；32k→48k 未评估（§2.2.1）。

什么时候别直接用这套配方：需要严格安全对齐的公开部署，先补 cybersecurity 与 jailbreak； 只有普通 GPU、没有 WSE，2,000 tok/s 与 16 秒不能假定；代码/科学为主时，Table 1 里部分更大模型更强，但 GPT-OSS 20B 在 LCBv5 上也高于 K2（73.22 vs 63.97），规模不是唯一因素。推断（由 Table 1 对照）； 底座不是 Qwen2.5-32B 时，论文未报告其他底座的迁移结果（§2）。

笔记勘误（6 条）只改页面，不动 content/posts/ 原文

1. 「平均减少近 12%」把三处口径混在一起。 笔记写规划「平均减少了近 12% 的答案 token」。原文有三层：Table 3 表注写 “response length decreases on average”， 但没有给出平均降幅的数值；§3 写 “by up to nearly 12%”，§5.1 写 “response lengths are reduced by nearly 12%”， 这两处不是六项算术平均；按 Table 3 原始 token 数复算，六项降幅的算术平均为 7.03%。 因此不能把「近 12%」当成平均值。

2. H100 的「近 3 分钟」没有原文依据。 笔记写 32,000 token 在 NVIDIA H100 上需要近 3 分钟；v3 没有点名 H100， 只说 WSE 上 16 秒、以及典型云环境 nominal 200 tok/s（§2.4）。32,000/200 = 160 秒可以复算， 但硬件型号不是原文给的。

3. 「规划提升准确率」被归到了 Table 3。 Table 3 只有平均 token 数；准确率证据在 Table 2。笔记把两件事写进了同一句「如表3所示」。

4. 「超过 10 倍」应为「10 倍」。 原文写 “10 times improvement”（2,000 vs nominal 200，§2.4），是 10 倍，不是超过 10 倍。

5. 数学上的「超越 DeepSeek V3.1」只对 Micro-Avg. 成立。 Table 1 中 DeepSeek V3.1 在 AIME 2024（91.87 vs 90.83）、AIME 2025（82.49 vs 81.24）、 HMMT25（83.54 vs 73.75）更高；K2 仅在 Omni-HARD 更高（60.73 vs 53.22）。 Micro-Avg. 由 173 题的 Omni-HARD 主导（占 263 题的 65.8%）。

6. 代码和科学「远超同等规模模型」不成立。 Table 1 中 GPT-OSS 20B 的 LCBv5 为 73.22，高于 K2 的 63.97； Nemotron 32B 的 GPQA-D 为 74.98，高于 K2 的 71.08。 K2 在 SciCode sub 上为 39.2，高于 Nemotron 的 37.1，但不是所有代码/科学指标都领先。
