AgenTracer：多智能体系统失败了，是谁在哪一步造成的？

多智能体系统越复杂，失败越难查：日志很长，错误可能藏在很早的一步，表面看却像后面才坏。AgenTracer 把「失败归因」做成数据问题：对失败轨迹做反事实回放，逐步用分析器提供的正确动作替换、重跑，最早能让任务转成功的那一步就是关键错误；对成功轨迹做程序化故障注入，主动制造已知位置的失败。两条路合成 TracerTraj-2.5K，再用多粒度 GRPO 训练 8B 追踪器。Who&When 自动子集 step-level 上（w/ G），它拿到 42.86%，Claude-4-Sonnet 是 40.65%；同一格去掉 G 后 Claude 38.83 反超 AgenTracer 的 37.30。

Guibin Zhang、Junhao Wang、Junjie Chen、Wangchunshu Zhou、Kun Wang、Shuicheng Yan · NUS / CUHK / OPPO / NTU 原文 v2 ↗
TL;DR · 30 秒抓住核心

论文把「关键错误」定义为决定性的最早错误：轨迹里存在某一步，把它替换成 oracle 给出的修正动作并重跑后续步骤后，整个任务从失败变成成功；所有满足条件的位置里取时间最早的那个。对失败轨迹，作者让 DeepSeek-R1 扮演分析器，逐步给出「最小侵入」的修正动作，重跑并检查结果，找到最早成功点。对成功轨迹，则随机选 K 个注入点，用扰动算子改掉动作再重跑；一旦诱发失败，注入点就是已知标签。

训练侧，AgenTracer-8B 以 Qwen3-8B 为底座，用去掉 KL 的 GRPO。奖励是三段式：格式必须严格包在 <think> 与 <answer> 里（二值门控）；agent 级是否正确（二值）；step 级用高斯核按距离给部分分。最终输出 <agentID> | <stepID>。这套组合在 Who&When 两个子集上多数单元格超过 Claude-4-Sonnet 与 Gemini-2.5-Pro，但并非每个单元格都赢：automated step-level 去掉 G 后 Claude 38.83 高于 AgenTracer 37.30；TracerTraj-agentic 的 agent-level（w/ G）Claude 55.20 也高于 AgenTracer 53.28。

01

系统越像团队，失败越像谜案

读完这节你应该知道：失败归因要回答什么，以及为什么现成的大模型做不好。

一个由 Planner、Coder、Tester 等多个角色组成的系统，执行一条长轨迹后给出错误答案。最终答案错了，但错误可能来自很早就下载错的文档、某个 agent 传错的参数、或某次工具调用的静默失败；后面的步骤看起来都「正常」，只是在错误前提上继续推理。论文引用的 Berkeley 研究显示，流行多智能体框架的失败率最高可达 86.7%。§1

论文把任务形式化为：给定失败轨迹 τ 和二元判定 Ω(τ)∈{0,1}，找到责任 agent i* 与决定性错误步 t*。这里的「决定性」不是「看起来最可疑」，而是「修正它就能让任务成功」；若有多个这样的位置，取时间最早的那个。这个定义把归因从主观阅读日志，变成可复现的反事实实验。§3

现成模型的表现并不好：论文称当前推理模型在该任务上的准确率通常低于 10%；Table 1 里 Who&When handcraft 的 step-level，GPT-4.1 只有 3.44/3.44（w/ G 与 w/o G），Gemini-2.5-Pro 只有 9.72/6.90。AgenTracer-8B 在这一格是 20.68/20.68。Table 1

输入

一条失败轨迹

包含每一步的状态、动作与执行 agent；日志长，错误可能被后续「看似正常」的步骤掩盖。

输出

责任 agent + 错误步

输出格式固定为 <agentID> | <stepID>；两个粒度分别评分，避免只猜对 agent 或只猜近步骤。

难点

错误早、信号晚

Figure 4 的案例里，根因在第 2 步（Web Surfer 取到旧文件），直到第 11 步才出现能证明它的证据。

02

已有方案：人工标注太贵，直接让 LLM 读日志又太弱

读完这节你应该知道：Who&When、MAST 与 AgenTracer 的数据规模差在哪里。

路线 A

人工标注的失败数据集

Who&When 是公开的失败归因基准，含 handcraft 与 automated 两个子集；MAST 也提供人工标注的失败轨迹。论文指出 MAST 与 Who&When 分别只有约 200 与 127 条人工标注的多智能体失败轨迹，规模不足以系统训练归因模型。§1

路线 B

让通用 LLM 直接推理

把整条轨迹一次性喂给 GPT-4.1、Gemini-2.5-Pro、Claude-4-Sonnet 等模型，让它们输出错误位置；这是论文的 all-at-once 设定 §5.1。Table 1/2 显示这类直接推理在 step-level 上普遍很弱，且给不给 ground truth G 并不稳定提升准确率，有时反而更差 §5.2。

AgenTracer 的不同点是先自动造数据、再训专用小模型：用反事实实验与故障注入生成「错误位置已知」的监督信号；论文把这套标注流程称为 automatic trajectory annotation；训练时再用格式门控与高斯核把「接近正确步骤」变成可学习的部分分。§4

03

方法：反事实回放找「最早能救活」的那一步，故障注入造「已知错在哪」的样本

读完这节你应该知道：两条标注路径怎么工作、奖励函数怎么拆、为什么可以去掉 KL。

3.1 反事实回放（失败轨迹）

对每条失败轨迹 τ，按时间从 0 到 T 逐步尝试：分析器 πanalyzer 拿到当前状态、原动作、历史、环境反馈 F 与标准答案 G，给出一个「最小侵入」的修正动作 a't；用修正动作替换原动作，重跑后续步骤得到 τ'。若 Ω(τ')=1，说明第 t 步是能翻转结果的位置；取最早满足条件的 t 作为 t*，该步执行 agent μ(t*) 即 i*。分析器被要求只给修复指导，不泄露完整答案。§4.1

3.2 程序化故障注入（成功轨迹）

对每条成功轨迹，从 0..T 中随机抽 K 个注入点；在每个点用扰动算子 Π 改掉原动作，得到 ãt，再重跑。若注入后 Ω(τ̃)=0，则注入点 (μ(t), t) 按构造就是决定性错误：因为我们知道错误是亲手放进去的。每条成功轨迹取第一个成功诱发失败的点，避免同一轨迹重复标注。两条路径合并成 Dtracer = D− ∪ D+，即 TracerTraj-2.5K。§4.1

3.3 训练：去 KL 的 GRPO + 三段奖励

底座是 Qwen3-8B，RL 算法用 GRPO，但去掉 KL 项，并把裁剪参数改成随训练步数衰减的 Bs = max(0.2·B0, B0(1 − s/Stotal))：前期裁剪宽、鼓励探索，后期收窄、稳定利用。论文没有给出 B0 的具体取值。§4.2

07

边界：标注质量依赖分析器，合成失败未必像真实失败

读完这节你应该知道：哪些结论有表格支撑，哪些是论文没有验证的空白。

分析器

oracle 上限决定标签质量

反事实回放依赖 DeepSeek-R1 给出「最小侵入」的修正动作；若分析器本身判断错，最早成功点可能标错。论文没有报告分析器自身的修正成功率或人工抽检一致率。§4.1

合成分布

注入失败 ≠ 真实失败

故障注入制造的失败由扰动算子决定，模式可能比真实系统里的交互错误、环境变化、幻觉更简单推断（论文只描述注入机制，未做合成 vs 真实的分布对比）。§4.1

统计

没有种子与方差

Table 1 / Table 2 在每个设定下只有一个数（每格为 w/ G / w/o G 两值）；没有报告多种子、标准差或置信区间。AgenTracer 与 Claude 在 automated step w/o G 的 1.53 点差（Table 1）、agentic agent w/ G 的 1.92 点差（Table 2），都无法判断是否稳定。

还有两点。第一，「最早决定性错误」是一个有用但单一的定义：如果失败是多个小偏差累积、或真正的根因在更晚但更深的策略层，最早翻转点可能只是表层症状推断（由定义只取最早满足条件的位置推出）；论文没有讨论这种归因偏差。第二，Table 3（Appendix A）的 TracerTraj 测试集按域划分后每域只有 147 / 63 / 56 条，math 与 agentic 的单元格样本量很小，百分比的一位小数并不代表高精度推断（样本量小，论文未给方差）。Appendix A

Table 1 与 Table 2 的粗体/下划线声称标出最好与次好，但抽取文本无法复现格式；页面不据此判定最优，只按数值转录。Table 1 / Table 2

最后，论文只验证了 coding、math 与通用 agentic 三类任务 Table 2；机器人控制、多智能体博弈、实时环境等更开放场景没有实验。论文结论只说这条路线 paves the way for self-correcting and self-evolving agentic systems §6；「自动修复」与「实时归因」是笔记列出的未来方向，不是该节的内容。
