Learning When to Plan：每步都规划反而更差，让智能体自己学会「何时该想」

ReAct 把「动手前先想」写死在每一轮循环里。论文在 Crafter / POGS 上的实验显示：零样本下每步都规划既不省钱也更差，存在一个中间的最优规划频率。 做法是把「何时规划」写成一次收益减成本的决策，再用「SFT 启动 + PPO 微调」把这项元认知能力教给 8B 模型。 代价是必须依赖教师的示范数据，且只在两个回合制环境里验证过。

Paglieri, Cupiał, Cook, Piterbarg, Tuyls, Grefenstette, Foerster, Parker-Holder, Rocktäschel · UCL / Oxford / NYU / Princeton 等 原文 arXiv 2509.03581 ↗
TL;DR · 30 秒抓住核心

常见的 agent 框架要么每步都想（ReAct 式「总是规划」），要么从来不想（只输出动作）。论文指出两者都次优：过度重规划会让智能体在子目标之间来回摇摆，论文用 Cnoise（不稳定性成本）描述它。

零样本实验里，性能随规划频率先升后降，形成一个「金发姑娘区」。在 Crafter 上 70B 模型规划「每 4 步一次」拿到 0.379，比「从不规划」0.343 和「总是规划」0.349 都高。

方法只有两步：先用教师模型生成 1,024 条带 <plan> 的轨迹做 SFT，再用 PPO 在环境里微调。关键是 SFT 不能省——直接对基座做 RL 并鼓励它规划，得分会掉到 0.210，比不规划的 0.274 还低。

01

「总是规划」和「从不规划」都不对：存在一个中间的最优频率

读完这节应知道：为什么把规划频率钉死会同时付出「钱」和「性能」两笔账。

推理模型的经验是「多想一点、答得更好」。但把一个单轮问答换成长程序贯决策，这条单调规律就不成立了。智能体每一步都在环境里行动，环境也在变；一个五步前写下的计划，跑到第三步可能已经过期。

于是有人把规划塞进每一轮循环——这正是 ReAct 的做法：每一步都先写一段自然语言思考，再挑一个动作。论文认为这带来两类代价：

  • 钱：每一步都产出一整段计划文本。在 Crafter 上，「总是规划」的 70B 智能体平均生成 38,836 个 token，而「每 4 步规划一次」只要 11,510 个。
  • 性能：频繁重规划会让计划与计划相互冲突，智能体在子目标之间摇摆、回溯变多。论文把它抽象成不稳定性成本 Cnoise：规划越频繁、计划质量越低，这项隐性成本越大。

在 POGS 环境里，论文用「访问了前两步所在节点」的回溯次数来量化这种不稳定（Figure 6）：「总是规划」的智能体回溯最多（柱高约 7），成功率也低于每 3–4 步规划一次的智能体；而「从不规划」的回溯同样偏高（约 5.6），只是原因不同——它根本没有方向。

核心前提

两个极端都差，中间最好

问题由此变成一个时间维度上的算力分配问题：不是「怎么规划」，而是「在一条长轨迹的第几步、因为什么才值得花 token 去规划」。论文称之为 dynamic planning。

02

两条现成路线：固定频率的提示词学不会，外部触发又绕开了模型本身

这一节给出对照：为什么「提示模型学会何时规划」行不通，以及论文和已有工作在哪一刀切分。

路线 A

固定频率规划

不改权重，只改系统提示词：让模型每 k 步（k = 1, 2, 4, 8 …）写一次计划，其余步只输出动作；或干脆从不规划。

发现问题：论文试过直接提示「只在必要时规划」。模型很少能稳定理解这种抽象指令，总是退化成「总是规划」或「从不规划」。零样本里因此根本无法给出一个真正的动态规划基线。

路线 B

外部中介 / 行为克隆

另一类工作用一个独立的「中介策略」决定何时调用外部规划工具，或者用 SFT 去模仿已有的动态规划数据。

论文的切分：这些方案把「何时」交给出模型之外的东西。论文坚持用一个单体 LLM，不加任何门控模块，让模型自己在输出里决定要不要写 <plan>。

这也是为什么论文要先花一节论证「金发姑娘区」：如果提示词能教会模型择时，剩下的就只是调一个提示词；正因为教不会，才必须用「先示范、再强化」来学习这个元认知能力。

03

把「何时规划」写成一次投资决策：预期收益 > 成本时才出手

全文最核心的一行是下面的不等式；其余的工程要么在估计左边，要么在惩罚右边。

规划优势 vs 规划成本

论文把环境建模为 POMDP ⟨S, A, T, R, O, γ⟩。在时刻 t，智能体手里有一份旧计划 pt−1；规划优势定义为：换成一份新计划 pt 后，预期未来回报的提升。

Aplan(ct) = 𝔼pt ~ ψθ(·|ct, dt=1) [ Vπθ(ct, pt) − Vπθ(ct, pt−1) ]
左侧只在 dt=1（决定规划）时计算：新计划到底让价值提升了多少

右边的成本被拆成三项：

Cplan = Ctokens + Clatency + Cnoise   ，   Ctokens = ktokens · |pt|
tokens 成本 = 单价 × 计划长度；延迟成本在回合制环境里约等于 0；不稳定性成本 = knoise · fp · (1 − Q̄p)，即频率 × (1 − 平均计划质量)

三项里只有 Ctokens 会在训练里被显式扣掉。Cnoise 从不显式计算，论文的论证是：糟糕的频繁规划会自然拉低任务奖励，于是被 RL 目标隐式惩罚。这个取舍后面会变成一条重要的边界（见 07）。

三条策略只是「一个模型的三种读法」

论文把行为拆成决策策略 φθ（要不要规划）、规划策略 ψθ（写什么）、执行策略 πθ（做什么动作）。三者不是三个网络，而是同一个 LLM 输出的不同片段：

pt = dt · ψθ(pt | ct, pt−1) + (1 − dt) · pt−1
dt=1 就换新计划，dt=0 就沿用旧计划；dt 在实现中就是「这次输出开头是不是 <plan>」

自己动手：在两条成本上找一个甜点区

04

SFT 负责「会写计划」，PPO 负责「学会挑时机」，缺了前者 PPO 会跑偏

这一节回答工程问题：为什么要先 SFT，以及 RL 的奖励长什么样。

第一步：用教师数据做启动

  • 教师：Llama-3.3-70B-Instruct，在 Crafter 里生成 1,024 条轨迹。
  • 多样性：每条轨迹的规划频率 K 从 U[2, 12] 里均匀采样，并轮换 16 种不同风格的规划提示（子目标、里程碑、短期序列、高层战略……）。
  • 格式：该规划时输出 <plan>…</plan> [Action]，不该规划时只输出 [Action]；这就是动态规划的训练目标。
  • 学生：Llama-3.1-8B-Instruct，这一阶段只做动作预测，不做 world modeling——附录 C.1 发现额外建模环境会让 KL 更大、遗忘更多。

第二步：PPO 微调

优化目标把任务奖励和规划 token 成本放在同一条回报里：

θ* = arg maxθ 𝔼τ~θ [ Σt=0H γt ( Rtask(st, at) − dt · Ctokens,t ) ]
只有真的规划（dt=1）才扣 token 成本；延迟与不稳定性不上奖，靠「规划不好 → 奖励低」被隐式惩罚

工程上：actor 8B + critic 1B（Llama-3.3），RSLoRA 分别挂在 actor 与 critic 上；用 vLLM 托管权重、BALROG 接环境、Ray 做数据收集，每个 epoch 后把权重广播回 vLLM。实验在 8×H100 上跑，其中 6 张训、2 张采样，一个实验通常 24–48 小时。超参：KL 系数 0.05、rollout 长度 16、历史截断到 16 条观测、max output 200 tokens。

一个反直觉的工程选择：论文放弃了显式奖励塑形（比如惩罚无效动作、过长回复、过密规划）。他们发现这些 shaping 往往把智能体逼成「完全不规划」。最终只保留 token 成本一项，让「金发姑娘」频率自己浮现。

三个反直觉的读法

  • 跳过 SFT 直接教 RL 规划，比不规划更差。Base+RL 动态拿到 0.210，低于同配置不规划的 0.274，而且 token 反而飙升到 10,818.7。论文的解释是：没有 SFT 提供的结构化示范，基座模型在 RL 里学不会「计划能帮上忙」，生成计划只是额外开销。
  • 动态规划同时更准也更省。SFT+RL 动态（0.387 / 1,714）相对 SFT 前身（0.343 / 1,870）奖励更高、token 更少；相对 70B 的最佳配置（0.379 / 11,510）token 少 85%。
  • 规划质量随 RL 提升。用 GPT-5 mini 做 LLM-as-a-judge（100 个种子）：SFT+RL 的计划完成率 0.20（SFT 0.16），因环境变化而进行有效重规划的比例 0.41（SFT 0.35）。
为什么「总是规划」的 70B 反而不如「每 4 步」？对照 Cnoise 与过思考的解释

论文给了两条互相补充的解释：一是 instability cost（Cnoise）——过密的计划互相冲突，智能体反复改主意；POGS 的回溯统计是最直接的证据，「总是规划」回溯最多。二是「过思考」（Sui et al., 2025）与长上下文稀释注意力：每一步都写一段计划，关键信息反而被淹没。

这个效应在 Gemini 2.5 Flash 上也复现了，但形态不同：在 POGS 这种对强模型而言太简单的环境里，多加计划甚至不如规划一次。论文由此推断，「金发姑娘区」的位置依赖模型能力与环境难度。

07

它教的是「何时写计划」，不是「如何推理」：范围窄、依赖教师、两项成本没有真正优化

读完这节应知道：哪些结论论文撑得住，哪些只是隐式假设。

边界一

只在两个回合制环境、两个模型规模上验证

POGS 是自定义的合成图搜索，Crafter 是 2D 网格生存游戏；训练用 8B，零样本评测用 70B 与 Gemini 2.5 Flash。论文自己在 limitations 里承认：最优分配策略如何随模型规模变化，以及能否推广到更开放的领域（网页、代码、机器人），都还没测。

边界二

SFT 启动是硬依赖，教师的质量就是上限

数据来自一个「固定频率规划」的 70B 教师，教师本身不是动态规划的最优解。没有它，Base+RL 动态掉到 0.210。这意味着方法的起点取决于能否拿到结构良好的 <plan> 示范，换新任务就要重新造数据。

边界三

Clatency 与 Cnoise 只是概念上的，没有显式优化

回合制环境里延迟成本近似为 0；不稳定性成本只通过「奖励变低」间接惩罚，没有任何一项奖励项直接对应它。附录 C.3 还显示，训练足够久后加大 token 惩罚会明显降低显式规划频率，而得分几乎不变——说明部分推理被「内化」进权重，此时显式计划对自主表现并非必需，但论据是「没有显式计划就无法被人引导」。

边界四

自主运行仍不能通关 Crafter

论文说：计算约束下，没有任何自主运行的智能体完整通关。挖钻石通关是人类给出高层计划之后实现的（论文记录约 20 次尝试）。这既是 steerability 的正面结果，也说明纯自治的上限仍有距离；附录 D 还给了失败案例：计划正确，但没有确认熔炉可达就动手制作。

一句话：这篇论文解决的是「在已会规划的前提下，何时才值得规划」，并把这件事收敛成一个可训练、可被引导的元认知策略；它没有声称解决「怎么规划得更好」，也没有在开放域上证明有效性。
