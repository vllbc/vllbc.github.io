GEPA：用自然语言反思演化 prompt，rollout 最多少 35×

GEPA 不更新模型权重，而是把复合 AI 系统的每条执行轨迹——推理、工具调用、编译器报错、评分器反馈——当作学习材料，让一个 LLM 读出失败原因，直接改写对应模块的 prompt。它维护一组在不同任务实例上「各有所长」的候选，而不是只追当前平均分最高的那一个。 在四个任务、两个模型上，GEPA 的 Qwen3-8B 聚合分达 61.28，GPT-4.1 mini 达 66.97；IFBench 上只用 678 次 rollout，约为 GRPO 固定 24,000 次的 1/35。

Lakshya A. Agrawal 等 · UC Berkeley / Stanford / MIT 等 arXiv 2507.19457v1 ↗ 代码 ↗
TL;DR · 30 秒抓住核心

问题：RL 的梯度只看到最终标量奖励，丢掉了轨迹里的语言信息。 GRPO 这类方法通常要几千到几万次 rollout 才能适配新任务；每次 rollout 可能包含昂贵的工具调用，或者模型根本不能微调（§1）。

方法：反思式 prompt 突变 + 帕累托候选选择。 对选中的候选和目标模块采样一小批任务，把模块输入、输出、推理和评分器反馈交给 LLM 反思，提出新 prompt；新候选只在小批量上评估，提升后才进入候选池并在验证集上打分。候选选择不是「总选当前最好」，而是保留每个任务实例上的赢家，再按赢的次数加权采样（§3.2、§3.3、Algorithm 1–2）。

结果：Qwen3-8B 上平均高 GRPO 10.14 个百分点，最高 19.0。 四个任务的逐项差是 HotpotQA 19.0、IFBench 2.73、HoVer 13.66、PUPA 5.19 个百分点；平均 10.14，论文写「10% on average」，摘要写「up to 20%」，§5 又写「up to 19%」——三处口径分别是 10% 平均 / 20% / 19%，不完全一致。不是每个任务都大幅领先。

代价：只优化 prompt，不碰权重；只做指令，不做 few-shot。 论文承认数据充足时权重更新可能更强；GRPO 基线只用 LoRA，没有做全参数微调；GEPA+Merge 在 Qwen3-8B 的 IFBench 上反而降到 28.23，低于 baseline 的 36.90（§5、Table 1）。

01

RL 只拿标量奖励，浪费了轨迹里的自然语言

GEPA 的出发点：每次 rollout 的成本很高，但轨迹本身信息很丰富。

复合 AI 系统由多个 LLM 模块、工具调用和控制流组成。用 GRPO 这类 RL 方法优化时，系统跑完一条轨迹，评分器把它压成一个标量奖励，梯度只从这个奖励反传。轨迹里的推理链、检索到的文档、工具输出、编译器报错、评分器的中间判断，都被丢掉了（§1、§2）。

论文的观察是：这些轨迹本来就是自然语言，现代 LLM 可以直接读懂。与其只告诉模型「这条得 0.3 分」，不如把完整轨迹和失败原因交给 LLM，让它反思「哪个模块的哪条指令导致了失败」，再改写那条指令。这样一次 rollout 可以提供比一个标量多得多的学习信号（§1、§3.2）。

缺口 1

样本效率

论文引用此前的 GRPO 工作：实际使用中常见几万到几十万次 rollout。每次 rollout 可能调用昂贵工具，或者需要采样大模型，成本很快成为瓶颈（§1）。

缺口 2

不能改权重

很多最强模型只能通过 API 访问，无法做 LoRA 或全参数微调。prompt 优化不需要权重访问，这是 GEPA 的适用场景（§1、§8）。

论文把优化目标写成：在最多 B 次 rollout 的预算内，最大化复合系统在任务分布上的期望得分。GEPA 只优化 prompt 集合 Π，不优化权重 Θ；这也是它与 GRPO 的根本区别（§2、Eq.2）。

02

已有路线：贝叶斯 prompt 优化、进化算法、权重 RL

GEPA 的位置是「用环境反馈做定向突变 + 用帕累托保持多样性」。

路线 A

MIPROv2：贝叶斯优化指令与示例

MIPROv2 同时优化指令和 few-shot 示例，用 TPE 贝叶斯搜索候选组合。论文的对照设置是 auto=heavy：18 个指令候选、18 组 bootstrapped 示例；rollout 预算从 PUPA 的 2,270 到 HoVer 的 6,926（§4.3）。

路线 B

EvoPrompt / AlphaEvolve：进化搜索

EvoPrompt 把 LLM 和进化算法结合，但论文认为它的 prompt 种群没有充分利用训练反馈；AlphaEvolve 直接在代码层面做进化，适合可显式编码的解，不直接解决「多个 prompt 模块」的复合系统（§7）。

路线 C

GRPO：权重空间的 RL

GRPO 用组内相对优势估计梯度，更新 LoRA 或全参数权重。它能看到最终奖励，但看不到评分器产生奖励之前的语言轨迹；论文的 baseline 固定 500 步、24,000 次 rollout（§4.3）。

GEPA 与三者都不同：它像进化算法一样维护候选种群，但突变由自然语言反馈驱动；它像 prompt 优化器一样不改权重，但优化对象是复合系统里的每个模块，而不是单个整体 prompt；它像 RL 一样使用环境反馈，但反馈是文本，不是标量梯度（§3、§7）。

03

三个部件：候选池、反思突变、帕累托选择

奖励仍然可以只是 0/1 或任务得分；变化发生在「从哪条轨迹学、学哪个模块、下一步选谁」。

3.1 候选池：每个候选是整套系统 prompt 的一个实例

GEPA 把复合系统记为 Φ = (M, C, X, Y)，M 是语言模块，C 是控制流。每个模块 Mi 有 prompt πi 和权重 θi；GEPA 只改 π，不改 θ（§2）。候选池 P 初始只有原始系统；每次迭代从池中选一个候选、选一个模块、改这条模块的 prompt，生成新候选（§3.1、Algorithm 1）。

3.2 反思突变：把模块输入输出、轨迹、评分器反馈一起给 LLM

对选中的候选，GEPA 从训练集抽一个小批量（论文用 b=3），在目标模块上跑几条 rollout，记录模块的输入、输出、推理，以及最终成功/失败。反馈函数 μf 还可以返回评分器执行过程中的文本，例如编译器报错、检索到了哪些文档、哪些约束满足/未满足（§3.2）。

这些材料被拼成一个反思 prompt，交给 LLM；LLM 要判断「目标模块的 prompt 缺了什么、哪条指令导致失败」，并输出一条新的 prompt。新候选是当前候选的副本，只替换目标模块的 prompt。模块按 round-robin 选择，保证每个模块都有机会被更新（§3.2、Algorithm 1）。

π′j ← LLMreflect( πj, inputsj, outputsj, tracesj, feedbackμf )
§3.2 · 反思对象是「目标模块」的轨迹，不是整个系统的最终答案；这是 GEPA 能做模块级 credit assignment 的关键

论文强调「评估轨迹」也是学习信号：评分器在给出最终分数前可能执行编译、运行、profiling 等步骤，这些步骤的文本比最终分数更有诊断价值。GEPA 把评分器改造成 μf，在返回分数的同时返回反馈文本（§3.2）。

3.3 帕累托选择：不让「当前最好」垄断预算

如果每次都选当前平均分最高的候选来突变，优化器很容易在找到一个局部最优后停住：它会把剩余预算都花在改进这一个候选上，而不是探索其他策略。论文用 Figure 6 展示这一点：SelectBestCandidate 在找到一个新策略后反复尝试改进它，最终耗尽预算（§3.3）。

GEPA 的做法是：对每个训练实例，找出所有候选在该实例上的最高分；保留「至少在一个实例上达到最高分」的候选，去掉被严格支配的候选；再按「在多少个实例上是最好的」加权采样。这样，一个候选即使平均分不高，只要它在某个任务上是唯一赢家，就有机会被选中并继续进化（§3.3、Algorithm 2）。

P*[i] = arg maxk S[Pk][i]   →   去掉被支配者   →   P(select Pk) ∝ |{i : Pk ∈ P*[i]}|
§3.3、Algorithm 2 · 选择概率与「赢得的任务实例数」成正比，不是与平均分成正比

此外还有一个可选的 Merge 策略：从两个候选的谱系里各取表现最好的模块，拼成一个新候选。Merge 最多调用 5 次；它在 GPT-4.1 mini 上最多带来 5.0 个百分点的提升，但在 Qwen3-8B 上并不总是有效（§3、§4.3、§5、Appendix F）。

04

没有权重更新，但有 rollout 预算：对齐到 MIPROv2 的量级

论文给的是 rollout 数、模型和硬件；没有给美元成本或总 GPU 小时。

预算

与 MIPROv2 对齐，误差 ≤10.15%

为了公平比较，GEPA 的 rollout 预算按每个 benchmark 对齐到 MIPROv2 的实际消耗；两边提案/验证流程不同，预算差异始终在 10.15% 以内（§4.3）。

每次迭代

minibatch 3，Merge 最多 5 次

GEPA 的 minibatch size 为 3；Merge 启用时最多调用 5 次。没有梯度更新、没有 LoRA、没有优化器状态（§4.3）。

模型

Qwen3-8B 与 GPT-4.1 mini

两个模型分别代表开源与商业模型；所有模块共用同一个模型，上下文上限 16,384 token。Qwen3-8B 温度 0.6、top-p 0.95、top-k 20；GPT-4.1 mini 温度 1.0（§4.2）。

硬件

1×H100/A100 80GB

训练实验在 1×H100/A100 80GB 上跑，rollout 用独立 GPU；GRPO 基线 500 步、24,000 次 rollout。论文没有给 GEPA 的 API 费用、GPU 小时或每个任务的 wall-clock（§4.3）。

GRPO 基线的配置是：每步 group size 12、4 个训练实例（总 batch 48）、LoRA rank 16、α=64、dropout 0.05、学习率 1e-5、β=0.01、梯度裁剪 0.1、每 20 步累积一次梯度；500 步共 24,000 次 rollout（§4.3）。这些数字对复现很重要，也说明「35× 更少 rollout」比较的是固定 24,000 的 GRPO，而不是调过预算的 RL。

05

一轮迭代：选候选 → 选模块 → 采样 → 反思 → 评估 → 入池

下面的回路是 GEPA 的核心循环；Merge 是从帕累托池分出的可选分支。

注意两个细节。第一，新候选只在 minibatch 上评估；只有比父代更好，才会进入候选池并在验证集 Dpareto 上打分。这控制了每次迭代的成本，也让「提升」是相对父代，而不是相对全局最优（Algorithm 1）。第二，Merge 不是每轮都做，最多 5 次；它的收益依赖两条已经分化出不同优势模块的谱系（§5、Appendix F）。

07

边界：prompt 不是权重的替代品，35× 也不是每个任务

GEPA 的优势有明确的适用条件；论文自己列了若干限制。

边界 1

数据充足时，权重更新可能更强

论文明确说：prompt 学习与权重学习的边界还不清楚；rollout 昂贵时 GEPA 有优势，但数据充足或大规模 rollout 可行时，权重更新可能更好。GRPO 基线只用 LoRA，没有做全参数微调（§8）。

边界 2

只优化指令，不优化 few-shot

GEPA 当前只改指令，不选示例。MIPROv2 同时优化指令和示例；在示例很重要的任务上，GEPA 可能放弃了一部分性能。论文把「prompt 更短」当作成本优势，但也承认这是限制（§8）。

边界 3

大部分 rollout 花在验证集

GEPA 的总 rollout 里，多数用于在 Dpareto 上评估候选，真正用于学习的训练 rollout 少得多。论文建议研究更小的验证集，或在动态选择、子采样的验证集上跟踪分数，来进一步省预算（§5、§8）。

边界 4

Merge 不是稳定增益

GEPA+Merge 在 GPT-4.1 mini 上聚合最高，但在 Qwen3-8B 上聚合 57.62 低于 GEPA 的 61.28，IFBench 甚至低于 baseline。Merge 的调用时机与预算分配需要按模型/任务调参（§5、Appendix F）。

结果层面还有三条限制。第一，「35×」是 IFBench 单任务：HotpotQA 是 6,438 对 24,000（约 3.7×），HoVer 约 3.5×，PUPA 约 11×；不能把 35× 说成四个任务的平均。第二，「10% 平均」是 Qwen3-8B 四个任务逐项差的平均：19.0、2.73、13.66、5.19 的算术平均是 10.145 ≈ 10.14（聚合差 61.28−51.14 也是 10.14）；它不是聚合分的相对提升，也不是 GPT-4.1 mini 的结果。第三，没有统计检验：Table 1 只给单点分数，未报告置信区间、方差或随机种子；是否来自单次运行原文未说明。页面不把 0.几 的差说成显著（Table 1、§5）。

方法层面的边界是「反馈质量」：GEPA 假设评分器能给出有诊断价值的文本。如果任务只有 0/1 奖励、没有可读的中间反馈，反思突变可能退化成「让 LLM 猜哪里错了」（推断，由 §3.2 的反馈构造反推）；论文把「反馈工程」列为未来方向，没有系统比较不同反馈的质量（§8）。
