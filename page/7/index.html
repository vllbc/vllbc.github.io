构建

通过镜像源拉去镜像

docker pull docker.m.daocloud.io/nvidia/cuda:11.8.0-cudnn8-devel-ubuntu22.
04

创建Dockerfile，基于拉去的镜像创建自定义的镜像

mkdir ~/docker-projects/gpu-experiment/
cd ~/docker-projects/gpu-experiment/
vim Dockerfile
# 1. 基础镜像：CUDA 11.8 + CuDNN 8 + 开发工具（devel）+ Ubuntu 22.04
# 保留devel版本以支持后续可能的编译需求，但仅包含最核心组件
FROM nvidia/cuda:11.8.0-cudnn8-devel-ubuntu22.04

# 2. 关闭交互模式，避免安装时弹窗
ENV DEBIAN_FRONTEND=noninteractive

# 3. 安装基础系统工具并添加sudo支持
RUN apt-get update && apt-get install -y --no-install-recommends \
    apt-utils \
    openssh-client \
    # 基础shell工具
    bash curl wget ca-certificates \
    # 文本编辑工具
    vim nano \
    # 版本控制工具（后续拉代码用）
    git \
    # 基础编译工具（devel已包含大部分，这里补充必要的）
    build-essential \
    # 添加sudo支持
    sudo \
    # 清理缓存，保持镜像精简
    && rm -rf /var/lib/apt/lists/*

# 4. 配置用户和权限（与主机UID/GID匹配）
# 创建与主机相同GID的用户组
# 红色的部分需要根据自己主机的UID/GID进行修改。查看方式：在终端输入 id 命令即可。
RUN groupadd -g gid username && \
    # 创建与主机相同UID的用户并加入组
    useradd -u uid -g gid -m -s /bin/bash username && \
    # 允许该用户使用sudo且无需密码
    echo "username ALL=(ALL) NOPASSWD:ALL" >> /etc/sudoers

# 5. 配置CUDA环境变量（确保后续在容器内编译时能找到CUDA）
ENV CUDA_HOME=/usr/local/cuda
ENV PATH=$CUDA_HOME/bin:$PATH
ENV LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH

# 6. 创建工作目录并设置权限
RUN mkdir -p /workspace && \
    chown -R username:username /workspace
WORKDIR /workspace

# 7. 切换到普通用户（与主机用户匹配）
USER username

# 8. 启动容器时直接进入bash，等待手动配置环境
CMD ["/bin/bash"]

给拉取的镜像打标签（与 Dockerfile 中的 FROM 一致）： 因为 Dockerfile 中写的是 nvidia/cuda:xxx，需要将手动拉取的镜像重命名为该标签，否则构建时仍会去官方源拉取

agentic RL

vllbc 发布于 2025-10-17 收录于 Agent LLM

在一个需要多轮对话完成的长rollout，目前有两种主流做法，第一种是把每一轮的上下文内容给拼接起来。最后形成一条长长的轨迹通过小心的设置mask来让模型可以训练。第二种是把所有的单轮交互切开，直接看做独立的rollout送进batch，每一个步骤都送一个相同的final reward来训练。这两种做法其实都有各自的问题。第一种做法最后一次完整对话会变超级长，非常耗显存。第二种做法的话，模型会明显遇到上下文缺失的问题。

ReasoningBank：Scaling Agent Self-Evolving with Reasoning Memor

vllbc 发布于 2025-10-17 收录于 Agent Reading

论文深度解读

首先，让我们对这篇论文进行一个整体性的深入剖析。

这篇论文的核心论点是，当前的大语言模型代理（LLM Agents）在执行持久化、长期的真实世界任务时，存在一个致命缺陷：它们无法从过去累积的交互历史中学习。这导致它们像一个“失忆的专家”，每次都从零开始，不断重复过去的错误，也无法利用相似问题的解决经验。论文将这一问题归结为现有记忆机制的不足。

H2R：Hierarchical Hindsight Reflection for Multi-Task LLM Agents

vllbc 发布于 2025-09-23 收录于 Planning Reading

规划的工作，解决的问题是在以往的经验工程中直接检索会导致检索到大量无关的干扰信息，降低了成功率，这个问题的根本原因是检索粒度太粗了，方法是分层规划，解耦成做什么的高级知识和怎么做的低级知识，类似HIPLAN：Hierarchical Planning for LLM Agents with Adaptive Global-Local Guidance，构建方法是在事后主动进行反思，通过基于轨迹的子目标推断、对比性洞察提取和结构化的记忆单元（高层记忆单元包含{任务描述, 成功子目标序列, 相关规划洞察}，低层记忆单元包含{子目标描述, 对应子轨迹, 相关执行洞察}）。此外对于高级计划由planner检索，低级动作由executor检索。这篇论文非常值得阅读。
